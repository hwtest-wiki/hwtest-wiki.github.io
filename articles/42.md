# 跑分变慢，先查 Gear / lane 还是先看眼图？——UFS 5.0 一致性测试从链路状态到 Tx、Rx、Channel

<div class="article-meta"><span class="badge">📘 模块六 · 高速接口一致性测试 · 第 8 篇 · 存储家族第 1 篇 · UFS / eMMC</span><span class="badge">⏱ 约 33 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


系统吞吐下降时，先读取当前 **Gear、Series、ActiveLanes 和 Power Mode**，再决定是否架示波器。如果目标配置根本没有生效，眼图测得再漂亮，也解释不了系统为何运行在低档；如果链路状态正确但 UIC 错误持续增加，再进入 Tx、Rx、Channel 电气测量，定位效率更高。

本文按测试计划的顺序组织：先确认接口对象与工作状态，再确定参考面、台面和判据，最后用受控 A/B 完成复测闭环。文中的公开速率、协议层次和 Linux 字段可用于准备测试；具体电气限值、码型、校准流程和通过条件仍以 DUT 对应版本的 CTS 与授权规范为准。

## 1. 接口与应用

UFS 是 JEDEC 定义的嵌入式高速存储接口，典型对象包括手机、平板、PC、车载与工业计算平台。Host 侧通常集成 UFS 主控制器，Device 侧把控制器与 NAND 封装为 BGA 器件。它解决的是主机与存储器件之间的命令、数据、任务管理和设备管理，不等同于 NAND 内部接口，也不是可随意外接的通用高速端口。

截至 **2026-08-11**，公开基线为：

| 对象 | 当前公开版本 | 工程含义 |
|---|---|---|
| UFS | UFS 5.0 / JESD220H | 定义 UFS 设备、命令、协议与功能要求 |
| 主机控制器接口 | UFSHCI 5.0 / JESD223G | Host 软件访问 UFS 控制器的寄存器、队列与描述符接口 |
| 物理层 | MIPI M-PHY 6.0 | 提供高速串行差分电气接口，新增 HS-G6 PAM4、1b1b 与可选链路均衡训练 |
| 互连层 | MIPI UniPro 3.0 | 提供链路、流控、可靠传输及 G6 相关机制 |

公开核对入口：[JEDEC UFS 5.0 公告](https://www.jedec.org/news/pressreleases/jedec%C2%AE-announces-updates-universal-flash-storage-ufs-and-memory-interface-0)、[MIPI M-PHY 6.0 / UniPro 3.0 公告](https://www.mipi.org/press-releases/mipi-releases-unipro-v3-and-mphy-v6-accelerating-jedec-ufs-performance-for-edge-ai-in-mobile-pc-automotive)、[Linux UFS 架构与 REF_CLK 文档](https://www.kernel.org/doc/html/latest/scsi/ufs.html)。完整电气模板与通过条件仍以对应版本授权规范和 CTS 为准。

JEDEC 公告给出的 UFS 5.0 有效接口上限约为 **10.8 GB/s**，并说明它与 UFS 4.x 保持硬件兼容。这个数字是接口能力，不代表任意器件、文件系统或应用负载都能达到同样跑分。NAND 阵列、控制器、缓存策略、温度、队列深度和读写模式都会限制端到端性能。

UFS 每个方向最多使用两条单向 lane：Host 到 Device 最多 **2 TX lane**，Device 到 Host 最多 **2 RX lane**，从 Host 视角可写成 **2TX + 2RX**。两组 lane 方向独立，因此支持全双工；但不能把两个方向的带宽相加，宣称为顺序读取带宽。顺序读只消耗 Device→Host 方向，顺序写只消耗 Host→Device 方向。

![图1：UFS 5.0 公开接口上限与 lane 方向。用于区分每方向两条单向 lane、全双工能力和单向顺序吞吐；10.8 GB/s 为 JEDEC 公布的有效接口上限，不是某颗器件跑分。](/images/42/ill01_pain.png)

eMMC 5.1 可作为接口架构对照。HS400 使用 **8-bit 并行、半双工**总线，理论接口速率为 **400 MB/s**；UFS 使用独立收发差分 lane。两者差异会直接改变设计约束和一致性测试方法，但不能仅凭接口峰值推断具体应用体验。

## 2. 原理、协议栈与代际

### 2.1 数据从命令走到差分线

UFS 的线上数据路径可按下列顺序理解：

**SCSI / UFS 命令、Task Manager、Device Manager → UTP / UPIU → UniPro → M-PHY**

- 应用层处理 UFS 命令集、SCSI 命令、任务管理和设备管理。
- UTP 提供命令、任务和设备管理服务，在线上用 UPIU 承载 Command、Data、Response 等信息。
- UniPro 负责链路、流控、可靠传输和互连管理。
- M-PHY 把信息转换为实际的高速差分信号。

**UFSHCI 不在这条线上。** 它是主机软件与 UFS Host Controller 之间的控制器接口，包含寄存器、UTP 请求描述符、Doorbell、中断和队列等机制。写测试计划时，应把“软件如何把请求交给控制器”和“控制器如何经 UPIU / UniPro / M-PHY 发送”分开。

![图2：UFSHCI、协议栈、数据嵌入时钟和器件 REF_CLK 的分层关系。用于避免把主机控制器接口写成线上协议，或把 REF_CLK 写成高速数据时钟 lane。](/images/42/ill02_whatis.png)

![图3：UFS 数据路径与控制面。UPIU 经 UniPro 和 M-PHY 在线上传输；UIC / DME 用于配置和读回互连属性；UFSHCI 位于 Host 软件与控制器之间。](/images/42/ill03_arch.png)

### 2.2 数据时钟与 REF_CLK

M-PHY 高速 lane 使用**数据嵌入时钟**，接收器从数据边沿恢复采样时钟，相关电路是 CDR。测试 Tx 抖动、Rx 容限或均衡时，讨论的是高速数据、UI、CDR 和参考接收器。

器件 **REF_CLK** 是提供给控制器或 PHY 的参考时钟配置，公开常见频率包括 **19.2、26、38.4、52 MHz**。Linux UFS 文档中的 `ref_clk`、`ref-clk-freq` 与设备属性 `bRefClkFreq` 都属于这一类。REF_CLK 可能影响初始化、PLL、低功耗切换或稳定性，但它不是线上伴随数据传输的独立时钟 lane。

### 2.3 G1 到 G6

G1～G5 按 NRZ、8b/10b 模型理解；Series A 与 Series B 是不同线速率系列。测试记录不能只写“G5”，还要写 Series。公开的 M-PHY 6.0 发布信息把新档位称为 **HS-G6**，本文不把它硬塞进 G1～G5 的 Series A / B 分类。

| Gear | Series A | Series B | HS-G6 公开最大值 | 调制 / 编码 | 两 lane 单方向容量 |
|---|---:|---:|---:|---|---:|
| G1 | 1.2480 Gb/s | 1.4576 Gb/s | — | NRZ / 8b10b | G1B 约 0.292 GB/s |
| G2 | 2.4960 Gb/s | 2.9152 Gb/s | — | NRZ / 8b10b | G2B 约 0.583 GB/s |
| G3 | 4.9920 Gb/s | 5.8304 Gb/s | — | NRZ / 8b10b | G3B 约 1.166 GB/s |
| G4 | **9.9840 Gb/s** | **11.6608 Gb/s** | — | NRZ / 8b10b | G4B 约 2.332 GB/s |
| G5 | **19.9680 Gb/s** | **23.3216 Gb/s** | — | NRZ / 8b10b | G5B 约 **4.664 GB/s** |
| G6 | — | — | **46.694 Gb/s/lane** | PAM4 / 1b1b | JEDEC 公布约 **10.8 GB/s** |

G5B 的 4.664 GB/s 是按 `23.3216 × 2 × 0.8 ÷ 8` 得到的编码后理论容量，尚未扣除更高层协议和系统开销。G6 的符号率约为 **23.347 GBd**，使用新的 **1b1b** 线编码，并支持可选链路均衡训练；不能沿用 G5 NRZ 眼图，也不能只凭 PHY 线速率自行反推应用吞吐。工程文档直接采用 JEDEC 公布的约 10.8 GB/s。这里的“均衡训练”是 G6 新增的独立机制，不等于 Link Startup、能力发现或 Power Mode Change。

![图4：M-PHY G1～G6 工程速率表。用于记录 Gear、Series、调制、符号率和单方向 lane 容量；G6 为 PAM4，不能复用 G5 NRZ 测量方法。](/images/42/ill04_versions.png)

## 3. 设计与正确使用

### 3.1 先把 eMMC 对照模型写正确

eMMC 5.1 HS400 是 8-bit 并行半双工接口，理论 400 MB/s。读方向由 Device 向 Host 发送数据，并提供 **DS** 作为读数据采样参考；写方向由 Host 向 Device 发送数据，Device 以 **CLK** 为采样参考。两套时序不能合成一套预算。

eMMC 5.1 还支持 Command Queuing，最多 **32 个任务**。队列能力会改善并发访问，但不改变 HS400 的并行电气属性。

下面只给出可复算的预算方法。假设 HS400 为 400 MT/s，则 1 UI 为 2500 ps、半 UI 为 1250 ps：

- Read 假设：PCB DQ↔DS skew 55 ps、封装 skew 35 ps、DS→DQ 偏差 220 ps、jitter 70 ps p-p、read setup / hold 各 120 ps。把 p-p jitter 平分到两侧后，setup 与 hold 示例裕量均为 `1250-55-35-220-35-120=785 ps`。
- Write 假设：PCB CLK↔DQ skew 55 ps、CLK→DQ 偏差 100 ps、jitter 70 ps p-p、write setup / hold 各 120 ps。示例裕量均为 `1250-55-100-35-120=940 ps`。

这些板级 skew、器件偏差和 jitter 是**显式教学假设**，用途是说明预算表如何分方向、分 setup / hold 建立；它们不是 JEDEC 限值，也不能用于解释标准为何停在某个速率。

![图5：eMMC HS400 的 Read / Write 时序预算。读方向以 DS 为参考，写方向以 CLK 为参考；图中预算为显式教学假设，不是 JEDEC 限值。](/images/42/ill05_emmc.png)

![动图1：eMMC HS400 从 200 到 400 MT/s 时，Read 与 Write 的半 UI、setup 和 hold 预算如何变化。合成教学模型·非CTS判据·非真实DUT数据，不用于推断标准制定原因。](/images/42/anim01_wall.gif)

### 3.2 UFS 设计输入

原理图和 PCB 评审至少确认：TX / RX 方向没有接反；差分对极性、阻抗、长度和过孔策略满足平台要求；两条 active lane 的拓扑和逃线一致性可控；REF_CLK 频率与器件配置匹配；PHY 与存储子系统供电、回流路径和去耦符合器件指南；测试点、socket 或 interposer 不破坏目标参考面。

速率升高时，固定的上升时间、确定性抖动和通道时间常数会占据更多 UI。下面的动画只解释这一因果关系，不给出 CTS 限值。

![动图2：同一合成通道上从 G4A 扫到 G5B，NRZ 裸眼随 UI 缩短而收缩。图中教学眼图模板为合成教学模型·非CTS判据·非真实DUT数据；连续扫描不是 Link Startup 或标准规定的逐档训练。](/images/42/anim02_gear.gif)

### 3.3 三个链路动作分开记录

1. **Link Startup**：通过 `UIC_CMD_DME_LINK_STARTUP` 拉起 UIC / UniPro 链路。
2. **能力发现**：用 `DME_GET` 读取本地属性，用 `DME_PEER_GET` 读取对端属性，分别确认双方最大 Gear、可用 TX / RX lane 等能力，例如 `PA_MAXRXHSGEAR`、`PA_AVAILTXDATALANES`。
3. **Power Mode Change**：设置并确认 `PA_TXGEAR`、`PA_RXGEAR`、`PA_ACTIVETXDATALANES`、`PA_ACTIVERXDATALANES`、`PA_HSSERIES`、`PA_PWRMODE`。

链路失败后降 Gear 可以是主机或平台实现的恢复策略，但不能写成标准强制的 Link Startup 固定流程。测试记录应保留“请求值、确认值、触发条件、恢复动作”四项证据。

测试模式可通过 UIC / DME、厂商测试固件、socket、interposer 或专用夹具实现，具体入口以 DUT 和对应 CTS 为准。**RMMI 是芯片内部接口**，不能写成 PC 到 DUT 的外部管理口。

## 4. 到底测什么

接口一致性至少分为四个层次，不能用一次系统跑分代替：

| 层次 | 对象 | 主要输出 |
|---|---|---|
| M-PHY 电气 | Tx、Rx、Channel、时钟恢复与电气模式 | 波形、抖动、压力容限、S 参数、参考面和校准记录 |
| UniPro | Link Startup、属性、流控、错误处理、功耗状态 | 状态转换、属性读回、协议错误与恢复记录 |
| UFS / UFSHCI | UPIU、命令、任务管理、设备管理、队列和控制器行为 | 协议一致性、描述符 / 寄存器行为、异常处理 |
| 系统互操作 | Host、Device、固件、板级环境和工作负载 | 兼容矩阵、稳定性、性能与温压结果 |

Tx、Rx 和 Channel 是三套不同问题：

- Tx 测 DUT 发出的信号是否满足对应角色、Gear、Series、lane 和码型条件。
- Rx 测 DUT 在校准压力信号下能否保持目标 BER 或 CTS 规定的接收行为。
- Channel 测两参考面之间的传输损耗、反射和模式转换，为 Tx / Rx 结果提供通道证据。

![图6：Tx、Rx、Channel 三类测量对象。Tx 关注发送质量，Rx 关注校准压力与 BER，Channel 关注 4-port VNA 混模 S 参数；图中曲线和教学眼图模板均为合成教学模型·非CTS判据·非真实DUT数据。](/images/42/ill06_test3.png)

协议测试还要确认 Link Startup、能力发现和 Power Mode Change 的边界。把三者统称为“训练”会掩盖失败阶段，也会让报告缺少可复现的属性读回。

![图7：Link Startup、能力发现与 Power Mode Change 的独立流程。用于规定测试步骤和证据点；错误后降 Gear 仅可作为实现相关恢复策略记录。](/images/42/ill07_bench.png)

测试计划可按“角色 × 方向 × Gear / Series × lane 数 × 功耗状态 × 温压角”建立矩阵。Host TX、Device TX、Host RX、Device RX 分别列项；1 lane 与 2 lane 不合并；G5B NRZ 与 G6 PAM4 不共用测试方法。每个用例写清前置状态、进入测试模式的方法、激励、参考面、观察量、判据、退出条件和失败后需要保留的寄存器。这样可以避免电气项目通过了，实际却遗漏某个角色或 lane 的情况。

功能和互操作项目还应覆盖正常启动、Hibern8 进入 / 退出、重复 Power Mode Change、复位与异常恢复。若项目只关注某一组高性能配置，也要保留低速启动路径和目标配置确认，因为高 Gear 的测量通常建立在前序状态正确的基础上。

## 5. Tx / Rx / Channel分别看什么

### Tx

Tx 项目从 DUT 角色和方向开始：Host TX 与 Device TX 不是同一个测点。记录目标 Gear、Series、lane、pattern、摆幅 / 均衡配置、CDR 或时钟恢复方法、参考接收器处理、测量参考面和去嵌文件。G1～G5 为 NRZ，G6 为 PAM4，应使用对应版本的码型、采集、参考接收器和判据。

观察量通常包括差分幅度、眼图、上升 / 下降时间、确定性与随机抖动、总抖动、占空或交叉特征、共模行为，以及 CTS 指定的其他项目。仪器软件显示“PASS”之前，必须确认测试包版本、码型和参考面没有用错。

Tx 失败时先判断问题随 lane、方向还是 Gear 变化。只有 Lane 1 失败，优先检查该 lane 的焊接、过孔、探测和去嵌；两个 lane 同时在高 Gear 失败，可继续检查共享电源、REF_CLK、PHY 配置和通道损耗。若原始波形稳定而参考接收器后的结果异常，应复核 CDR、均衡和测试包配置，避免把软件处理链问题归到 DUT。

### Rx

Rx 台面由 BERT / 码型发生器产生目标 Gear 和 pattern，再注入 **ISI、SJ、RJ**。压力信号必须在 DUT 接收端规定参考面校准，保存每项应力、校准波形、校准时间和不确定度，然后才接入 DUT。更换线缆、夹具、参考面或温度条件后，按 CTS 要求判断是否需要重校准。

BER 结论必须同时给出目标、观察位数、驻留时间和置信度。统计示例：若目标为 `BER≤1×10^-12`，零误码、单边 95% 置信上界需要观察约

`N=-ln(1-0.95)/10^-12≈2.996×10^12 bit`

在 G5B 单 lane 23.3216 Gb/s 下，理想连续观察时间约为 **128.5 s**。这是 Poisson 零误码统计示例，不是替代 CTS 的统一条件；实际测试是否允许零误码法、是否按 lane 计数、是否需要更长 dwell、重试或分频点扫描，以对应版本 CTS 为准。

Rx 失败需要保存失败应力点，而不只保存最终 BER。至少记录当时的 ISI 文件、SJ 频率 / 幅度、RJ、输出幅度、lane、错误开始时间和累计位数。若失败集中在某段 SJ 频率，可关联 CDR 跟踪区域；若随 ISI 增加单调恶化，可转查通道与接收均衡；若错误呈突发并与电源或温度同步，应把供电和环境日志纳入同一时间轴。

### Channel

Channel 使用 4-port VNA 对完整差分通道进行混模测量。先完成四端口幅相一致的差分校准，再连接左右夹具与 DUT 通道。左右夹具分别建立 S4P 文件，把参考面移动到规定的 Ref A / Ref B，例如两端球脚或 CTS 定义的等效平面。

重点结果包括：

- `Sdd21`：差模到差模的传输，观察插损及频率相关形状；
- `Sdd11`：差模输入反射，观察阻抗不连续和回损；
- `Scd21`：差模输入、共模输出，观察不平衡、过孔或结构引起的模式转换。

混模下标按“输出模式在前、输入模式在后”读取，因此差模转共模是 `Scd`，不是 `Sdc`。这一记法可由 [Teledyne LeCroy 的混模 S 参数说明](https://www.teledynelecroy.com/oscilloscope/blog/mode-conversion-in-mixed-mode-s-parameters/)和 [Panasonic 的参数对照](https://industrial.panasonic.com/ww/design-support/lecture/noise-filters5-3)交叉核对。

报告不能只放一条插损曲线。VNA 端口映射、校准方法、扫频范围、IFBW、功率、电缆稳定性、夹具 S 参数、端口延伸 / 去嵌方法和最终参考面都要可复现。

Channel 结果用于解释链路余量，但不直接替代 Tx 或 Rx 判定。Sdd21 变差说明信号能量衰减增加；Sdd11 峰值常提示局部阻抗不连续；Scd21 抬高则提示差分结构不平衡。若更换板后只有 Scd21 明显变化，应重点检查差分对的不对称过孔、参考平面切换和测试夹具，单纯增加均衡量会掩盖原因。若要观察共模输入转成差模输出，才使用 `Sdc21`。

## 6. 测试台面与参考面

### 6.1 Tx 台面

控制软件通过平台允许的 UIC / DME 或厂商测试固件配置 DUT 输出。差分探头、探针台或专用夹具从 DUT TX 侧取样，示波器执行差分校准并导入探头 / 转接段 S 参数，把结果去嵌到球脚参考面。UFS 器件常焊接在板上，没有统一的外部测试连接器；测试点位置和可去嵌性应在设计阶段确定。

![台面图1：UFS Tx 一致性台面。差分探头从 DUT TX 侧取样，探头与转接段经 S 参数去嵌到球脚参考面；屏中 G5B NRZ 教学眼图模板和 9 dB CTLE 为合成教学模型·非CTS判据·非真实DUT数据。](/images/42/fig_setup_tx.png)

### 6.2 Rx 台面

先断开 DUT，在规定参考面接入校准示波器，分别校准 ISI、SJ、RJ、幅度和其他 CTS 应力；保存校准配置后再接 DUT。误码观察可通过 CTS 规定的 loopback、测试功能、错误计数器或厂商方案完成，不能假设所有器件都有外部 BER 引脚。

![台面图2：UFS Rx 压力测试台面。ISI、SJ、RJ 先在球脚参考面校准，再接入 DUT 并观察 BER；图中 14.8 dB、11 MHz 与容限曲线均为合成教学模型·非CTS判据·非真实DUT数据。](/images/42/fig_setup_rx.png)

### 6.3 Channel 台面

4-port VNA 的 P1 / P2 接差分通道一端，P3 / P4 接另一端。校准先到电缆端，再用左右夹具的 S4P 去嵌到 Ref A / Ref B。端口极性或映射错误会直接污染 Sdd / Sdc 结果，因此连接表应写进测试步骤并在校准后验证。

![台面图3：UFS Channel 的 4-port VNA 台面。完成差分校准后去嵌左右夹具，在 Ref A / Ref B 之间输出 Sdd21、Sdd11、Scd21；图中 11.1 dB 等曲线为合成教学模型·非CTS判据·非真实DUT数据。](/images/42/fig_setup_channel.png)

三套台面的共同要求是：参考面先定义，校准与去嵌再围绕参考面展开。若测试点位于球脚之外，报告应说明扣除了哪些结构、保留了哪些结构，以及 S 参数文件版本。

## 7. 仪器和关键设置

### 示波器与 Tx 软件

示波器带宽、采样率、记录长度和探头带宽要覆盖目标 Gear 与对应 CTS 方法。设置中明确差分通道配对、终端、deskew、采样时钟恢复、CDR 模型、均衡 / 参考接收器、pattern 识别、去嵌和测试包版本。G6 PAM4 需要匹配的 PAM4 采集与分析能力，不能只把 NRZ 垂直刻度改成四电平。

下面的 CTLE 动画只展示高频提升如何改变合成 G5B NRZ 眼。**9 dB、14.8 dB 和教学眼图模板均为合成教学模型·非CTS判据·非真实DUT数据**，不能写成 CTS 规定值、真实测量结果或标准制定依据。

![动图3：合成通道 B 上扫描 CTLE 0～12 dB，观察 G5B NRZ 眼的变化。9 dB、14.8 dB 和教学眼图模板均为合成教学模型·非CTS判据·非真实DUT数据，只用于解释均衡与通道损耗的因果关系。](/images/42/anim03_eq.gif)

### BERT、抖动源与 Rx 校准

设置项至少包括：目标 Gear / Series / lane、pattern、输出幅度、终端、ISI 网络或通道文件、SJ 频率与幅度、RJ rms、校准示波器设置、参考面、BER 目标、观察 bit 数、每点 dwell、扫描顺序和失败重试规则。SJ 扫频时，频点密度要覆盖 CDR 转折区域；不能只测最高频点。

### VNA

Channel 建议使用真正的 4-port 测量，记录 ECal / SOLT / TRL 等校准方法、连接器或探针定义、端口功率、IFBW、点数、平均次数、扫频范围和 time-domain gating 是否启用。S 参数导出应保留 Touchstone 文件、端口定义、阻抗和去嵌前后版本。

### 环境与辅助测量

温度、电压、PHY 电源纹波、REF_CLK 频率与抖动、DUT 固件、Host 固件和驱动版本都可能影响结果。高低温或电压角测试前，确认夹具与探头在目标环境下仍满足校准有效性。

仪器间还要建立统一时间和触发关系。Rx 压力扫描若同时记录供电纹波、REF_CLK 和 UIC 错误，建议由 BERT 或控制脚输出标记，便于把首个误码与环境事件对齐。自动化脚本应锁定仪器配置并导出原始文件，避免操作员只保存截图。软件升级后先用 golden setup 做回归，确认测试包、驱动和去嵌算法没有改变基线。

## 8. 判据从哪里来

判据按层次引用，不跨层代用：

1. **M-PHY CTS**：用于对应 M-PHY 版本、Gear、Series、角色和测试项的电气一致性。
2. **UniPro CTS**：用于链路、状态、属性、流控与互连协议一致性。
3. **JEDEC UFS / UFSHCI**：JESD220H 定义 UFS 5.0，JESD223G 定义 UFSHCI 5.0；分别覆盖设备 / 协议与 Host Controller Interface。
4. **系统互操作规范**：由平台、Host、Device、OEM 或项目定义兼容矩阵、性能和环境要求。

公开公告适合确认版本、架构和公开性能上限，但不能补齐付费或会员 CTS 的详细限值。无法访问对应条款时，报告应写“限值待授权规范确认”，不能根据教学图、仪器默认模板或上一代测试包猜测。

## 9. 报告怎么看

先检查测试条件，再看 PASS / FAIL。一个可复现的 UFS 报告至少包含：

| 类别 | 必填字段 |
|---|---|
| 版本 | UFS、UFSHCI、M-PHY、UniPro、CTS 与仪器测试包版本 |
| DUT 身份 | Host / Device 角色、料号 / 版本、固件、驱动、板号与装配状态 |
| 链路状态 | TX Gear、RX Gear、Series、Active TX / RX lanes、Power Mode |
| 时钟 | REF_CLK 频率与来源；CDR / recovered clock 设置另列 |
| 激励 | pattern、幅度、ISI、SJ、RJ、扫描点、测试方向 |
| 参考面 | Tx / Rx / Channel 参考面定义、探头 / 夹具拓扑、照片或连接图编号 |
| 校准与去嵌 | 校准时间、方法、S 参数文件名 / 版本、去嵌链、校准有效期 |
| 接收处理 | CDR、参考接收器、CTLE / DFE 或 PAM4 相关设置 |
| BER | 目标、错误数、观察 bit 数、驻留时间、置信度和中断 / 重试情况 |
| 环境 | 温度、各电源电压、负载、REF_CLK、供电纹波条件 |
| 质量 | 仪器误差、校准残差、重复性和测量不确定度 |

读波形时要确认横纵轴、参考面和处理链。读 BER 时确认分母；只写“0 error”没有统计意义。读 S 参数时确认端口映射与去嵌状态。读协议报告时确认失败发生在 Link Startup、能力发现、Power Mode Change、UPIU 还是更高层命令阶段。

跨实验室对比时，优先核对 CTS / 测试包版本、参考面、S 参数文件、CDR / 均衡和温压条件。任何一项不同，都可能让数值不可直接横向比较。

报告结论建议分成“满足判据”“不满足判据”“条件不完整”“仅供趋势观察”四类。校准过期、参考面不明、观察 bit 数不足或使用了错误测试包时，不应给出正式 PASS / FAIL。合成教学图和工程预扫可以用于选择频点、带宽和 A/B 条件，但最终签核要回到授权 CTS 的条款号、限值、测试配置和原始证据。

## 10. Debug闭环

### 10.1 先读链路，再分层看错误

下面是 Linux 公开头文件可见的字段格式，用于说明应采集什么证据。**公开字段示例，非真实DUT日志**：

```text
$ DME_GET(public PA attributes)
PA_TXGEAR               [0x1568] -> 5
PA_RXGEAR               [0x1583] -> 5
PA_ACTIVETXDATALANES    [0x1560] -> 2
PA_ACTIVERXDATALANES    [0x1580] -> 2
PA_HSSERIES             [0x156A] -> 2
PA_PWRMODE              [0x1571] -> 0x11
```

示例值只演示字段，不代表任何板卡当前运行状态。Linux `unipro.h` 给出了 PA 属性名和地址；实际读回方式取决于驱动、调试接口、权限和平台实现。

随后读取 UFSHCI 的 UIC 五层错误寄存器类别：

```text
REG_UIC_ERROR_CODE_PHY_ADAPTER_LAYER  0x38
REG_UIC_ERROR_CODE_DATA_LINK_LAYER    0x3C
REG_UIC_ERROR_CODE_NETWORK_LAYER      0x40
REG_UIC_ERROR_CODE_TRANSPORT_LAYER    0x44
REG_UIC_ERROR_CODE_DME                0x48
```

PHY Adapter 错误优先关联电气、lane、CDR、均衡和通道；Data Link、Network、Transport 与 DME 类别用于缩小协议与管理层范围。错误寄存器需要结合时间戳、计数变化、触发负载和链路状态解释，不能只截一次静态值。

分层定位时保留“首次异常层”和“后续连带层”。例如 PHY Adapter 先报错，随后 Data Link 出现重放或超时，根因可能仍在电气侧；如果 PHY 层稳定而 Transport 或 DME 单独持续报错，再转向连接、属性和管理流程。清零计数器后重复同一负载，可以确认错误出现顺序；没有清零和时间戳的累计寄存器，难以支持根因判断。

![图8：Linux 公开 PA 属性与 UFSHCI UIC 五层错误寄存器类别。图中终端内容为公开字段示例，非真实DUT日志，用于建立先读状态、再按层定位的证据链。](/images/42/ill08_debug.png)

### 10.2 做受控 A/B

一次只改变一个变量，并保留变更前后的 PA 属性、错误计数、吞吐与电气证据：

1. **Gear A/B**：目标 Gear 与较低 Gear 对比，观察错误率和稳定性是否随 UI 放宽而改善。
2. **lane A/B**：2 lane 与 1 lane 对比，区分单 lane 缺陷、lane 间不一致或 lane 配置问题。
3. **板 / 夹具 A/B**：golden board、另一块板、替代夹具或去嵌文件对比。
4. **温度 / 电压 A/B**：在规格允许范围内改变温压，观察边界是否移动。
5. **REF_CLK A/B**：核对频率配置、源质量和板级分配，不把它与数据 CDR 混为一项。
6. **供电 A/B**：改变负载或测量 PHY / 存储电源纹波、跌落和噪声耦合。

若实现相关恢复策略在错误超过阈值后请求降 Gear，必须记录触发条件和 Power Mode Change，禁止写成“标准自动逐档训练”。动画中的 1 s 窗口、阈值、G5B→G4B 和性能指数都只是策略教学示例。

![动图4：错误计数超过教学阈值后，主机策略请求 G5B→G4B Power Mode Change。公开字段示例，非真实DUT日志；恢复窗口、阈值与性能指数为合成教学模型·非CTS判据·非真实DUT数据，不表示跑分精确变化。](/images/42/anim04_train.gif)

### 10.3 恢复目标配置复测

A/B 找到敏感变量后，修复设计、固件、配置、夹具或校准问题，再恢复目标 Gear、Series、lane、Power Mode、REF_CLK、温压与原始负载。最终复测应同时满足：

- PA 属性确认回到目标配置；
- UIC 五层错误计数在规定窗口内符合项目要求；
- 对应 Tx / Rx / Channel 或协议项通过授权判据；
- 系统负载下没有复现原故障；
- 报告保留修复前、A/B、修复后证据。

## 11. 工程师速查

| 问题 | 先做什么 | 关键证据 |
|---|---|---|
| 跑分变慢 | 先读 Gear、Series、ActiveLanes、PWRMODE | PA 属性、工作负载、温压；不要先假定是眼图 |
| Link Startup 失败 | 确认 UIC 命令结果与 PHY / DME 错误 | `UIC_CMD_DME_LINK_STARTUP`、0x38～0x48 |
| 能力不符 | DME_GET 读本地，DME_PEER_GET 读对端 | `PA_MAXRXHSGEAR`、`PA_AVAIL*DATALANES` |
| 目标档未生效 | 检查 Power Mode Change 请求与确认 | `PA_TXGEAR`、`PA_RXGEAR`、ActiveLanes、HSSeries、PWRMode |
| 高 Gear 错误增加 | 做 Gear、lane、板 / 夹具、温压、供电 A/B | 错误计数趋势、Tx / Rx / Channel 数据 |
| Tx 不通过 | 核对角色、pattern、参考面、去嵌、CDR / 均衡 | 原始波形、处理链、S 参数文件、CTS 版本 |
| Rx 不通过 | 重查压力校准和 BER 统计量 | ISI / SJ / RJ、bit 数、dwell、置信度 |
| Channel 异常 | 复核 4-port 校准、端口映射与夹具去嵌 | Sdd21、Sdd11、Scd21、Ref A / Ref B |
| REF_CLK 相关 | 核对 19.2 / 26 / 38.4 / 52 MHz 配置与源质量 | `ref_clk`、`bRefClkFreq`、频率 / 抖动 / 电源 |
| eMMC HS400 对照 | Read 看 DS，Write 看 CLK，预算分方向 | 8-bit、半双工、400 MB/s、CQ 最多 32 tasks |
