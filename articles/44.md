# 同一块 Gen5 SSD，为什么这个槽跑满、那个槽会回退？

<div class="article-meta"><span class="badge">📘 模块六 · 高速接口一致性测试 · PCIe</span><span class="badge">⏱ 约 10 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


> PCIe 不是“看到一张眼图就结束”的接口。它把 **Tx 合规、Rx 容限、通道、链路训练和协议互操作**分成不同对象；掉到 Gen1 或 x4，只是告诉我们该从哪一层开始找证据。

同一块 Gen5 SSD，插 CPU 直连槽能跑满，换到另一个槽却协商到低代；一张 x16 卡又只跑 x4。这个现象常常让人先怀疑卡、SSD 或驱动，但不能据此断言根因。插槽拓扑、通道损耗、过孔和连接器、参考时钟、训练协商、平台分 lane 策略、固件，甚至插接与供电，都可能参与。

这一篇只做一件事：把“掉速”拆成可测对象。下面的眼图、阈值和翻转均来自 `pcie_phys.py` 的**教学模型**；它们说明趋势，不是 PCI-SIG CTS 模板，也不能直接写进产品报告。

![图1：同一设备在不同槽表现不同，是分层定位的入口，不是单一根因证明。](/images/44/ill01_pain.png)

## 一、链路、lane、速率、宽度：先读协商结果

PCIe 是点对点串行差分互连。Root Complex 通常在 CPU、SoC 或芯片组，Endpoint 可以是 SSD、GPU、网卡或加速卡。每条 lane 都有一对 Tx 和一对 Rx，因此是全双工；x1、x4、x8、x16 是多条 lane 叠加出来的宽度。

数据线上没有转发时钟。接收端用 CDR 从数据边沿恢复采样时钟，所以它属于“看眼图”的串行接口。与此同时，PCIe 还有供两端 PLL 使用的参考时钟；它不能和数据的嵌入式时钟混为一谈。

![图2：PCIe 的 Root Complex、Endpoint 与全双工 lane。](/images/44/ill02_link.png)

速率是 Gen 和 GT/s，宽度是 xN。先记录两者，连同发生回退的时间点、LTSSM 状态和错误计数，才有后续定位的起点。x16 变 x8 或 x4 也不必然等于“最后几根线坏了”：平台拓扑和 bifurcation 配置必须先排除。

### Common Clock、SRNS、SRIS：剩下的相对误差不一样

Common Clock 下两端使用同源 refclk，通常相对漂移较小。SRNS 是独立时钟且不使用 SSC；SRIS 是独立时钟且各自使用 SSC。后三者不是简单的“好/坏”排序，而是 CDR、抖动预算、校准和验证条件不同。

SSC 是**下扩频**概念：时钟为分散辐射峰值而向低频方向调制，不应简化成“±0.5% 抖动”。做抖动分析时，CDR 或 golden PLL 的设置要按适用规范和架构匹配；不匹配会把应当跟踪的调制误算进残余抖动。

![图3：三种参考时钟架构与教学残余量，明确 SSC 是下扩频。](/images/44/ill03_clock.png)

## 二、Gen1 到 Gen6：NRZ、PAM4 与有效带宽别混读

Gen1/2 使用 8b/10b，Gen3/4/5 使用 128b/130b，Gen6 引入 PAM4、FLIT 和 FEC。公开资料通常把 Gen6 标为 64 GT/s；其 PAM4 符号率仍是 32 Gbaud，与 Gen5 同阶，但每个 PAM4 符号承载两 bit。GT/s、编码效率、协议开销和应用实测 GB/s 是不同层面的数字。

| 代际 | 公开线速率 | 物理编码重点 | 每 lane 理论带宽理解 |
|---|---:|---|---|
| Gen3 | 8 GT/s | 128b/130b、NRZ | 约 1 GB/s，未含协议实际开销 |
| Gen4 | 16 GT/s | 128b/130b、NRZ | 约 2 GB/s，未含协议实际开销 |
| Gen5 | 32 GT/s | 128b/130b、NRZ | 约 4 GB/s，未含协议实际开销 |
| Gen6 | 64 GT/s | PAM4、FLIT、FEC | 约 8 GB/s 的编码层近似，系统开销另算 |

![图4：代际、编码和 GT/s 的关系；不把 GT/s 直接等同应用吞吐。](/images/44/ill04_gens.png)

## 三、通道与 preset：眼为什么会先好、再坏

通道不是一根理想线。封装、FR4 走线、过孔和连接器随频率带来损耗；阻抗不连续还会反射。它们叠加为边沿变慢、码间串扰、振铃和抖动。第 44 篇模型把这几项显式放进去，方便扫描一个旋钮时不丢掉原因。

![图5：教学通道由封装、走线、过孔、连接器和反射共同组成。](/images/44/ill05_channel.png)

Tx FFE preset 的目标是抵消一部分高频损失。补得太少，远端高频不够；补得太多，过冲、振铃和噪声同样会伤害判决窗口。因此“把 preset 开大”不是调试方法。

![图6：真实模型眼图随 Tx FFE 扫描经历欠均衡、接近匹配和过均衡。](/images/44/ill06_eq.png)

![动图1：走线变长后，模型由高代往低代回退；端点与翻转以动图 meta.json 为准。](/images/44/anim01_channel.gif)

![动图2：Tx FFE 连续扫描出现欠均衡 FAIL、可用区和过均衡恶化；判据为教学判据。](/images/44/anim02_preset.gif)

这里的 FAIL/PASS 只表示模型的教学眼高、眼宽判据，不是 Tx 合规结论。真正的 Tx 合规测试需要适用的测试模式、测试点、夹具、参考面、分析模型和规范流程。

## 四、LTSSM 与 Recovery.Equalization：训练不是“自动修好一切”

链路训练由 LTSSM 驱动。达到更高代时，Recovery.Equalization 会围绕速率、Tx preset 和接收均衡做协商；如果条件不能满足，链路可能选择可工作的较低速率或较低宽度。训练结果很有价值，但它是**定位证据**，不能单凭一次回退就把根因锁死为“信号差”。

![图7：Recovery.Equalization 在链路状态机中的角色，以及四类测试对象不可互相替代。](/images/44/ill07_recovery.png)

xN 的木桶效应同样要谨慎解释：多条 lane 的一致性、连接和板级拓扑都会影响最终可用宽度。下图只演示“最差 lane 拖低可训练宽度”的物理趋势。

![动图3：x16 的教学 lane 集合中，最差 lane 增加损耗后，模型宽度可回退至 x8 或 x4。](/images/44/anim03_lane.gif)

## 五、Gen6 PAM4、FLIT、FEC：三眼要把 FEC 前后说清

NRZ 是两电平、一只眼；PAM4 是四电平、上中下三只眼。PAM4 用更多电平提高每符号携带的信息量，同时把电平间距压得更紧。因此评估需要看三只眼、电平分离等质量，而不是只看一张 NRZ 式单眼图。

FEC 的作用是纠正一定范围内的前纠错错误。它不是“物理层不需要裕量”的许可证；报告和调试要明确口径：观察的是 FEC 前错误风险、FEC 后错误表现、还是业务层后果。也不要把 Gen6 说成“假翻倍”或“天然误码高”——应准确说它在相近符号率下使用 PAM4，并以 FLIT/FEC 配合完成系统设计。

![图8：Gen6 PAM4 三眼与 FEC 前风险概念，数值来自教学模型。](/images/44/ill08_pam4.png)

![动图4：教学通道损耗增加时，PAM4 三眼和 FEC 前风险指数同步变化。](/images/44/anim04_pam4.gif)

## 六、Tx、Rx、通道、协议/互操作：四类证据各回答各的问题

| 对象 | 主要回答的问题 | 不能替代什么 |
|---|---|---|
| Tx 合规 | 发送端在规定条件、参考面和分析流程下是否满足要求 | 不能替代 Rx 容限 |
| Rx 容限 | 接收端面对校准压力信号时还能否可靠恢复 | 不能替代通道测试 |
| 通道 / CEM | 互连的 S 参数、损耗、回损、串扰及治具/拓扑是否符合适用要求 | 不能替代系统互操作 |
| 协议 / 互操作 | LTSSM、错误、Recovery、配置与系统行为如何关联 | 不能替代任一物理层合规结果 |

PCIe 不“独创”参考封装或 DFE；各类高速链路都会使用参考模型和均衡。PCIe 的测试流程为何常见 embed、参考接收器或行为级 DFE，取决于所测对象和适用方法。不要把它描述成“所有 PCIe 都只判均衡后眼”，更不能把一套公开教学模型冒充受控 CTS。

## 七、通道 / CEM：先把参考面和治具讲明白

通道测量面对的是互连：PCB 走线、过孔、连接器、线缆、卡边和治具。S 参数、参考面、去嵌/嵌入、校准状态和被测拓扑必须一起记录。CEM 讨论的板卡/插槽环境也不能和 Base Spec 的协议、电气定义混成一本“万能判据”。

示波器带宽不要套“0.7 到 1 倍波特率”的通用口诀。带宽、采样、夹具、探头、CDR、分析软件和适用测试方法要由被测代际和目标测量决定；不清楚时先查公开版本的规范、仪器应用手册和实验室受控流程。

## 八、分层定位：把一次掉速变成一张证据链

1. **先读链路**：记录实际 Gen、xN、LTSSM、Recovery 与错误计数，并核对平台拓扑、bifurcation 和固件策略。  
2. **再看通道 / 电气**：用正确参考面测损耗、回损、串扰，复核 FFE/CTLE/DFE 与分析模型。  
3. **看 refclk / CDR**：确认 Common Clock、SRNS 或 SRIS，SSC 设置和测量恢复环路的匹配。  
4. **看协议 / 互操作**：将协议分析仪的训练、错误、重放和回退事件与电气证据对齐。  
5. **最后回到系统条件**：供电、温度、插接、机械应力、固件与电源管理策略都要留痕。  

![图12：分层定位顺序，避免把“掉速”直接等同于某一条线的眼图问题。](/images/44/ill10_debug.png)

## 九、测试计划：让复现结果能被别人复查

- 建立矩阵：平台、Endpoint、插槽、Gen、xN、温度、供电模式、固件版本、时钟架构。  
- 每次测试保留：拓扑图、测试点、参考面、夹具/S 参数版本、仪器设置、校准证据、原始波形或日志。  
- 将 Tx、Rx、通道、协议的结论分别写；关联可以写，替代不可以写。  
- Gen6 单独标明 PAM4 三眼、电平质量、FEC 前后观察口径和延迟/错误统计窗口。  
- 不满足条件时写“未覆盖”或“需复测”，不要用一张好看的均衡后眼图替代缺失试验。

![图13：PCIe 测试速查：对象、证据与不可替代关系。](/images/44/ill11_quickref.png)

## 写在最后

PCIe 最实用的排障口诀是：**先读协商 Gen/xN，再分开 Tx、Rx、通道和协议；时钟架构与参考面全留档，PAM4 把 FEC 前后分开讲。**

### 最小记录清单

| 类别 | 必留字段 |
|---|---|
| 链路 | Gen、xN、LTSSM/Recovery、错误计数、发生时间 |

| Tx / Rx | 测试状态、码型、适用 preset、CDR/分析模型、压力源校准、BER 窗口 |
| refclk | Common/SRNS/SRIS、SSC 条件、仪器恢复环路设置 |
| Gen6 | PAM4 三眼/电平质量、FEC 前后口径、统计窗口、延迟观察 |

### 公开资料入口

- PCI-SIG：PCI Express Base Specification 与 CEM Specification 的公开介绍和版本信息。  
- PCI-SIG：PCIe 6.0 / 7.0 的公开新闻稿与技术概览，用于确认 PAM4、FLIT、FEC 等代际方向。  
- 仪器厂商的 PCIe 测试应用资料：用于了解测试点、夹具、CDR、S 参数和校准步骤；具体设置以适用版本、许可证和实验室流程为准。  

### 不该写进报告的句子

- “一大半掉速都是链路问题。”——没有适用数据来源。  
- “Gen4/5 裸眼基本全闭，PCIe 从来不判裸眼。”——绝对化且混淆测试对象。  
- “带宽按 0.7 到 1 倍波特率选。”——不是跨平台通用规则。  
- “Gen6 是假翻倍、天然误码高。”——不准确；要明确符号率、PAM4、FEC 和观察口径。
