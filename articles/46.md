# 同一套主机和扩展坞，换根 Type-C 线，80G 为什么掉到 20G？

<div class="article-meta"><span class="badge">📘 模块六 · 高速接口一致性测试 · Thunderbolt / USB4</span><span class="badge">⏱ 约 19 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


同一台主机、同一个Thunderbolt 5扩展坞、同一块高速固态和同一台显示器，合格的被动线A接上后协商到80Gbps，显示与存储可以同时工作；换成同规格、同长度的被动线B，设备没有完全消失，链路却只剩20Gbps，显示能力下降，固态吞吐也跟着掉。

最容易犯的错误，是马上下结论：**线B坏了。**

但“换线后恢复”只能证明问题跟这根线参与的路径有关，不能证明根因一定是铜线损耗。线缆能力标识、连接器接触、主动线缆内部Retimer、链路训练、电气裕量、供电和隧道建立，都可能改变最终结果。

这一篇只做一件事：**把一次80G→20G回落，沿着证据链查到可以关闭。**

![图1：固定主机、坞、固态和显示器，只换同规格被动线；线A稳定80Gbps，线B方向1回落20Gbps。](/images/46/ill01_case.png)

---

## 一、先把翻车条件钉死：一次只换一根线

开始测试前，先建立基线。主机固件、操作系统、电源模式、扩展坞、固态、显示器、端口、插接方向、温度和业务负载全部固定，只替换线缆。

| 条件 | 线A | 线B |
|---|---:|---:|
| 主机 / 坞 / 固态 / 显示器 | 相同 | 相同 |
| 端口、插接方向、供电 | 相同 | 相同 |
| 型号/认证标称能力 | USB 80Gbps / TB5 | USB 80Gbps / TB5 |
| 实际协商 | 80Gbps | 20Gbps |
| 现象 | 显示与高速存储同时工作 | 显示能力下降、存储吞吐下降 |

这里的80G和20G是本篇贯穿案例的**链路状态示例**，用来说明排查方法；正式项目必须保存平台实际日志和认证工具输出，不能拿本文数字替代产品报告。

第一条结论已经出来了：**口型没变，功能也没有完全断，但高档链路没有建立。**所以接下来不应该先看文件拷贝速度，而应该先问：双方原本支持什么，最后到底协商成了什么？

---

## 二、第一步不是抓眼图，而是保存能力与协商证据

USB Type-C、USB4和Thunderbolt不是同一个概念：

- **Type-C**说明连接器和引脚体系；
- **USB4 / Thunderbolt**说明高速链路、路由和产品能力；
- **DisplayPort、PCIe和USB数据**是链路实际承载的业务。

![图2：Type-C连接器、USB4/Thunderbolt高速链路和可承载业务是三个层次。](/images/46/ill02_capability.png)

对于线B，先保存下面四组证据：

1. **主机、坞和线缆的可追溯能力**：官方规格、认证记录、准确型号，以及平台能读到的线缆识别信息；
2. **实际协商档位**：20、40还是80Gbps，方向和模式是什么；
3. **链路事件**：训练失败、重试、Recovery、回落和重新连接发生了几次；
4. **业务状态**：显示、PCIe隧道和USB数据中，哪些真正建立。

如果准确型号或认证记录显示线B本来就只支持20Gbps，问题到这里基本结束：这是**能力不支持**，不是信号质量失效。不要只凭线身印字、包装或外观判断；平台能读到哪些线缆信息也取决于线缆类型和实现。

如果线B有可追溯的80Gbps规格或认证证据，但实际只能建立20Gbps，才进入下一层：**它为什么守不住高档？**

> **一句话记住：先分“不会”还是“做不到”。准确型号或认证记录没有80G，叫不会；有可追溯的80G能力证据却反复回落，才叫做不到。**

---

## 三、把问题切成三层：Channel、Tx/Rx、隧道

一根线参与的失败，不能只靠一张眼图或一次拷文件判断。按照第35篇的一致性测试框架，把证据分成三层：

| 层级 | 本案例要回答的问题 | 关键证据 |
|---|---|---|
| Channel | 线缆、连接器和路径是否吃掉了高档通道预算 | 通道损耗、回损、串扰、线缆能力与方向 |
| Tx / Rx | 发送端是否发得合格，接收端能否承受规定压力 | 规定测试模式、波形/抖动、压力眼、BER、错误计数 |
| 路由 / 隧道 | 电气链路建立后，显示和PCIe/USB业务是否正确建立 | 协商日志、隧道状态、吞吐、恢复事件 |

![图3：一张眼图不能证明隧道正确，一次拷贝满速也不能证明链路有余量。](/images/46/ill06_test_layers.png)

排查顺序也由这张表决定：

- 高档根本训不上，优先查能力、Channel和Tx/Rx；
- 高档稳定建立，但只有某项业务失败，再查路由、隧道和互操作；
- 大负载、热插拔或休眠恢复才失败，还要把USB PD与恢复时序纳入。

本案例是**80G训不上、回落20G**，因此先走电气与通道，不先研究带宽调度。

---

## 四、一致性测试环境怎么搭：先把三套台面分开

Thunderbolt / USB4的一致性测试不是一台示波器包打天下。至少要分成Channel、Tx和Rx三套台面；协议与隧道日志作为第四组旁证。混用台面最常见的后果，是把夹具损耗判成DUT失败，或者目标档已经回落，仪器还在分析一段无效波形。

### 台面A：Channel——VNA看线缆与连接器

**仪器与连接：** 矢量网络分析仪（VNA）→ 同轴线缆 → Type-C测试夹具 → 被测线缆或通道 → 对端夹具 → VNA。本案例的线A和线B都是被动线缆，因此可以按适用方法测差分S参数。主动线缆带有有源器件，必须按其工作方向、供电和专用测试方法处理，不能照搬本案例的无源VNA/TDR流程。

![图4：Channel台面把VNA、两端夹具、被动线缆和参考面串起来；每个lane和方向单独保存结果。](/images/46/ill04_channel_bench.png)

**搭建动作：**

1. VNA预热后完成端口校准，把校准面尽量推到夹具同轴端；
2. 测量或导入夹具S参数，按适用规范做去嵌，把最终参考面移到Type-C连接界面；
3. 按lane和方向逐项测量，主动线缆还要固定插入方向；
4. 保存插损、回损、串扰等曲线以及原始Touchstone文件；
5. 记录线缆型号、长度、弯折状态、温度、夹具编号和去嵌文件版本。

Channel测试的目标不是证明“这根线看起来做工不错”，而是回答：**从规定参考面看进去，这条路径在目标速率下是否仍落在通道预算内？**

补充说明：如果排查对象是主动线缆，内部可能带Retimer。Retimer会恢复时钟和数据后重新发送，但它不是无损放大器：输入侧必须先收得到，输出侧也必须重新满足发送端要求。这个分支不属于本案例根因。

### 台面B：Tx——示波器看DUT发出的信号

**仪器与连接：** DUT → Type-C一致性测试夹具 → 高频同轴线 → 高带宽实时示波器或适用的采样系统。另一侧由一致性工具、控制器或专用夹具负责让DUT进入规定测试模式。

![Setup A：Tx台面由DUT、Type-C夹具、同轴链路和示波器组成；测试模式、lane、方向、参考面、校准和去嵌必须写入记录。](/images/46/fig_setup_txrx.png)

**搭建动作：**

1. 用适用的一致性工具确认DUT进入目标代际、目标档位、目标lane和规定测试码型；
2. 校准示波器通道、同轴线与夹具，加载正确去嵌文件；
3. 在规范规定的参考面应用参考接收器、CDR和测试模板；
4. PAM3模式确认上下两只眼和三个电平都被正确识别，不能套用NRZ模板；
5. 每次切换lane、方向或码型，都重新截图并保存原始波形与软件报告。

### 台面C：Rx——BERT给DUT注入规定压力

**仪器与连接：** 误码仪（BERT）或适用合规测试设备Tx → 规定损耗/抖动注入路径 → Type-C夹具 → DUT Rx；DUT的回传、错误计数或环回数据再送回BERT或由一致性软件读取。

**搭建动作：**

1. 先不用DUT，在规定参考面校准压力信号；
2. 按测试项目加入规定的损耗、抖动和噪声，保存校准后的压力眼；
3. 接入DUT，确认目标档没有回落，并让DUT进入规定接收测试状态；
4. 运行规定码型和测试时间，记录误码、错误计数、Recovery和掉链事件；
5. 改变lane或方向时重新确认校准是否仍适用。

### 台面D：协议旁证——确认“正在测的就是目标档”

协议分析器或平台日志不是Tx/Rx仪器的替代品，但它必须与三套电气台面同步记录。每轮测试至少保存：双方能力、线缆识别、实际协商档位、训练重试、Recovery、隧道状态和掉链时间戳。这样才能确认示波器或BERT看到的信号，确实来自目标80Gbps状态，而不是回落后的20Gbps链路。

## 五、测试结果怎么判：先验证测试有效，再看单项margin

一致性软件亮出红色FAIL之前，先做“有效性检查”。下面任一项不成立，本轮结果都应该判为**无效测试**，而不是DUT FAIL：

- DUT确实处于目标代际、档位、lane、方向和测试模式；
- 校准未过期，夹具与去嵌文件编号正确；
- 参考面、参考接收器、CDR和模板对应当前规范版本；
- 波形没有削顶、过载或明显连接异常；
- Rx压力信号在接入DUT前已经于规定参考面校准。

![图5：判结果前先确认目标状态、校准/去嵌、分析设置和Rx压力信号都有效。](/images/46/ill05_result_gate.png)

80Gbps / Thunderbolt 5使用PAM3，有三个电平和上下两只眼；不能拿NRZ的一只眼模板直接判。

![图5：NRZ与PAM3的电平和眼数对比。](/images/46/ill05_pam3.png)

确认测试有效后，再按下面的顺序判：

| 测试 | PASS依据 | 除PASS/FAIL外必须保存 |
|---|---|---|
| Channel | 适用规范要求的通道项目全部满足 | 每个lane/方向的最差频点、margin、曲线和Touchstone |
| Tx | 规定码型、参考接收器和模板下，全部发送端项目满足 | 最差lane、最差方向、单项margin、原始波形 |
| Rx | 校准压力信号下，规定测试时间内满足BER或错误要求 | 实际注入压力、累计bit/时间、误码、Recovery和掉链 |
| 隧道/互操作 | 目标链路稳定建立，规定业务在测试窗口内持续运行 | 档位、显示模式、吞吐、错误与恢复日志 |

判定时不要只抄总结果。若四个lane都PASS，但其中一个lane只剩很小margin，报告仍要把它列为量产和温度复测重点；若软件总结果FAIL，也必须写清是哪个项目、哪个lane、哪个方向、距离限值多少。

本案例的结论模板应写成：

> 线B在目标80Gbps、方向1和特定lane下出现高频回损负margin；同一台面、同一校准和同一条件下，线A对应项目通过并保有正margin。该失败项与线B回落20Gbps重复出现，下一步用TDR定位阻抗异常位置。

公开资料不足以给出全部正式限值，因此本文不编造眼高、眼宽、S参数或BER门槛。**项目报告必须引用适用版本的USB-IF CTS、Intel Thunderbolt认证要求及授权工具结果。**

## 六、问题怎么Debug：把线B定位到“连接器附近的阻抗不连续”

下面沿着本案例真实走一遍。最终根因不是笼统的“线损太大”，而是：**线B在一个插入方向、一个lane上出现连接器附近的阻抗不连续，高频回损恶化；80G最先失去margin并训练失败，系统最终回落20G。**

这里不写受控规范的具体限值，只展示如何用证据逐步排除、定位和修复。

### 1. 先证明不是台面

保持仪器、夹具、校准、去嵌、码型和软件版本不变，换上已知通过的Golden线缆或Golden DUT。如果Golden样品也失败，优先查台面；如果Golden稳定通过而线B稳定失败，才继续分析线B路径。

本案例中，线A在相同台面、lane和方向下重复通过；线B重复出现目标档失败。交换VNA端口和两块夹具后，异常仍跟着线B走。因此可以先排除示波器、VNA端口和单块夹具。

### 2. 用方向和lane把范围缩小

接着只改变一个变量：

- 线B按方向1插入：目标80G反复训练失败；
- 线B翻转到方向2：80G可以建立，但margin明显弱于线A；
- 分lane测量：异常集中在方向1对应的一组高速差分通道；
- 对比直线与正常弯折：异常位置不随线身弯折移动。

失败同时依赖**线B、插入方向和特定lane**，范围已经从“整套系统”缩到“线B某一端连接器及其对应通道”。如果是线材全长介质损耗，通常不会只盯住一个连接器方向；如果是主机或坞问题，异常不会始终跟着线B走。

### 3. 用VNA看频域，再用TDR找位置

VNA结果显示：异常lane的插损整体没有比其他lane差到足以单独解释回落，但回损在高频段明显恶化。这个组合很关键：

- **插损整体恶化**更像线长、导体或介质损耗；
- **局部回损恶化**更像某个位置阻抗不连续；
- **只在一个lane异常**又把怀疑点进一步指向触点、焊接或局部几何结构。

![图6：线A与其他lane的回损保持正常，线B的异常lane在高频段明显恶化。](/images/46/ill06_vna_debug.png)

随后用TDR观察差分阻抗随距离的变化。异常台阶出现在靠近线B一端连接器的位置；翻转测试后，这个异常仍跟着同一个物理端。频域的回损异常与时域的位置证据互相吻合，根因由“线可能不好”收敛为：**该端连接器附近存在局部阻抗不连续。**

![图7：TDR把异常台阶定位到线B一端连接器附近，与VNA回损异常形成交叉证据。](/images/46/ill07_tdr_debug.png)

### 4. 为什么它会让80G掉到20G

80G使用PAM3，三个电平把原有电压空间切得更细；连接器处的反射返回接收端后，会同时压缩电平间隔并扰动采样时刻。目标档训练无法得到足够裕量时，链路不会一定彻底断开，而是尝试更低档位。20G的单位间隔与电压裕量更宽，因此同一处不连续在20G仍可能“能用”。

这解释了三个现象为什么同时出现：

1. 线B没有完全断路，设备仍能识别；
2. 80G反复训练失败；
3. 回落20G后显示和存储还能工作，但能力与吞吐下降。

### 5. 解决办法必须对应根因

针对这个根因，解决办法不是“软件强制80G”，也不是盲目增加均衡，而是处理连接器端的阻抗不连续：

- **量产线缆问题：** 隔离该批次，检查连接器端接、差分对剥线长度、焊接/压接、屏蔽与应力固定；返修或更换线缆后重测；
- **自研线缆或板端结构：** 缩短失去参考面的差分段，保持两线对称，优化焊盘/过渡区几何，减少残桩和多余焊料；
- **接触问题：** 清洁或更换连接器，检查触点变形、异物、镀层和插拔磨损；
- **主动线缆：** 除连接器外，还要检查该方向Retimer供电、参考时钟与lane映射，但必须有对应测量证据再改。

如果项目只是整机集成、无法返修商用线缆，工程处置就是更换满足相同规格且通过Channel测试的线材，并将失败线的型号、批次和方向特征反馈供应商。**强制锁定高档会把可恢复的降档变成掉链或误码，不是修复。**

### 6. 修复后做双向交叉验证

修复件回到原VNA/TDR台面后，连接器附近的异常台阶消失，原异常lane的回损恢复正margin；换回原失败线，异常再次出现。随后在系统台面按两个插入方向复测，80G均能稳定建立。

这个“修复件PASS + 原失败件仍FAIL”的双向交叉验证很重要：它证明结果变化来自修复，而不是重新校准、温度变化或某次插接碰巧改善。

![图8：修复动作必须对应连接器端阻抗不连续，修复后同时验证回损、TDR和系统80G状态。](/images/46/ill08_fix_verify.png)

这也是为什么“换线就好”不能直接关闭问题。真正可关闭的结论应写成：

> 在固定主机、坞、固态、显示负载、端口和温度条件下，被动线B方向1的特定lane出现高频回损负margin；TDR将阻抗异常定位在线B一端连接器附近。处理该端接结构后，原lane和两个方向的Channel项目恢复通过，80Gbps稳定建立，原显示与存储并发组合连续复测通过；原失败件复测仍能重现异常。

如果没有这条证据链，只能写“现象随换线消失”，不能写“根因已确认”。

## 七、修复后必须回到原始组合复测

本案例的闭环不是“换上好线，跑一次测速软件”，而是回到开头完全相同的条件：

1. 同一主机、固件、OS与端口；
2. 同一扩展坞、固态和显示器；
3. 同一供电、温度、插接方向和负载；
4. 重新保存能力与协商日志；
5. 确认目标80Gbps稳定建立；
6. 重跑原来的显示+存储并发场景；
7. 记录训练、错误、恢复和吞吐证据。

![图9：固定条件与保存证据。](/images/46/ill10_evidence.png)

修复前是“声明80G、方向1实际20G、特定lane回损失败、连接器附近TDR异常”；修复后必须变成“同样条件、两个方向稳定80G、Channel恢复通过”，并且最初失败的显示与存储并发组合也恢复。到这里，这个问题才从“换线似乎好了”变成“根因明确、措施对应、复测可关闭”。

---

## 一句话总结

**同一个Type-C口从80G掉到20G，先查能力与实际协商，再按Channel、Tx/Rx、隧道三层取证；找到先失去margin的项目，修复后回到原始组合复测。**

## 🔧 工程师速查（附录）

### 80G回落排查顺序

| 步骤 | 必做动作 | 输出证据 |
|---|---|---|
| 1. 固定条件 | 主机/坞/线/端点/端口/方向/供电/温度/负载 | 复现矩阵 |
| 2. 查能力 | 主机、设备、线缆声明能力 | 能力清单 |
| 3. 查协商 | 实际档位、方向、训练/Recovery/回落 | 系统与协议日志 |
| 4. 测Channel | 目标模式、参考面、夹具去嵌、通道项目 | 通道报告与margin |
| 5. 测Tx/Rx | test mode、码型、参考接收器、压力信号、BER | 合规报告与错误计数 |
| 6. 查隧道 | 显示、PCIe、USB业务是否建立 | 隧道状态与吞吐 |
| 7. 修复复测 | 回到原始失败组合完整重跑 | 前后对比证据 |

### 报告必须写清

- USB4或Thunderbolt版本、目标档位、方向和lane；
- DUT、固件、OS、线缆型号/长度/方向、坞和端点；
- 测试模式、码型、夹具、参考面、校准与去嵌版本；
- 参考接收器/CDR/压力信号设置；
- 单项结果与margin，不只写总PASS/FAIL；
- 修复前后是否在完全相同条件复测。

### 异常特征与解决办法

| 异常证据 | 定位方向 | 对应措施 |
|---|---|---|
| 所有lane高频插损都偏大 | 线长、材料或整体通道预算 | 缩短路径、换低损耗线材，重新验证全部lane |
| 单lane局部回损恶化，TDR靠近连接器有台阶 | 触点、焊接/压接或端接几何 | 处理连接器端接、差分对对称性和参考面连续性 |
| 异常跟着夹具或仪器端口走 | 测试系统 | 修复夹具/同轴、重做校准与去嵌，旧结果作废 |
| Channel通过，Tx单方向失败 | DUT Tx或板级发送路径 | 对比lane/方向，检查发送端电源、时钟和板级通道 |
| Channel与Tx通过，Rx压力下误码 | DUT Rx、CDR或均衡容限 | 复核压力眼，扫描容限边界后修接收路径 |
| 电气均通过，隧道仍失败 | 固件、路由或互操作 | 查协议日志、版本和能力交换，不再改模拟通道 |

### 常见误判

- ☐ 看到Type-C口就默认支持USB4/TB；
- ☐ 换线恢复就直接判“线坏”；
- ☐ 链路已经回落，却仍按目标档解释吞吐；
- ☐ 一张眼图通过，就认为隧道和互操作也通过；
- ☐ 用教学动画阈值代替正式CTS；
- ☐ 修复后换了测试组合，没有回到原始失败条件。
