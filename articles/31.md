# 眼图不是一张“眼睛”：先把 UI、时间参考、码型和判据锁定，再谈余量

<div class="article-meta"><span class="badge">📘 模块三 · 信号完整性 SI · 眼图</span><span class="badge">⏱ 约 17 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


实验室里最危险的眼图，不一定是闭得最狠的那张，而是**看起来很漂亮，却没有写清怎么得到的那张**。

同一条链路，只要换了时间参考、码型、参考面、带宽、滤波、去嵌或接收器模型，眼高、眼宽和 mask 结果都可能变化。截图上那只“眼睛”只是结果；真正能支撑结论的是它背后的测试条件和证据链。

本文不把眼图当作一张好坏示意图，而是按工程顺序处理十个问题：UI 到底是什么、波形怎样折叠、NRZ 与 PAM4 有什么不同、时间参考如何选、台面如何搭、码型如何定、哪些数字能用、外观能提供什么线索，以及失败后怎样回到可复测的根因。

## 1. 先定 UI：它是符号周期，不一定是 bit 周期

UI（Unit Interval）首先是**一个符号占用的时间**：

`UI = 1 / Symbol Rate`

NRZ，也可写作 PAM2，每个符号承载 1 bit，所以 5 GBd 对应 5 Gb/s，1 UI 为 200 ps。PAM4 每个符号有四个电平，可承载 2 bit；同样是 5 GBd，线路比特率是 10 Gb/s，但 1 UI 仍然是 200 ps。这里的线路比特率不等于扣除编码、FEC和协议开销后的有效载荷吞吐率。

这一区分会直接影响仪器设置。把 PAM4 的 10 Gb/s 直接代入 `1 / bit rate`，会把 UI 错算成 100 ps，后续折叠窗口、抖动归一化和 mask 横坐标都会跟着错。

![图1：UI、NRZ和PAM4的关系。5 GBd教学示例中，NRZ每符号1 bit、数据率5 Gb/s；PAM4每符号2 bit、数据率10 Gb/s；两者UI都为200 ps。](/images/31/ill01_symbol_ui.png)

Tektronix 的 PAM4 资料也采用相同定义：PAM4 用四个电平编码每符号 2 bit，在相同符号率下提供 NRZ 的两倍数据率，并在同一 UI 内形成三只眼。公开核对见 [What is PAM4? Signaling Basics, vs. NRZ, and Testing](https://www.tek.com/en/blog/time-get-ready-pam4)。

## 2. 眼图怎样形成：切片、对齐、折叠，再累积密度

眼图不是从一条“代表性波形”画出来的。正确过程是：

1. 先确定时间参考；
2. 按固定长度截取连续波形，常见显示窗口为 2 UI；
3. 把不同时间位置的窗口对齐到同一横坐标；
4. 累积足够多的轨迹，用颜色或亮度表示出现密度。

在理想的 2 UI NRZ 显示中，符号边界位于 0、1、2 UI，判决中心位于 0.5 和 1.5 UI。显示两只重复的眼口只是为了便于观察左右边界，不代表协议一定以 2 UI 为测量单位。

![图2：连续码流按时间参考切成多个2 UI窗口，再折叠到同一坐标。红点是判决中心，橙线是符号边界。](/images/31/ill02_folding.png)

轨迹数量太少时，眼图只是一组稀疏线条；累积增加后，常见路径变亮，低概率尾部逐渐出现。**显示密度、采集数量和命中统计必须一起保存**，否则两张看似相同的眼图可能代表完全不同的统计深度。

## 3. NRZ 一只眼，PAM4 三只眼

NRZ 只有高、低两个电平，因此只有一个判决阈值和一只眼。PAM4 有四个电平，需要三个判决阈值，对应上、中、下三只眼。

PAM4 不能只把 NRZ 的 mask 复制三次。工程上还要关注：

- 三只眼的高度、宽度和中心是否一致；
- 四个电平的线性度；
- 上升、下降及不同跨级跳变的差异；
- 三只眼中最差的一只；
- 参考接收器、FEC 和 BER 定义。

![图3：同一5 GBd教学模型下，NRZ形成一只眼，PAM4形成三只眼；PAM4需要分别观察三只眼及电平线性。](/images/31/ill03_nrz_pam4.png)

因此报告里不能只写“眼高 120 mV”。至少要写清调制方式、测的是哪只眼、采用什么归一化和接收器处理。

## 4. 读眼图：先分“测到了什么”和“推断了什么”

一张眼图里常见的观察量包括：

- **眼高**：指定时间位置和统计定义下的垂直开口；
- **眼宽**：指定电平或 BER 条件下的水平开口；
- **交叉区**：上升沿与下降沿的时间分布和幅度分布；
- **轨迹厚度**：噪声、抖动、ISI、带宽和采集处理共同作用后的结果；
- **判决中心**：参考接收器或测量算法使用的采样位置。

![图4：眼图解剖。符号边界、判决中心、眼高、眼宽、交叉区和轨迹密度分别对应不同测量问题。](/images/31/ill04_anatomy.png)

眼高不等于“真实噪声余量”的全部，眼宽也不等于“总抖动”的全部。它们都依赖测量定义：在哪个时间或电平读取、允许多少命中、是否经过参考滤波、是否使用外推、采样数量是多少。没有这些条件，单独比较两个截图上的眼高眼宽，意义有限。

下面的动画只演示综合链路损伤增加时，轨迹如何逐步侵入判决区域。参数扫描同时改变边沿展宽、ISI、数据相关抖动和噪声，没有加载任何接口 mask，也不输出合规结论。

![动图1：综合链路损伤连续增加，边沿展宽、ISI、数据相关抖动和噪声同步变化，眼口逐步失去采样空间；非CTS、非真实DUT。](/images/31/ill04b_channel_anim.gif)

## 5. 时间参考不是一律写 CDR

眼图的横向结果取决于“相对于什么时间参考”。

| 链路类型 | 常见时间参考 | 需要写进报告的内容 |
|---|---|---|
| 数据嵌入时钟的串行链路 | 规范规定的参考 PLL / CDR | 环路模型、带宽、阶数、是否含 SSC、参考接收器版本 |
| 转发时钟链路 | 时钟通道 / forwarded clock 经规范规定的 PLL、恢复和 deskew 处理 | 数据与时钟的探测位置、处理模型和参考面 |
| DDR / LPDDR 源同步链路 | 对应代际、方向和测项指定的 DQS、RDQS、WCK 或 CK | 读写方向、信号组关系、burst筛选、门控和去嵌 |

![图5：三类时间参考。嵌入时钟链路按规范使用参考PLL/CDR；转发时钟链路按规范处理时钟通道；DDR/LPDDR按代际、方向和测项选择DQS、RDQS、WCK或CK。](/images/31/ill05_time_reference.png)

所以“眼图都用 CDR”“DDR 不测眼图”都不准确。DDR5 的系统验证会对实际探测到的 DQ、DQS 等信号做 eye diagram 和电气时序分析；Tektronix 的 [DDR5 Measurement Challenges](https://www.tek.com/en/documents/whitepaper/ddr5-measurement-challenges)明确给出了系统探测、眼图和相关参数测量场景。LPDDR还要按具体代际和测项区分WCK、RDQS/DQS、CK等参考，不能一律写成DQS；可对照Tektronix的 [LPDDR5系统级发送端验证资料](https://www.tek.com/en/datasheet/lpddr5-memory-interface-electrical-verification-and-debug-opt-lpddr5sys--system-level-transmitter-te)。

HDMI TMDS 则有独立时钟通道。公开应用说明中，数据眼相对于恢复后的时钟进行处理，并按 CTS 指定记录长度累积至少 400,000 UI。这里引用它是为了说明**参考时钟和采集深度由具体标准定义**，不是把旧版 HDMI 的数值套到其他接口。来源见 [Physical Layer Compliance Testing for HDMI](https://www.tek.com/en/documents/application-note/physical-layer-compliance-testing-hdmi-using-tdsht3-hdmi-compliance-test-s)。

## 6. 台面决定结果：先锁参考面，再谈仪器读数

眼图测试的对象不是“示波器屏幕”，而是某个规定参考面上的信号。测试前至少固定：

- DUT 角色、方向、lane、速率、调制和工作模式；
- 测量参考面及夹具、线缆、探头或 interposer；
- 端接、探头负载和差分去偏斜；
- 示波器带宽、采样率、记录长度和采集模式；
- 去嵌文件、参考接收器滤波、CTLE/DFE等处理；
- 时间参考、测试码型、采集 UI 数量和环境条件。

![图6：眼图测试台面和参考面。DUT、夹具/探头、示波器或BERT之间必须明确参考面、校准、deskew、带宽、去嵌和接收器处理。](/images/31/ill06_bench.png)

一个可复现的记录可以这样写：

> DUT Tx lane 0，5 GBd NRZ；Ref A 位于连接器焊盘；差分有源探头；20 GHz带宽；48 GS/s；记录 2 M UI；使用规范指定参考PLL；夹具S参数去嵌到Ref A；温度25 °C；测试码型为规范指定pattern。

这段记录比“眼图通过，余量不错”更有价值。后者无法复测，也无法判断差异来自 DUT 还是测量链。

## 7. 码型不能一律用 PRBS

不同码型回答的问题不同：

| 码型 | 适合回答的问题 | 不能替代什么 |
|---|---|---|
| 规范指定一致性码型 | 正式合规测试 | 不能被“更方便”的自选码型替换 |
| PRBS7 / PRBS31等 | 通道表征、BER、压力与调试 | 不自动等于所有接口的正式CTS码型 |
| 1010或重复时钟码 | 幅度、频率、边沿和基线检查 | 覆盖不了长连0/1和复杂数据相关ISI |
| 业务流量 | 系统复现、互操作和偶发问题 | 不适合直接替代可控的合规激励 |

![图7：四类码型的用途边界。正式一致性优先规范指定码型；PRBS用于BER和通道表征；1010用于基线；业务流量用于系统复现。](/images/31/ill07_patterns.png)

采集数量也不能写成“越多越好”就结束。需要记录总 UI 数、命中数、分段方式、是否发生错误、是否启用持久显示和统计外推。罕见事件如果只出现一次，更要保存原始波形和时间戳，而不是只留最终热力图。

## 8. Q、BER、浴盆和 mask：四类证据不能混成一个结论

### 8.1 Q 到 BER 的换算有前提

对二电平、垂直噪声近似高斯、上下电平分布可用均值和标准差描述的模型，可写：

`Q = (μ1 - μ0) / (σ1 + σ0)`

`BER = 0.5 × erfc(Q / √2)`

按这个模型复算，`Q = 6` 时 `BER ≈ 9.87 × 10^-10`，`Q = 7` 时 `BER ≈ 1.28 × 10^-12`。

这些值不是任何接口的通用判据。严重 ISI、确定性抖动、非高斯尾部、低概率突发和 PAM4 多阈值问题，都不能只靠这条公式得出最终 BER。

### 8.2 浴盆曲线有横向条件

横向浴盆是采样相位与 BER 的关系。它可以来自真实 BER 扫描，也可以来自模型外推；两者必须在报告中区分。外推结果要写明拟合模型、目标 BER 和置信边界。

### 8.3 mask 是标准定义的禁区

mask 只有在**版本、角色、速率、码型、参考面、对齐和采集条件都正确**时，才能支撑该标准版本下这一项mask测项的结果，不能代替整套接口合规。Keysight 的公开说明中，进入 fail region 的采样点会被记录为 mask failure，并同时统计波形数和失败样本；因此无hit也应写成“在本次已采集的N个样本或波形中无hit”，不能外推为BER保证。来源见 [Eye Diagram Mask Test](https://helpfiles.keysight.com/csg/N1930xB/Analyzing/Eye_Diagram_Mask_Test.htm)。

![图8：Q-BER模型、横向浴盆和mask的证据边界。Q换算需要二电平高斯假设；浴盆要写明实测或外推；mask结论依赖正确标准版本和测试条件。](/images/31/ill08_evidence.png)

## 9. 病态眼图能分诊，但不能单凭外观定根因

常见外观确实能给出方向：

- 轨迹上下变厚：先查噪声、电源相关性、串扰和探测噪底；
- 交叉区横向散开：先查时钟、PLL/CDR、周期抖动和数据相关抖动；
- 拖尾、不同前导码形成多条路径：先查通道损耗、反射和均衡；
- 只在某一 lane、方向或速率出现：优先做受控对比，而不是先改所有参数。

![图9：四类病态眼图线索。垂直增厚、横向散开、数据相关拖尾和综合闭眼分别指向不同的下一步证据。](/images/31/ill09_fingerprints.png)

但“眼图变矮就是串扰”“眼宽变窄就是时钟坏了”仍然过度简化。探头负载、带宽限制、错误去嵌、参考PLL、码型和接收器均衡都可能制造相似外观。

下面的动画依次增加垂直噪声、时序抖动和ISI，用来练习观察方向。真实问题往往是多因素叠加，最终仍要靠频谱、TIE、S参数、近端探测或受控A/B确认。

![动图2：依次增加垂直噪声、时序抖动和ISI，观察轨迹厚度、交叉区和数据相关拖尾的变化；外观只提供线索，不代替根因证据。](/images/31/ill09b_impairments_anim.gif)

## 10. 一套可复测的眼图 Debug 闭环

![图10：眼图工程闭环。从定义对象、锁定条件、采集证据、结果分层、根因定位到回原条件复测。](/images/31/ill10_workflow.png)

实际工作按下面的顺序更稳：

1. **定义对象**：接口版本、角色、方向、lane、速率、调制、工作状态。
2. **锁定测试条件**：参考面、台面、时间参考、码型、带宽、去嵌、接收器模型、采集数量。
3. **保存原始证据**：原始波形、仪器setup、mask文件、去嵌文件、日志、环境和时间戳。
4. **分层下结论**：先写观察量，再写是否满足当前判据，最后才写根因假设。
5. **做受控A/B**：换lane、方向、速率、线缆、夹具、均衡档位、温度或供电，每次只改一个变量。
6. **补专用证据**：TIE/频谱查抖动，VNA/TDR查通道，电源同步采集查相关性，BERT查真实错误分布。
7. **回原条件复测**：修复后恢复原码型、参考面、带宽、去嵌、温压和观察位数，确认改善可重复。

一份合格报告至少包含：测试对象、仪器与校准状态、连接图、参考面、setup文件、码型、采集深度、原始眼图、量化结果、判据出处、异常证据、A/B记录、修复动作和复测结果。

眼图最有价值的地方，不是替你宣布“信号好不好”，而是把电压、时间和数据相关行为压到同一张统计图中，帮助你决定**下一步该拿什么证据**。

## 🔧 工程师速查

### 1. 基本关系

| 项目 | 正确写法 |
|---|---|
| UI | `1 / Symbol Rate`，是符号周期 |
| NRZ / PAM2 | 1 symbol = 1 bit，5 GBd = 5 Gb/s |
| PAM4 | 1 symbol = 2 bit，5 GBd = 10 Gb/s，形成三只眼 |
| 2 UI显示 | 边界0/1/2 UI，理想判决中心0.5/1.5 UI |

### 2. 时间参考

| 链路 | 优先参考 |
|---|---|
| 嵌入时钟串行链路 | 规范指定参考PLL/CDR |
| HDMI等转发时钟链路 | 时钟通道 / forwarded clock及规范规定的PLL、恢复和deskew处理 |
| DDR / LPDDR | 按代际、方向和测项使用DQS、RDQS、WCK或CK |

### 3. 码型选择

| 目的 | 码型 |
|---|---|
| 正式一致性 | CTS指定码型 |
| BER / 通道表征 / 调试 | PRBS或规范要求的压力码型 |
| 幅度、频率、边沿基线 | 1010或重复时钟码 |
| 系统复现 | 真实业务流量，同时保存协议和错误日志 |

### 4. 结论边界

- Q-BER换算仅用于二电平、高斯垂直噪声等假设成立的模型。
- 浴盆要注明真实扫描还是外推，并写目标BER和模型。
- mask必须绑定标准版本、角色、速率、码型、参考面、对齐和采集条件；结果只覆盖该项mask测项。
- 合成教学眼图不得写成真实 DUT 实测或 CTS 通过结论。

### 5. 报告必填字段

- DUT、角色、方向、lane、速率、调制、工作状态；
- 仪器、探头/夹具、校准、参考面、deskew；
- 带宽、采样率、记录长度、采集UI数；
- 时间参考、码型、去嵌、参考接收器和均衡；
- 原始波形、setup、mask、日志、环境和时间戳；
- 判据出处、异常证据、A/B动作、修复与回原条件复测。

### 6. 常见误区

- ☐ 把 PAM4 bit rate 直接当 symbol rate 算 UI；
- ☐ 所有链路都写“CDR触发”；
- ☐ 认为 DDR / LPDDR 不做眼图；
- ☐ 正式一致性测试一律改用 PRBS；
- ☐ 用 1010 的漂亮眼图代表最坏数据相关条件；
- ☐ 只截屏，不保存 setup、原始波形和采集数量；
- ☐ 用合成 mask 或 Q-BER教学换算宣布 PASS/FAIL；
- ☐ 凭眼图外观直接定根因，不做受控A/B和专用证据。
