先说个很多人都纳闷过的现象。

你和同事都买了标称 **256GB** 的手机，跑分软件一测，存储读写速度差了一大截：一个顺序读能到 **每秒三四 GB**，另一个只有 **每秒几百 MB**；装大型游戏、拷一段 4K 视频、系统更新解压，快的那台明显利索，慢的那台转圈转到你怀疑人生。查参数才发现：快的用的是 **UFS 4.0 / 3.1**，慢的用的是 **eMMC**。

再比如做嵌入式的同学会发现，同样一颗闪存，接 **eMMC** 时 PCB 上密密麻麻拉了 **十来根等长线**（数据 + 时钟 + 命令），一到高速就为对齐这些线头疼；换成 **UFS** 之后，就剩 **几对差分线**，PCB 反而清爽了，速度还翻了好几倍。

这两件事背后，是**存储接口从并行到串行的一次架构换代**：从 eMMC 那条"并行总线 + 转发时钟"，换成了 UFS 的"MIPI M-PHY 串行差分 + 嵌入式时钟 + 全双工 + 命令队列"。而测试工程师要保证"这颗 UFS 器件能跑到标称 Gear、跟主控稳定互通"，用的又是一套和显示家族既像又不像的测法——**这，就是这一篇要讲的。**

先把差距量化成一个数：**UFS 4.0 的链路上限是 4640 MB/s，eMMC 5.1 HS400 是 400 MB/s，正好 11.6 倍。**
这一篇会把这 11.6 倍拆开，一层层算给你看——**它不是"串行比并行先进"这种口号，是一串能拿计算器验的 ps 和 mV。**

## 一、先认清主角：UFS / eMMC 是什么、就在你兜里

**UFS（Universal Flash Storage，通用闪存）** 是 JEDEC 定义的高性能嵌入式存储接口，专门装在**空间和功耗都紧张**的设备里：手机、平板、车机、可穿戴、部分工业与消费电子。它对上给操作系统一套 **SCSI 命令**（所以系统眼里 UFS 更像一块小 SSD），对下用 **MIPI M-PHY** 高速串行差分把数据搬进搬出。

它取代的是 **eMMC（embedded MultiMediaCard）**——一种把 NAND 闪存 + 控制器封在一起、走**并行总线**的老接口。eMMC 现在还没死，低端手机、IoT、便宜的嵌入式设备里仍常见，但高端设备早已全面 UFS 化。

UFS 有三大结构特征，正好对应这一篇的三条测试主线：

1. **串行 M-PHY + 嵌入式时钟 → 靠 CDR**：没有独立时钟线，时钟埋在数据里，接收端用时钟恢复（CDR，↔第 32 篇）捞出来——**所以要看眼图**。
2. **全双工**：M-PHY 每个方向有独立的 TX / RX 差分 lane，读和写可以同时进行（eMMC 是半双工，同一时刻只能读或只能写）。
3. **命令队列（SCSI-based）**：主控可以一次抛出多条命令排队执行，不用等一条完成再发下一条——这是 UFS 比 eMMC 快出一个数量级的关键之一。

![图2：认清 UFS 主角。中间一条 UFS 链路连 Host（SoC/主控）↔ Device（UFS 闪存器件）。画清三件事：①M-PHY 物理层——每方向独立 TX/RX 差分 lane（最多 2 lane），高速串行、嵌入式时钟；②UniPro 协议栈跑在 M-PHY 之上做可靠传输；③对上是 SCSI 命令、支持命令队列。旁边标身边场景：手机/平板/车机/可穿戴/部分 SSD。底部点出三大结构特征：①串行 M-PHY 嵌入式时钟→靠 CDR（要看眼图）②全双工（读写同时，eMMC 半双工）③命令队列（多命令排队，eMMC 做不到）。一句话：UFS 的物理层是 MIPI M-PHY，天生站在"看眼图"那岸](/images/42/ill02_whatis.png)

## 二、原理与演进：从 eMMC 并行，到 UFS 的 M-PHY 串行 + 分层协议栈

### 2.1 分层：像网络协议一样一层层叠上去

UFS 不是"一根总线走天下"，而是一套**分层协议栈**，从上到下：

- **应用层（Application）**：UFS 命令集，基于 **SCSI**——系统把它当块存储设备访问。
- **UTP（UFS Transport Protocol，传输协议层）**：把上层命令打包成 UPIU 传输单元。
- **UniPro（Unified Protocol，MIPI 定义的统一协议）**：负责可靠传输、流控、纠错，内部又分 L1.5（PHY 适配）/ L2（数据链路）/ L3（网络）/ L4（传输）几层。
- **M-PHY（MIPI 物理层，L1）**：真正把比特流以高速差分信号发出去的一层。

**关键认知：UFS = SCSI 命令 + UniPro 协议 + M-PHY 物理层。** 其中 UniPro 和 M-PHY 都是 **MIPI 联盟**的东西——这也是为什么我们说"存储和 MIPI 是一门 PHY"。

### 2.2 关键分水岭：并行 eMMC vs 串行 M-PHY

这是本篇最重要的一张对比，也是"从看时序搬到看眼图"的分水岭：

- **eMMC = 并行总线 + 转发时钟**：最多 8 根数据线 + 1 根命令线 + 1 根时钟线并排走，所有线要**严格等长对齐**；接收端**不用 CDR**，直接按那根转发过来的时钟采样。测的是 **setup/hold 时序裕量**，不是眼图。速率一高，并行线间的 skew、串扰就成了瓶颈——这就是并行接口的天花板。
- **UFS = 串行差分 M-PHY + 嵌入式时钟**：几对差分 lane，**时钟埋在数据里**，接收端靠 **CDR** 恢复。测的是**眼图 + 抖动**，和 USB3 / PCIe / DP 完全同路。串行差分天生抗噪、好扩速，这就是 UFS 能一路冲到 HS-G5（每 lane 23.2 Gbps）的底气。

一句话记：**eMMC 在"看时序"那岸，UFS 靠 M-PHY 跨到了"看眼图 / CDR"这岸**——和显示家族的 DP、外设家族的 USB3 站在了同一边。

### 2.3 并行的天花板，是能拿计算器算出来的

"并行拉不上去"这句话，很多文章讲到"skew 和串扰顶不住"就停了。可**顶不住**是个感觉，不是结论。真要落到台面上，它是一道除法：

> **并行侧的裕量 = UI ÷ 2 −（一堆固定的 ps）**

分母那个 UI 随速率线性缩水，分子里那一堆却**一个都不随速率变**——它们是走线长度差、封装引线差、器件的输出偏差、主控的建立保持要求，全是绝对时间。以 eMMC 5.1 HS400 的量级列一份预算（教学模型）：

| 这一项吃掉多少 | ps | 为什么它不随速率变 |
|---|---|---|
| 8 根数据线的 PCB 等长误差 | 120 | 板子画完就定死了 |
| 封装内引线长度偏差 | 100 | 封装做完就定死了 |
| 器件 DS→DQ 输出偏差 tDQSQ | 380 | 器件手册上的死数 |
| 主控建立要求 tIS | 250 | 采样电路的物理需求 |
| 主控保持要求 tIH | 250 | 同上 |
| 时钟 / 选通抖动 | 80 | 和速率无关的绝对抖动 |
| **合计** | **1180** | **一个都不随速率变小** |

把这 1180 ps 摆进不同速率的半个 UI 里：

| 数据率 | 1 UI | 半个采样窗 | 还剩多少裕量 |
|---|---|---|---|
| 200 MT/s | 5000 ps | 2500 ps | +1320 ps |
| 300 MT/s | 3333 ps | 1667 ps | +487 ps |
| **400 MT/s（HS400）** | **2500 ps** | **1250 ps** | **+70 ps** |
| **423.7 MT/s** | 2359 ps | 1179 ps | **0 ← 墙** |
| 500 MT/s | 2000 ps | 1000 ps | −180 ps |

看最后两行：**并行的墙落在 424 MB/s 上**（8 bit 宽，MT/s 和 MB/s 数值相同）。而 eMMC 5.1 的 HS400 标称 400 MB/s，**只剩 70 ps 裕量，占半窗的 5.6%**。

这个数值本身就是答案：**HS400 不是"还能再快一点"，它本来就是贴着物理天花板做出来的**。JEDEC 当年把 eMMC 停在这里，不是不想往上，是那道除法已经除不动了。

串行这一岸为什么不吃这个亏？因为它**根本没有"多根线之间对齐"这件事**——只有一对差分线，时钟埋在数据里，接收端自己捞。它要对付的是另一件事：ISI（码间干扰）。而 ISI 是**按 UI 记的**，速率翻倍 ISI 也翻倍，但它可以靠均衡补回来——skew 补不回来，那是绝对时间。

![动图①：同一根旋钮，两种架构的两种死法。上方一根"目标吞吐"滑条从 290 MB/s 一路推到 4640 MB/s，左右两岸共用这一根旋钮。左岸 eMMC 8 bit 并行：一条彩色开销条（等长+封装 220 ps / tDQSQ 380 ps / tIS+tIH 500 ps / 抖动 80 ps，合计 1180 ps）一动不动，外面那个绿色"半个 UI 采样窗"随速率越缩越小，缩到 424 MB/s 时窗比开销条还窄——判定翻成 FAIL，裕量转负。右岸 UFS 差分串行：同一个吞吐折算成每 lane 速率，眼图从 0.99 UI 一路收到 0.70 UI，接收端 9 dB 均衡一直开着，眼高从 391 mV 掉到 343 mV，**全程 PASS，压根没到过判定线**。底部一句：并行的墙在 424，串行一路到 4640](/images/42/anim01_wall.gif)

### 2.4 全双工 + 命令队列 → 为什么快出一个数量级

光有高速串行还不够，UFS 快还靠两件事：**全双工**（读写同时进行，M-PHY 独立 TX/RX lane）+ **命令队列**（多条命令排队、乱序完成，像 PC 上 SSD 的 NCQ）。eMMC 半双工、命令基本串行，所以哪怕拉到 HS400（400 MB/s），也追不上 UFS 的 GB/s 级。

![图3：UFS 的两大骨架。上半——分层协议栈：应用层(SCSI/UFS 命令) → UTP(打成 UPIU) → UniPro(L1.5/L2/L3/L4，MIPI 定义) → M-PHY(L1，MIPI 物理层)，右侧标注"UniPro+M-PHY 都是 MIPI 家的"。下半——并行 vs 串行的分水岭，两岸各配一张真算出来的图：左岸 eMMC = 8 根并行数据+命令+1 根转发时钟，下方画真算的采样窗（半窗 1250 ps，固定开销 1180 ps 占满，只剩 70 ps 缝），标"看 setup/hold 时序"；右岸 UFS = 一对差分 lane、嵌入式时钟、靠 CDR，下方画本篇真跑的 G5 眼图（过 9 dB 参考均衡后 329 mV / 0.67 UI），标"看眼图"。两岸中间一道竖线写"同一件事的两种量法"。右侧另标全双工(独立 TX/RX)+命令队列。底部一句：从 eMMC 到 UFS，就是并行换串行、看时序搬到看眼图](/images/42/ill03_arch.png)

## 三、版本与速率：从 HS-G1 到 HS-G5 的 Gear 阶梯

UFS 的速率用 **M-PHY 的 HS-Gear（高速档）** 表示，每一档又分 **Rate A / Rate B** 两个略不同的频点，全部用 **8b/10b 编码**（20% 开销）。主流版本对应关系（均为 2 lane）：

| 版本 | 最高 Gear | 每 lane 线速率 | 2 lane 原始带宽 | 有效吞吐（8b/10b 打八折） |
|---|---|---|---|---|
| UFS 2.0 / 2.1 | HS-G3 | 5.0 / 5.8 Gbps | 11.6 Gbps | **1160 MB/s** |
| UFS 3.0 / 3.1 | HS-G4 | 11.6 Gbps | 23.2 Gbps | **2320 MB/s** |
| UFS 4.0 | HS-G5 | 23.2 Gbps | 46.4 Gbps | **4640 MB/s** |

> ⚠️ 表里的 4640 MB/s 是**链路层可用带宽的上限**，不是跑分软件的实测值（真机顺序读通常在 4000 MB/s 出头）。
> 上限和实测之间那一截，是控制器、NAND、文件系统的事，不归物理层管。**引用这个数时请带上"链路上限"四个字。**

要点：

- **HS-Gear 逐档翻倍**：G1 1.25/1.45G → G2 2.5/2.9G → G3 5.0/5.8G → G4 11.6G → G5 23.2G（Gbps/lane，Rate A/B）。
- **8b/10b 开销**：每 8 bit 用 10 bit 传，20% 开销——所以"原始线速率 ÷ 8"的 MB/s 数字要再打个八折才是有效带宽（UFS 4.0：46.4G × 0.8 ÷ 8 = 4640 MB/s）。
- **还有 LS（PWM）低速档**：链路启动、控制、低功耗时用，速率只有几~上百 Mbps，不用 8b/10b——这套"高低速双模"和下一篇 MIPI D-PHY 的 HS/LP 双模是同一个思路。

### 3.1 阶梯往上爬一格，板子付出的代价

这张阶梯表看着人畜无害：一档一档往上翻倍就是了。但**板子不知道你在翻倍**——它只知道自己是 8 cm 的 FR4 走线加 3 个过孔，在 G5 的奈奎斯特频点上大约 11 dB 插损，这个数**从头到尾没变过**。

变的是 UI。速率翻倍，UI 减半，而通道那点时间常数是绝对的 ps——于是同一条尾巴，占的 UI 比例翻了一倍。**ISI 是按 UI 记的**，这就是为什么"板子一点没动，只是速率上去了，眼就塌了"。

![动图②：同一块板，把速率从 5.8 Gbps 一路推到 23.2 Gbps。屏幕中间是真实仿真的余辉眼图，下方一根滑条标着当前每 lane 速率与对应的 Gear 档位。5.8 G（HS-G3）时眼高 440 mV、眼宽 0.93 UI，眼睁得又大又方；11.6 G（HS-G4）掉到 283 mV / 0.79 UI，仍然过；继续往上，眼高一路缩水，在 16.7~17.1 G 之间擦穿 150 mV 的裸眼判据线，判定从绿色 PASS 翻成红色 FAIL；推到 23.2 G（HS-G5）只剩 34 mV / 0.23 UI，眼基本闭死。屏幕右上角常驻教学判据"裸眼 眼高 ≥150 mV，眼宽 ≥0.55 UI"，两条判据条实时跟着走。关键提示：先擦穿的是眼高，不是眼宽——通道短、损耗以幅度衰减为主，先没的是电压余量](/images/42/anim02_gear.gif)

看这张动图有两个细节值得停一下：

**第一，翻转点落在 16.7~17.1 G 之间**，也就是**在 G4 和 G5 之间**。这意味着这块板跑 G4 是有余量的，跑 G5 裸眼就是不行——不是板子坏，是**判据不该这么扣**（后面讲怎么测的时候会说清楚，G4/G5 的判据本来就扣在均衡之后）。

**第二，先擦穿的是眼高，不是眼宽。** 这一点和上一篇 HDMI 正好相反。HDMI 走的是几米长的线缆，时间弥散占主导，眼宽先关；UFS 焊在板上，通道只有几厘米，损耗以**幅度衰减**为主，所以**先没的是电压余量**。同样是"眼塌了"，塌法不同，排查方向也不同——**眼高先没，去查损耗和摆幅；眼宽先没，去查抖动和时间弥散。**

![图4：UFS 版本与速率阶梯。横向从左到右：UFS2.0/2.1 HS-G3 5.8G/lane（2 lane 46.4 Gbps 之一半，有效 1160 MB/s）→ UFS3.0/3.1 HS-G4 11.6G/lane（原始 23.2 Gbps，有效 2320 MB/s）→ UFS4.0 HS-G5 23.2G/lane（原始 46.4 Gbps，有效 4640 MB/s）。每档标 Rate A/B 两频点、8b/10b（20% 开销）虚线框，并标出该档的奈奎斯特频点（G3 2.9 GHz / G4 5.8 GHz / G5 11.6 GHz）——它决定示波器要多少带宽。右端大字标 UFS4.0 链路上限 4640 MB/s。底部一行小字：另有 LS/PWM 低速档（链路启动/低功耗，几~上百 Mbps，不用 8b/10b）——高低速双模和 MIPI 一个思路](/images/42/ill04_versions.png)

## 四、番外主角：eMMC——正在退场的并行老兵

这一篇的第二主角是 **eMMC**，它是理解 UFS"为什么这么设计"的最好对照物。

- **物理层**：并行总线，最多 **8 bit 数据 + 命令线 + 时钟线**，源同步（转发时钟），接收端不用 CDR。
- **速率天花板**：eMMC 5.1 的 **HS400** 模式约 **400 MB/s**——这已经是并行接口拉到极限的样子。第二节那份预算算得很清楚：**再往上 24 MB/s，裕量就归零了**。
- **半双工 + 浅队列**：同一时刻只能读或只能写；eMMC 5.1 才加了简单的命令队列（CQ），但深度和 UFS 的 SCSI 队列没法比。
- **测法完全不同**：eMMC 走的是**并行时序测试**——测各数据线相对时钟的 **setup/hold 裕量、skew**，用示波器多通道量时序，**没有"眼图 + CDR + 参考均衡"这套**。这正好反衬出 UFS 换成 M-PHY 串行后，测法整个搬到了眼图这一岸。

一句话：**eMMC 是"并行 + 看时序"的老世界，UFS 是"串行 M-PHY + 看眼图"的新世界**；低端和 IoT 里 eMMC 还在服役，但趋势是被 UFS 全面取代。

**留一句给做 eMMC 调试的同行**：HS400 只剩 70 ps 裕量这件事，直接决定了你板上能犯的错有多小。**一段没走等长的 DQ、一个多打的过孔、一颗换了批次的器件**，几十 ps 就没了——而你总共只有 70 ps。这就是为什么 eMMC 板子对等长这么苛刻，而 UFS 反而"随便"些：串行那一岸的余量是靠均衡挣回来的，不是靠画板挣回来的。

![图5：eMMC——并行老兵（对照 UFS）。左：画 eMMC 并行总线 = 8 根数据 + 命令线 + 1 根转发时钟并排，标"要等长对齐、接收端不用 CDR"。中：一张真算出来的并行采样窗——横轴是以 ps 为刻度的时间轴，中间一条绿色"半个 UI = 1250 ps"的采样窗（对应 HS400 400 MT/s），窗内叠着彩色开销条：等长误差 120 + 封装偏差 100 + tDQSQ 380 + tIS 250 + tIH 250 + 抖动 80，合计 1180 ps，右端只剩一道 70 ps 的窄缝，标注"裕量 +70 ps，占半窗 5.6%"；下方一条红色虚线标"423.7 MT/s 处裕量归零 = 并行的墙"。右：测法对比框——eMMC 测 setup/hold 时序裕量 + skew（多通道示波器量时序，无眼图）vs UFS 测眼图 + 抖动 + CDR。底部一句：eMMC=并行看时序老世界，UFS=串行 M-PHY 看眼图新世界，低端/IoT 仍在用但正被取代](/images/42/ill05_emmc.png)

## 五、测什么·三类：Tx 眼图、Rx 压力测试、封装 / 通道

UFS（HS-Gear）的一致性测试，和 USB3 / DP 一样分三大阵营——**全程都在"CDR + 眼图"的世界里**：

1. **Tx / 发送端眼图**：示波器在规定测试点抓 M-PHY 差分 lane 的眼图，扣 **M-PHY CTS 的眼图模板** + 抖动分离（RJ / DJ / TJ，↔第 31 篇），并验各档 **去加重 / 摆幅**。Gear 越高（G4/G5）模板越严。
2. **Rx / 接收端压力测试**：用 BERT / 码型发生器造**校准过的压力眼**（把损耗 + 抖动加到规范最坏值），测器件的**抖动容限 / 接收灵敏度 / CDR 跟踪能力**（↔第 38 篇）。这一步验的是"最坏信号来了它还认不认得"。
3. **封装 / PCB 通道**：UFS 器件焊在板上，没有可插拔线缆，但**封装球脚→PCB 走线→器件**这段通道的插损 / 回损 / skew / 串扰同样要测（VNA / 示波器），高 Gear 下这段通道就是裕量杀手。

![图6：UFS 一致性测试三阵营（全程 M-PHY CTS + 眼图世界）。左 Tx/发送端：示波器在测试点抓 M-PHY 差分 lane 眼图→扣模板 + 抖动分离(RJ/DJ/TJ) + 去加重/摆幅各档；下方配一小块本篇真跑的 G5 眼图（过 9 dB CTLE 后 329 mV / 0.67 UI，绿色 PASS）。中 Rx/接收端：BERT/码型发生器造校准压力眼(loss+jitter 加满)→测抖动容限/接收灵敏度/CDR 跟踪（见第38篇）；下方配一小块抖动容限曲线示意，标出"最紧点在拐点"。右 封装/通道：VNA/示波器测封装球脚→PCB 走线→器件的插损/回损/skew/串扰(高 Gear 重灾区)；下方配一条真算的插损曲线，标出标称板 11.1 dB、预算最坏板 14.8 dB 两个点。底部标一句：UFS 没有可插拔线缆，通道就是封装+PCB 那段](/images/42/ill06_test3.png)

## 六、怎么测：进测试模式 + link startup 训到目标 Gear + 参考均衡

UFS 的测试流程，几乎照搬 USB3 / DP 那套（"学会一个通一片"）：

- **进测试模式**：通过 UniPro / M-PHY 的管理接口（**RMMI / RMC，M-PHY 管理与配置接口**）把器件切进测试态，让它固定输出 **PRBS 测试码型**、锁定目标 Gear（G4 / G5）。
- **link startup（链路启动）**：主控和器件先从 **LS（PWM）低速档**握手（UniPro 的 **PACP** 流程），再逐档往 HS 上试、协商 lane 数 / 速率 / 均衡参数，训到稳定档；训不上就回落到低 Gear（表现为掉速）。
- **测量**：示波器在测试点抓眼图套 M-PHY CTS 模板；BERT 灌压力眼测容限。**G4 / G5 必须挂参考均衡（CTLE / DFE，↔第 34 篇）**，把高频损耗补平、把闭着的眼睁开再判读——和 USB3 / PCIe / DP 同一个道理。

![图7：UFS 测试流程条（真台面见下面两张图）。三段横向流程：①进测试模式——上位机经 RMMI/RMC 管理接口→被测器件固定输出 PRBS 测试码型、锁定目标 Gear(G4/G5)。②link startup——Host↔Device 先 LS/PWM 低速握手(UniPro PACP)→逐档往 HS 上试→协商 lane 数/速率/均衡→训到稳定档，训不上则回落(掉速)。③测量——测试点接示波器抓眼图套 M-PHY CTS 模板；接 BERT 灌压力眼测容限。底部强调框：G4/G5 必挂参考均衡 CTLE/DFE（见第34篇）才能把眼睁开判读——和 USB3/PCIe/DP 同路](/images/42/ill07_bench.png)

## 七、⚙️ 关键仪器设置：把模块三的 SI 概念落到旋钮上

UFS 的仪器设置和 USB 3.x / DP UHBR 那套几乎一模一样：

- **去嵌（de-embed）↔第 33 篇**：把探测夹具 / 通道的损耗从测量结果里数学扣掉，还原器件球脚处的真实信号。
- **参考均衡 CTLE / DFE↔第 34 篇**：G4 / G5 必用，把高频损耗补平——**判据是"参考均衡之后"的眼图**，不是裸眼图。
- **时钟恢复 golden PLL↔第 32 篇**：M-PHY 是嵌入式时钟，示波器要用规范规定的黄金 PLL 环路参数恢复时钟，才能正确测抖动。
- **带宽按规范档设↔第 29 / 速查 02**：按波特率约 0.7～1 倍选示波器带宽（G5 约 23G，用 30～40G 级示波器足矣，别过冲）。
- **抖动分离 + eye mask↔第 31 / 32 篇**：把 TJ 拆成 RJ / DJ，再套 M-PHY 眼图模板判裕量。

> 一句话：**UFS 的仪器设置 = USB 3.x / DP 那套嵌入式时钟测法。** 你在第 41 / 44 篇学的东西，这里几乎能直接复用；eMMC 那套并行时序测法（量 setup/hold）在 UFS 上完全用不到。

### 7.1 那个 9 dB 是怎么定出来的

上面第二条"G4 / G5 必用参考均衡"，写在规范里是一个具体档位。问题是：**凭什么是这个数？**

答案不在电气原理里，在**预算**里。规范定档位时，不是照着你手上那块好板定的，而是照着**预算内最坏的那块板**定的——走线更长、板材更差、过孔更多，插损从标称的 11 dB 顶到 15 dB 左右。把那块最坏板架上 G5，然后把参考均衡从零开始往上加，看它要多少才睁得开眼：

![动图③：把一块预算最坏的板（插损 14.8 dB）架在 HS-G5 23.2 Gbps 上，参考 CTLE 从 0 dB 一路加到 12 dB。屏幕主体是真实仿真的余辉眼图，右上角常驻教学判据"均衡后 眼高 ≥70 mV，眼宽 ≥0.35 UI"。0 到 4 dB 这一段眼是全闭的，眼高眼宽都是零，判定红色 FAIL；5 dB 起眼缝开始撕开一条线；七到八 dB 之间判定翻成绿色 PASS，全程只翻这一次；继续加到规范档位 9 dB，眼高眼宽都还在判据线上方，但并没有富裕多少；一直加到 12 dB，眼高 258 mV、眼宽 0.67 UI，眼睁得很开。屏幕左下角一个小坐标系同步画着当前 CTLE 的频响曲线：低频压平、高频抬起，抬起量随滑条走。关键提示：判据扣在均衡之后，不是裸眼；规范档 9 dB 只比睁开的下限高一点七 dB](/images/42/anim03_eq.gif)

翻转点落在**七到八 dB 之间**。而规范给的档位是 **9 dB**——**只比"刚好睁开"高一点七 dB**。

这个"一点七"就是全部的秘密：

- **它不是随便给的**。给少了，预算内最坏的板过不了，规范就把合规产品判死了。
- **它也不能给多。** 均衡不是免费的，加得越多噪声和串扰一起被放大，接收端还得真做得出来。规范的态度一向是"**刚刚够**"。
- **所以你手上那块标称板跑 G5，过完 9 dB 均衡是 329 mV（见上面 S1 台面图），比最坏板的 75 mV 富裕得多**——那是你板画得好挣来的，不是规范送的。

📌 **注意动图②和动图③用的是两块不同的板，这是刻意的**：②用**你手上那块标称板**说明"G5 裸眼就是不行"；③用**预算内最坏那块板**说明"9 dB 这个档位是怎么定出来的"。两块板的插损不同，眼图数字不能横向对比。

### 7.2 接收端这一台，长什么样

Tx 那台是"看它发得好不好"，Rx 这台反过来：**造一个最坏的信号灌给它，看它还认不认得**。

![台面图 S2：UFS 接收端压力测试台。信号从左往右：码型发生器（输出 PRBS，锁 HS-G5 23.2 Gbps）→ 加损耗与注入抖动的压力眼生成单元（按规范最坏值加板级插损、加正弦抖动 SJ、加随机抖动 RJ）→ 一路同轴下行到被测板上的测试点 → 灌进 UFS 器件的接收端。误码结果不走另一根线，而是经 UniPro 链路回读，画成一条青色虚线绕回上位机，旁边一张卡明确写"回读走协议链路，不是另一根物理线"。右侧仪器屏内画的是抖动容限曲线：双对数坐标，横轴抖动频率 100 kHz 到 100 MHz，纵轴注入抖动量 UI p-p；一条阶梯状的容限模板（低频 2.0 UI 平台 → 3 MHz 起以 20 dB/十倍频下降 → 40 MHz 后落到 0.15 UI 地板），模板下方涂成红色危险区；实测曲线整体在模板上方，但在 11 MHz 附近向下凹了一块，最近处离模板只有 1.7 dB，用一个箭头标注"最紧的地方在拐点，不在最高频"。中部教学分叉分两遍讲：先·校准——把压力眼在被测板测试点处用示波器量出来、调到规范值，此时器件还没接；后·测量——校准好的压力信号原样灌给器件，读误码率。底部四张坑位卡：①压力眼必须先校准再灌，没校准的"最坏信号"既不最坏也不可复现 ②校准参考面就是灌信号的那个点，两次不能不一样 ③容限测的是 CDR 跟不跟得住，最容易挂的是环路带宽拐点那一段 ④误码率要跑够时间，看几秒钟不掉就宣布通过是自欺欺人](/images/42/fig_setup_rx.png)

关于这张图，最值得记住的是屏幕上那条曲线的形状：**最紧的地方在拐点，不在最高频。**

很多人下意识觉得"抖动越快越难跟"，于是把精力全花在高频段。但 CDR 是个环路——**低频抖动它跟得住**（环路来得及调），**高频抖动它跟不住但也不用跟**（幅度已经被规范压到 0.15 UI 的地板了）。真正难受的是**中间那一段**：环路刚好跟不动，而注入量还没降下来。本篇模型里这个最紧点落在 **11 MHz，只剩 1.7 dB 余量**。

**这条经验可以直接搬去用**：抖动容限扫出来是一条 U 形（或者说"凹"形）曲线，**先看拐点附近有没有贴模板**，那里才是命门。

## 八、判据从哪来：JEDEC + MIPI 两本 CTS，不是拍脑袋

和第 35 篇讲的一样，UFS 的判据来自标准的 **CTS（Compliance Test Specification，一致性测试规范）**，而且是**两家、两本**：

- **M-PHY CTS（MIPI）**：管电气层——眼图模板、抖动限值（RJ / DJ / TJ）、去加重 / 摆幅、接收均衡要求。眼图模板 / 抖动预算从信道损耗预算反推而来（↔第 35 篇）。
- **UFS 一致性测试（JEDEC）**：管协议 + 电气整体符合性。JEDEC 维护 UFS 标准（如 JESD220 器件、JESD223 主控 UFSHCI）及对应的一致性测试规范，验 link startup、UniPro 行为、命令队列、UPIU 等协议项。

所以 UFS 的判据体系是**分家的**：**电气 / PHY 归 MIPI M-PHY CTS，协议 / 命令归 JEDEC UFS 一致性**——两大本分别由不同测试系统跑。这一点和 DP 的"PHY CTS + Link Layer CTS 两本"结构上完全类似。

### 8.1 ⚠️ 关于本篇图上那些数字：它们是「教学判据」

M-PHY CTS 的眼图模板、抖动限值这些**具体数值，需要 MIPI 会员资格才能取得，不是公开信息**。所以本篇所有图、所有动图上标出来的判据，都是**为讲清物理趋势而设的教学判据**：

| 本篇用的教学判据 | 值 |
|---|---|
| 裸眼（低 Gear 直接扣） | 眼高 ≥ 150 mV，眼宽 ≥ 0.55 UI |
| 均衡后（G4 / G5 扣在 CTLE 之后） | 眼高 ≥ 70 mV，眼宽 ≥ 0.35 UI |
| 参考 CTLE 规范档位 | 9.0 dB |

其中**只有摆幅是公开值**：M-PHY HS-TX 大摆幅约 500 mV pp 差分（单边 250 mV），这个可以放心引用。

> 🔴 **请这样使用本篇的数字：**
> **物理趋势是成立的**——速率一翻倍眼就塌、翻转点在哪一档、均衡要加到多少才睁开、并行的墙在 424 MB/s、抖动容限最紧在拐点——这些结论都经得起推敲，也是你上手时该有的直觉。
> **但绝对数值不要引用到任何正式报告或设计文档里。** 要写报告，请去查你手上那一版 M-PHY CTS 和 UFS 一致性测试规范的原文。
> 同理，第二节那份 1180 ps 的 eMMC 预算也是教学模型——**结构是对的**（固定 ps ÷ 缩水的 UI），**具体分项数值请以你器件手册上的 tDQSQ、tIS、tIH 为准**。

## 九、常见翻车与调试：掉速 / 训不上高 Gear / 兼容不上 / 偶发读写错，怎么分层揪

UFS 翻车，**先分层、别一上来就赖信号**（顺序和 USB / DP 一样）：

1. **先看协商 / 训练层（link startup / Gear）**：器件被识别没？link startup 训到第几 Gear？——**"读写掉速""跑分只有一半"多半是没训到目标 Gear、回落了**，先查这里，跟眼图无关。

### 9.1 「跑分只剩一半」这句话，可以算出来

开篇那个"两台 256G 手机跑分差一截"的现象，到这里可以收口了。

**link startup 不是一次性成功或失败的事**，它是**从高往低试**：先按目标 Gear 拉，训不上就退一档再试，直到握上手为止。所以一块通道差了点的板，用户看到的**不是掉盘、不是黑屏，而是"能用，就是慢"**——这是最难被投诉、也最难被发现的一类问题。

把板级插损从好板一路劣化到差板，看它自己定在哪一档：

**4640 → 2320，比值正好 0.50。**

这不是巧合：**HS-Gear 阶梯本身就是逐档翻倍定义的**（G3 5.8 → G4 11.6 → G5 23.2），所以**掉一档 = 砍一半**，一分不多一分不少。你在跑分软件上看到的那个"差一截"，量出来就是这么个整数。

所以下次遇到"跑分只有标称一半"，**先别抓示波器**——去读一下 link 的当前 Gear。如果它老老实实停在 G4，那问题在通道 / 训练，不在 NAND，也不在系统。**这一步只要一条命令，比架台面快一百倍。**

2. **再看电气层（眼图 / skew / 均衡 / 通道）**：训到高 Gear 但偶发误码、花屏（车机屏）、掉盘——量 M-PHY 差分眼图、封装 / PCB 通道 skew、参考均衡后眼还睁不睁、球脚阻抗是否连续。
3. **协议 / 命令层（UniPro / 命令队列）**：链路稳但吞吐上不去、并发一多就出错——查 UniPro 流控、命令队列深度、UPIU 处理。
4. **供电 / 完整性层（PI，↔模块三）**：高负载读写时纹波 / 掉压导致偶发错误——存储大电流突发时 PI 尤其关键。
5. **eMMC 兼容 / 老器件**：若是 eMMC，问题多在并行 setup/hold 时序、等长走线、HS400 的数据选通（DS）——那是另一套并行世界的排查法。

**现象速查**：跑分只有标称一半 = 没训到目标 Gear / 回落；训到高 Gear 仍偶发误码 = 眼图 / 通道 skew / 均衡；吞吐上不去但链路稳 = UniPro 流控 / 命令队列；高负载才偶发掉盘 = 供电 PI；eMMC 高速不稳 = 并行 setup/hold / 等长 / DS 选通。

## 一句话总结

**一句话：从 eMMC 到 UFS，是存储接口从「并行 + 转发时钟 + 看 setup/hold 时序」换代到「MIPI M-PHY 串行差分 + 嵌入式时钟 + CDR + 看眼图」——一致性测试也随之整个搬到 USB3 / PCIe / DP 那一岸。学会了 USB3 / DP，UFS 你已经会了一大半，MIPI 也通了半只脚。**

- **换代**：并行 + 转发时钟 + setup/hold 时序（eMMC）→ M-PHY 串行差分 + 嵌入式时钟 + CDR + 看眼图（UFS）。
- **算得出来**：eMMC 的墙在 424 MB/s（1180 ps 固定开销 ÷ 越来越窄的 UI），UFS 4.0 链路上限 4640 MB/s，正好 11.6 倍。
- **怎么测**：抓 M-PHY 眼图、做抖动分离、G4/G5 挂参考均衡——**判据扣在均衡之后**。那个 9 dB 档位只比"刚好睁开"高一点七 dB，是按预算内最坏的板定的。
- **判据两本**：MIPI M-PHY CTS（电气）+ JEDEC UFS（协议）。本篇图上的数值是**教学判据**，趋势可信、数值别引用到报告。
- **一条能马上用的**：跑分只剩一半，先读 Gear——HS-Gear 逐档翻倍，**掉一档就是砍一半**。
- **承上启下**：UFS 的物理层 M-PHY，正是下一篇 MIPI 的同门兄弟。
