# 抖动到底是什么：怎么测、多少算超标，Fail后怎么定位

<div class="article-meta"><span class="badge">📘 模块三 · 信号完整性 SI · 抖动 Jitter</span><span class="badge">⏱ 约 24 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


一条高速链路偶发误码，仪器报告里却写着：

`RJ RMS = 2 ps`

2 ps看起来很小，于是有人直接得出结论：抖动不是问题。

这个判断缺了至少五个条件：测的是什么边沿、相对哪个时间参考、使用什么码型和带宽、2 ps属于哪种统计量、对应接口的判据又是什么。

本文用一条**5 GBd NRZ教学链路**贯穿全文。它的UI为200 ps；所有波形和数值均为合成模型，不代表真实DUT、接口规范值或CTS结论。我们的目标不是背一组RJ/DJ术语，而是完成一条工程闭环：

`理解抖动 → 判断何时关注 → 找到适用判据 → 正确测量 → 定位Fail → 对应整改 → 原条件复测`

---

## 一、抖动是什么，为什么会让链路误码

理想情况下，一个有意义的边沿应该在规定时刻到达。实际边沿可能提前，也可能延后。**这种相对声明时间参考的时刻偏差，就是抖动观察的核心。**

对于数字数据，常用TIE（Time Interval Error）描述被选中的实际转换边沿相对参考边沿偏了多少：

`TIE = 实际边沿时刻 − 参考边沿时刻`

更完整地说，对第`n_i`个发生转换的符号边界：

`TIE_i = t_cross,i − (t0 + n_i × UI)`

这里的`n_i`不是简单寻找“离实际边沿最近的参考边沿”，而是由已知码型、解码结果和声明的时钟恢复模型确定对应的符号序号。否则码型映射错误、CDR cycle slip或参考相位变化都可能被误算成TIE。TIE正负号也应以所用标准或仪器定义为准。

这里有三个对象不能混：

1. **UI**：一个符号占用的时间；
2. **数据转换边沿**：只有符号电平发生变化时才出现；
3. **时间参考**：外部参考、拟合理想时钟、Golden PLL或接收机CDR等。

UI按符号率计算：

`UI = 1 / Symbol Rate`

本文示例是5 GBd NRZ，因此UI为200 ps，线路比特率为5 Gb/s。如果换成5 GBd PAM4，UI仍然是200 ps，但线路比特率变成10 Gb/s。只看到“Gb/s”就直接计算UI，很容易从第一步开始就错。

数据边沿也不是每个UI都存在。NRZ数据只有在`0→1`或`1→0`时才有转换；长连零和长连一期间没有数据转换边沿。

![图1：UI、数据符号和TIE。5 GBd NRZ的UI为200 ps；只有发生电平转换的符号边界才有数据边沿。](/images/32/ill01_ui_tie.png)

抖动为什么会造成误码？因为接收器需要在有限的采样窗口里判断0或1。边沿向采样点移动，会压缩水平余量；垂直噪声又会通过有限上升时间转换成额外的交越时间变化。最终问题不是“边沿看起来有点抖”，而是：

> 在声明的接收模型、码型和工作角落下，接收器还剩多少可靠采样余量？

## 二、抖动从哪里来

RJ、DJ、PJ、DCD这些名称是统计或算法分类。工程排查时，先沿实际物理路径寻找候选源更有效。

### 1. 时钟源和PLL

晶振、参考时钟、PLL环路和电源噪声都会改变相位。宽带相位噪声可能形成随机分量，参考杂散或调制可能形成离散spur，SSC则是规范允许的受控频率调制。

### 2. 发送器和接收器

驱动器延迟、偏置、阈值、占空比和差分路径不对称会改变上升沿与下降沿到达时间。接收端阈值、均衡和CDR跟踪特性也会改变最终可见结果。

### 3. 通道损耗和ISI

通道对高频衰减更强，前后比特的拖尾会推动当前边沿。这个位移与码型历史有关，是DDJ的重要来源之一。

### 4. 串扰和周期活动

邻线、开关电源、时钟或其它周期活动会调制边沿。它可能表现为PJ、DDJ或某些算法中的BUJ，不能只凭分类名称倒推唯一物理源。

### 5. 测试台面

示波器时基、探头加载、夹具、deskew、参考源和分析算法都会进入读数。换了测试台面后异常跟着移动，首先应该怀疑测量链，而不是继续修改DUT。

![图2：抖动物理来源链。参考时钟、发送器、通道、接收器和测试台面都会影响最终读数；统计分类不能替代根因证据。](/images/32/ill02_sources.png)

## 三、什么时候需要关注抖动

不是所有数字接口都需要启动RJ/DJ分离，也不是所有时钟都应该套用同一套抖动指标。

| 场景 | 为什么需要关注 | 常见观察量 |
|---|---|---|
| 嵌入时钟高速串行链路 | 数据中恢复时钟，抖动直接影响CDR和采样余量 | 规范PLL/CDR下的TIE、TJ、BER、Rx JTOL |
| 分布参考时钟系统 | refclk经过Tx/Rx PLL传递到链路 | 相位噪声、滤波后的RMS jitter、TIE |
| 转发时钟接口 | 数据和时钟相关性、路径匹配及deskew决定采样 | clock-data skew、TIE及规定参考处理 |
| DDR/LPDDR源同步接口 | 按代际和读写方向选择数据选通；传统DDR通常使用DQS，LPDDR5/5X需区分RDQS/WCK及训练状态；CK主要约束CA时序 | DQ-选通关系、CA-CK、setup/hold、skew、period等 |
| 普通时钟网络 | 周期变化可能破坏芯片内部或板级时序预算 | period、cycle-to-cycle、TIE、wander |
| I2C/SPI/UART等低速接口 | 通常先看setup/hold、脉宽、频率或波特率误差 | 按器件手册和总线规范选择，不默认做RJ/DJ |

DDR/LPDDR报告还应记录read/write方向、byte lane、training状态；涉及WCK的代际还要记录WCK:CK比例和对应工作模式。

![图3：按链路时钟架构选择抖动测试。Tx jitter、Rx JTOL和reference clock jitter不是所有接口固定不变的“三件套”。](/images/32/ill03_when_to_care.png)

实际项目中，出现以下现象时也应该把抖动列入候选：

- 眼宽不足，但眼高仍有余量；
- BER偶发升高，并随温度、电压或负载状态变化；
- 换参考时钟、PLL档位或SSC模式后问题明显变化；
- TIE随码型、邻线活动或电源开关频率变化；
- period或cycle-to-cycle指标Fail；
- 同一DUT换仪器、夹具或CDR设置后结论不一致。

## 四、应该看哪个抖动指标

“抖动大小”不是一个统一数字。先确认工程问题，再选择观察量。

| 观察量 | 参考对象 | 回答的问题 | 不能单独回答 |
|---|---|---|---|
| TIE track | 声明的参考边沿 | 边沿误差怎样随时间变化 | 唯一根因、完整BER |
| Period jitter | 名义周期 | 单个周期偏了多少 | 长时间累积相位变化 |
| Cycle-to-cycle jitter | 相邻周期 | 相邻周期变化多大 | 低频wander |
| 相位噪声 | 理想载波及频偏 | 噪声功率分布在哪些频偏 | 数据相关抖动和最终BER |
| RJ/DJ分离 | 仪器统计模型 | 给出模型分量和外推输入 | 物理根因唯一性 |
| TJ@BER | 统计模型和目标BER | 模型假设下的水平预算 | 有限记录实测峰峰值 |
| 眼图/浴盆/BER | 参考接收机和采样条件 | 水平开口及误码证据 | 根因位置和所有工作角落 |

![图4：TIE、周期抖动、cycle-to-cycle、相位噪声和浴盆曲线回答不同问题。](/images/32/ill04_observables.png)

例如，一个独立时钟的cycle-to-cycle指标可能直接影响下游逻辑；一条嵌入时钟串行链路则更关心规范CDR处理后的发送端抖动和接收端JTOL。测错指标，即使数字很漂亮，也没有回答项目问题。

## 五、抖动不能超过多少，标准从哪里来

不存在脱离接口、代际、测试项目、测试点和参考模型的通用抖动限值。

查判据时按照下面的顺序：

1. 确认接口、代际、速率、产品形态和方向；
2. 确认测的是Tx、Rx JTOL、reference clock还是源同步时序；
3. 找Base/PHY规范、CTS、JEDEC标准、器件手册或系统时序预算；
4. 核对测试点、码型、test mode、参考通道、均衡和CDR/PLL；
5. 区分规范限值、设计目标、仪器建议和教学算例；
6. 把标准名称、版本、表格或测试项写入报告。

### 一个真实例子：USB 3.2发送端抖动

USB 3.2 Specification Revision 1.1的§6.7.3 Table 6-20规定了TP4处的发送端眼图和抖动判据。这里不是把探头接上就直接读数，而是：

- Gen1使用CP0和CP1，Gen2使用CP9和CP10；
- 采集`10^6 UI`并外推到`BER = 10^-12`；
- 在TP4处判定；
- 数据经过规定参考通道和参考均衡处理；
- 表中的Rj是按目标BER换算后的量，不是仪器报告里的`RJ RMS`。

| USB 3.2 Tx项目 | Gen1 5 GT/s | Gen2 10 GT/s |
|---|---:|---:|
| UI | 200 ps | 100 ps |
| Dj maximum | 0.430 UI（约86.0 ps） | 0.530 UI（约53.0 ps） |
| Rj maximum | 0.230 UI（约46.0 ps） | 0.141 UI（约14.1 ps） |
| Tj maximum | 0.660 UI（约132.0 ps） | 0.671 UI（约67.1 ps） |

这些数字只适用于表格声明的条件。USB 3.2同一份规范中的Table 6-19还给出了TP1处的**informative**参数，它不是Table 6-20的规范判定替代品。换测试点、换码型、换参考处理或换成Rx JTOL后，都必须重新查对应项目。

USB 3.2 Electrical Compliance Test Specification Rev 1.8的§3.3和§3.8进一步说明Gen1/Gen2 Data Eye and Jitter怎样执行；Base规范给出判据，CTS规定测试程序，两者不能只看其中一份。

![图5：抖动判据查找路径，以及USB 3.2 Rev 1.1 Table 6-20的公开规范示例。](/images/32/ill05_standard_path.png)

这个例子也说明：把本文教学算例的40.1 ps拿去和USB表格比较没有意义，因为它们的测试点、模型、码型和用途完全不同。

## 六、怎样测出抖动大小

下面是一套通用测量流程。具体参数仍以对应标准或器件手册为准。

### 先分清四种测量任务

“测抖动”至少包含下面四种不同台面。对象没分清，仪器上的数字即使正确，也可能回答了错误的问题。

| 测量任务 | 典型台面 | 核心动作与结果 |
|---|---|---|
| 串行数据Tx抖动 | DUT → Compliance Fixture/规定参考面 → 实时示波器 | 让DUT输出规定码型，按标准设置带宽、参考通道、均衡和Golden PLL/CDR，采集足够UI后读取TIE、眼宽、TJ@BER及适用分量 |
| Reference Clock抖动 | 时钟测试点/专用Fixture → 低负载探头 + 示波器或相位噪声分析仪 | 按规定频偏范围和滤波积分相位噪声，或测period、cycle-to-cycle和TIE；不能直接套串行数据的CDR设置 |
| Rx Jitter Tolerance | BERT/Pattern Generator → 抖动与损耗压力 → 校准参考面 → DUT Loopback/错误计数 | 先用校准示波器确认每个频点和幅度的受扰输入，再撤掉示波器接DUT，扫描抖动频率与幅度并读取BER；这不是被动“看Rx波形” |
| 源同步相对时序 | Data与Clock/Strobe在同一参考面同步采集 | 完成探头和通道deskew，按读写方向与训练状态测Data相对Clock、DQS、RDQS或WCK的TIE、skew、setup/hold |

因此报告不能只写“Jitter = X ps”。至少要说明这是Tx、Reference Clock、Rx JTOL还是源同步相对时序，以及测试点、时间参考和判定结果。

### 第一步：定义测量对象

先写清接口、代际、角色、方向、lane、速率、调制方式和工作模式。不要只写“测时钟抖动”或“测数据抖动”。

### 第二步：确定测试点和参考面

明确是在芯片焊盘、连接器、夹具端、近端还是经过参考通道后的测试点。测试线缆、夹具和转接板是否包含在判据内，也必须先确定。

### 第三步：准备DUT状态和码型

进入标准规定的test mode或输出指定码型。记录SSC、均衡、预加重、工作温度、电压和负载状态。

### 第四步：确认测量链能力

选择足够带宽和采样率的示波器、相位噪声分析仪或BERT；核对探头加载、夹具损耗、时基噪声、校准、deskew和去嵌。

### 第五步：设置时间参考

根据测项选择外部参考、拟合理想时钟、Golden PLL、软件CDR、硬件CDR或源同步参考。记录环路带宽、阶数、峰化和SSC处理。

### 第六步：选择观察量和分析条件

设置边沿筛选、阈值、码型、记录长度、采集UI数、带宽、滤波、均衡和分析算法。RJ/DJ分离还要记录软件版本和模型。

### 第七步：保存原始证据

保存原始波形、setup文件、分析报告、环境、边沿数量和时间戳。只有截图而没有原始数据，后续很难复核CDR、阈值或算法差异。

### 第八步：对照判据并报告不确定度

先确认测量有效，再比较判据。仪器本底、时基噪声、探头和夹具的不确定度不能用一个没有来源的固定倍数代替。

![图6：抖动测量台面。DUT、探测路径、采集、时间参考和分析设置共同决定最终读数。](/images/32/ill06_bench.png)

一份可复现的报告至少记录：

`接口/模式｜速率与调制｜码型｜测试点/参考面｜带宽/采样率｜探头/夹具/去嵌｜时间参考/CDR｜阈值/均衡｜记录长度｜算法版本｜仪器本底｜环境｜原始波形`

## 七、仪器给出的数字应该怎样理解

### 1. TIE必须绑定时间参考

同一组物理边沿，相对固定参考和跟踪型参考计算，可能得到不同TIE。CDR跟踪范围内、同时出现在数据和恢复时钟上的低频变化，可能不会完整出现在相对恢复时钟的TIE中。

![图7：橙色实际边沿完全相同；固定参考尺和跟踪型参考尺给出的可见TIE不同。具体参考必须服从接口规定的PLL/CDR模型。](/images/32/ill07_time_reference.png)

下面的动画保持橙色数据边沿完全不动，只让紫色参考刻度逐步跟随低频漂移。TIE箭头和下方TIE轨迹会同步变化。它演示的是“测量参考不同，结果可能不同”，不是接收机容限判定。

![图7b动图：数据边沿保持不变，参考刻度从固定参考逐步变成跟踪型参考，可见TIE随之变化。](/images/32/ill07b_reference_anim.gif)

### 2. RJ/DJ是工程模型，不是物理根因目录

在Dual-Dirac等常用模型中，RJ通常按高斯近似并用RMS，也就是标准差`σ`描述。有限记录中的RJ峰峰值会随带宽、采样和记录长度变化。

DJ常用于描述有界或可重复结构，候选分量包括DDJ、PJ、DCD和部分算法中的BUJ。ISI是产生DDJ的重要机制之一，但ISI和DDJ不是同义词。

![图8：RJ/DJ常用统计模型。分量名称和分离方式依标准、仪器及算法而变化。](/images/32/ill08_taxonomy.png)

### 3. Dual-Dirac外推不是有限记录实测峰峰值

常用公式为：

`TJ(BER) = DJ_δδ + 2 × Q(BER) × RJ_rms`

其中`DJ_δδ`是两个拟合高斯均值之间的间距，不能直接等同于所有物理DJ的真实`DJ_pp`。

继续使用本文教学模型：

- 5 GBd NRZ，UI = 200 ps；
- `RJ_rms = 2 ps`；
- `DJ_δδ = 12 ps`；
- 目标BER为`10^-12`；
- Dual-Dirac双尾高斯近似成立。

则：

`TJ(10^-12) = 12 + 14.07 × 2 ≈ 40.1 ps ≈ 0.20 UI`

这表示目标BER处的模型外推，不是“仪器实测到了40.1 ps峰峰值”，也不是任何接口的限值。

![图9：Dual-Dirac教学模型。40.1 ps是目标BER下的统计外推，不是有限记录实测峰峰值。](/images/32/ill09_dualdirac.png)

严重DDJ、非高斯尾部、突发误码、PAM4多阈值、FEC、模式依赖和接收机均衡都可能让简化模型失效。

## 八、抖动Fail后怎样定位

第一步不是马上改板，而是确认报告有效：

- DUT状态和码型正确吗？
- 测试点、参考面和通道处理正确吗？
- Golden PLL/CDR、带宽、阈值和均衡符合标准吗？
- 仪器本底和夹具是否足够？
- 同一条件能重复得到Fail吗？

确认测量有效后，再看证据。

### 直方图和浴盆

单峰不能证明RJ主导，双峰也不能证明DCD。码型、边沿筛选、多个周期源和参考模型都可能改变分布。浴盆曲线还受到判决阈值、垂直噪声、CDR、均衡和外推模型影响。

### TIE频谱

spur给出周期候选频率，但同频不等于同源。还要把它与电源、参考时钟、邻线和开关状态同步比较。

![图10：一个受控改频案例。TIE和电源频谱先同时出现500 kHz spur；把候选电源改为650 kHz后，两个spur同步移动。](/images/32/ill10_evidence.png)

下面的动画把候选开关电源从500 kHz调到650 kHz。只有当电源纹波、TIE轨迹和两个频谱spur同步改频，再恢复原设置能够复现时，证据才比“频率刚好相同”更强。

![图10b动图：候选开关电源从500 kHz改到650 kHz，电源spur和TIE spur同步移动。](/images/32/ill10b_correlation_anim.gif)

一套可执行的排查表如下：

| 观察 | 候选方向 | 下一条证据 |
|---|---|---|
| TIE频谱出现离散spur | 电源调制、参考杂散、周期串扰 | 同步采电源/参考/邻线；关源或改频后观察spur和BER |
| TIE随码型或边沿历史变化 | DDJ、ISI、均衡不足 | 固定码型、切换均衡、改变通道损耗 |
| 上升沿和下降沿群组不同 | DCD、阈值或路径不对称 | 分边沿统计、扫阈值、交换差分路径 |
| 改CDR带宽后读数明显变化 | 参考模型或低频跟踪影响 | 恢复标准设置并保存两组TIE |
| 换夹具或端口后异常移动 | 探头、夹具、deskew或时基 | 交换端口、重新校准、测本底和已知良品 |

![图11：抖动根因证据链。先写观察，再用同步采集、改频、开关源、换夹具和参数扫描隔离根因。](/images/32/ill11_debug.png)

每次只改变一个变量，并保存修改前后的原始波形、设置、TIE、频谱和BER。否则多个动作一起生效，即使问题消失，也无法证明哪项修复真正有效。

## 九、定位根因后怎样解决

整改必须对应已建立的根因证据。

| 根因方向 | 常见整改 | 必须同时复查 |
|---|---|---|
| 参考时钟或PLL | 优化参考源、环路参数、供电和布局 | 锁定、wander、spur、启动及全温角落 |
| 电源调制 | 改善去耦、回流、隔离和敏感rail供电 | 负载瞬态、纹波、其它rail耦合 |
| 通道损耗和ISI | 优化走线、过孔、连接器、端接和均衡 | 噪声放大、过均衡、不同码型和通道 |
| 串扰 | 增加间距、缩短并行、改善参考平面和层转换 | 其它victim、模式转换和EMI |
| DCD、阈值或路径不对称 | 修正偏置、驱动、阈值和差分路径 | 上升/下降沿、占空比、PVT角落 |
| 测试台面 | 校准、deskew、更换探头/夹具、测量本底 | 重复装夹、端口交换和已知良品 |

均衡不是万能修复。CTLE可能同时放大高频噪声，DFE依赖正确判决并可能出现错误传播，发送端预加重会改变摆幅和功耗。修复通道损耗时，必须确认没有用另一种代价换来一张更好看的单次眼图。

![图12：根因与整改对应关系，以及恢复原条件、重跑同一测项和检查最差角落的复测闭环。](/images/32/ill12_fix_retest.png)

## 十、怎样证明问题真的解决

问题消失不等于闭环完成。至少执行下面六项：

1. 恢复原来的速率、码型、温度、电压、SSC、均衡和测试台面；
2. 重跑同一个测试项目和相同记录长度；
3. 比较修改前后的原始TIE、频谱、BER和仪器设置；
4. 检查最差温压角落、lane、方向和工作模式；
5. 复查眼高、眼宽、锁定、功耗和其它相关项目是否退化；
6. 把结论限制在本次声明的测试项，不把单项抖动Pass写成完整接口合规。

最终报告应让另一个工程师能够回答：

- 测了什么；
- 相对什么参考；
- 用了哪个标准和判据；
- 为什么确认Fail有效；
- 哪条证据锁定了根因；
- 修改了什么；
- 怎样证明修改有效且没有引入明显回归。

## 十一、🔧 工程师速查

### 核心定义

| 项目 | 正确理解 |
|---|---|
| UI | `1 / Symbol Rate`；不能只看Gb/s |
| 数据边沿 | 只在符号电平发生转换时出现 |
| TIE | 被选边沿相对声明时间参考的误差 |
| RJ | 常用模型中按高斯近似并用RMS描述 |
| DJ | 有界/可重复结构的模型分量，分类依标准和算法 |
| TJ@BER | 目标BER下的统计外推，不是有限记录峰峰值 |

### 什么时候关注

| 对象 | 优先检查 |
|---|---|
| 嵌入时钟串行数据 | 规范CDR下的Tx jitter、BER和Rx JTOL |
| 参考时钟 | 相位噪声、滤波后的RMS jitter、TIE |
| 转发时钟 | clock-data关系、路径匹配和deskew |
| DDR/LPDDR | 按代际和读写方向区分DQ-DQS、DQ-RDQS或DQ-WCK；CA时序主要相对CK |
| 普通时钟 | period、cycle-to-cycle、TIE或wander |

### 判据查找

`接口/代际 → 测试对象 → 测试点/码型/参考 → Base/PHY或器件手册 → CTS执行程序 → 报告记录版本和测试项`

### 报告必填

接口与模式｜symbol rate和调制｜码型｜测试点/参考面｜探头/夹具/去嵌｜带宽/采样率｜时间参考/CDR｜阈值/均衡｜记录长度｜算法版本｜仪器本底｜环境｜原始波形

### Fail闭环

`确认报告有效 → 写观察 → 建候选 → 单变量A/B → 隔离根因 → 对应整改 → 恢复原条件 → 重跑同一测项 → 检查最差角落 → 限定结论范围`

> 本文教学案例、波形和40.1 ps算例均为合成模型；USB 3.2表格为公开规范示例，只适用于文中声明的版本、测试点、码型和参考处理条件。
