# 笔记本2.5G网口短线满速，为什么热机后会错包、掉线并回到1G？——以太网从PHY、MDI到双绞线怎么测

<div class="article-meta"><span class="badge">📘 模块六 · 高速接口一致性测试</span><span class="badge">⏱ 约 40 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


先看一个可复算、可复现的教学场景。

一台带原生RJ45的笔记本，连接经过认证的2 m Cat 6跳线和一台支持2.5GBASE-T的交换机。冷机25 ℃启动，Auto-Negotiation解析为2.5G，全双工，Training完成后Link Up；短时双向流量、文件传输和普通办公都正常。把流量固定为双向持续大包与混合包，记录温度、供电和错误计数：约40分钟后，PHY温度继续上升，某线对的SNR/MSE或错误趋势先恶化；再过几分钟，MAC侧出现FCS错误，随后记录到Local/Remote fault、Training restart或Link flap；链路重新协商成1G后，表面上又稳定了。

这里的温度、分钟数和错误顺序是**教学变量**，不是某款产品实测，也不是IEEE限值。真正复现时应固定线缆、Link Partner、流量方向、包长、散热、供电、驱动和固件版本，并用统一时钟记录：

```text
T0  上电、环境/PHY/Magnetics温度、驱动/NVM/固件版本
T1  AN广告与解析：速率、全双工、主从、EEE能力
T2  Training开始/结束、Link Up、训练耗时
T3  业务开始：方向、包长、offered load、USB/PCIe占用
T4  温度与电源轨变化、Pair C/PHY趋势
T5  首个PHY/PCS/FEC趋势或首个FCS——谁先出现必须保留
T6  Training restart、Local/Remote fault
T7  Link Down/Up、重新AN
T8  1G下同温度、同流量、同持续时间的错误结果
```

如果PHY厂商没有公开每线对SNR、MSE、symbol error或LDPC统计，就明确写“该层不可见”，不能拿零FCS反推线路零错误。反过来，看到FCS也不能立刻判定线坏、PHY坏、Magnetics坏或EEE有问题。

> ⚠️ 本文案例、时间轴和示意数据均为教学场景，不冒充任何产品实测。IEEE公开贡献稿只用于理解技术背景，不代表最终规范；模板、抖动、受压接收、BER和计时等具体限值，必须回到项目适用的IEEE 802.3版本、器件资料和授权测试工具。

## 一、以太网是什么、应用在哪里

以太网不是“一根网线加一个RJ45”，而是一套从帧、编码、模拟收发到布线介质的分层系统。笔记本里最容易混淆的是下面这些边界：

```text
主机软件/驱动
  ↓
MAC：帧、地址、流控、FCS、DMA
  ↓
PCS / PMA / PMD：编码、扰码、符号映射、CDR、均衡、回声与串扰消除
  ↓                         ┐
PHY模拟线端                 │ 通常合称PHY
  ↓                         ┘
Magnetics：隔离变压器、共模扼流圈、中心抽头网络
  ↓
MDI / RJ45参考面
  ↓
四对平衡双绞线Channel
  ↓
Link Partner
```

**MAC FCS错误是帧层结果，不是线路BER。** PCS/PMA错误、LDPC纠正块、不可纠正块、symbol error和MAC FCS属于不同层级；只有把它们放到同一时间轴，才可能看出“PHY余量先下降，还是主机/驱动先丢帧”。

笔记本还常见三种外观相似、内部完全不同的拓扑：

1. **原生RJ45**：CPU/PCH经PCIe或片内总线连接NIC，板上MAC/PHY再到Magnetics与RJ45。
2. **USB-C Dock的USB网卡**：USB主机连接Dock内USB-to-Ethernet控制器，控制器内部或外部再接PHY。
3. **Thunderbolt Dock的PCIe网卡**：PCIe经Thunderbolt隧穿到Dock，Dock内是PCIe NIC。

USB-C只说明连接器外形和端口能力，不能决定网卡走USB还是PCIe。Debug前应看设备管理器、PCI/USB枚举、Dock框图和控制器料号。USB NIC还要额外记录USB速率、Hub层级、主机控制器占用和Dock供电；PCIe NIC则关注PCIe链路、电源状态和AER。两者最后都可能接同类BASE-T PHY，但“满载掉速”的上游故障树不同。

![图2要证明：MAC、PHY、Magnetics、MDI、双绞线和Link Partner是不同证据层，且原生RJ45、USB Dock与Thunderbolt Dock不能按USB-C外形合并成同一拓扑](/images/47/ill02_stack.png)

## 二、传输原理和代际差异

### 2.1 先纠正“四对网线”的直觉

100BASE-TX全双工使用两对：一对朝一个方向发送，另一对朝相反方向发送。到了1000BASE-T以及2.5G、5G、10G BASE-T，**四对线均同时双向工作**。每对线上都叠加本地发送与远端发送，接收器需要消除自己的回声，并抑制来自其他线对的NEXT/FEXT，再做均衡、时钟恢复和符号判决。

因此不能把千兆及以上画成固定“两对Tx、两对Rx”。某一线对异常，也会同时影响两个方向，只是两端的接收算法、温度和噪声不同，最终错误可能先出现在一端。

### 2.2 五代BASE-T放在一张工程表里

| 制式 | 使用线对与双向方式 | 线路技术 | 公开可确认符号率 | 保守布线表述 |
|---|---|---|---|---|
| 100BASE-TX | 2对；全双工时每对方向相反 | 4B/5B、NRZI、MLT-3 | 125 MBd | Cat 5或更好，标准信道最长100 m |
| 1000BASE-T | 4对；每对同时双向 | 4D-PAM5、8B1Q4、格形编码 | 125 MBd/对 | Cat 5/5e或更好，最长100 m |
| 2.5GBASE-T | 4对；每对同时双向 | DSQ128/PAM16体系、LDPC | 200 MBd/对 | 100 m Cat 5e是保守标准表述 |
| 5GBASE-T | 4对；每对同时双向 | DSQ128/PAM16体系、LDPC | 400 MBd/对 | 100 m Cat 6是保守标准表述 |
| 10GBASE-T | 4对；每对同时双向 | DSQ128、PAM16分量、LDPC、THP | 800 MBd/对 | 100 m以Cat 6A为稳妥表述 |

MLT-3虽然有三个电平，但它是状态转换线码，**不要叫PAM3**。同样，PAM16有16个幅度状态，也不能直接用：

```text
4 对 × 符号率 × log2(16)
```

去计算净业务速率。2.5/5/10GBASE-T还包含DSQ128映射、PCS处理、LDPC、辅助信息和编码开销；这里列符号率是为了比较信道带宽与DSP压力，不是给出净吞吐公式。

100/1000BASE-T也不能与2.5/5/10G的LDPC计数混写。FCS发现的是完整帧末尾CRC校验不一致；LDPC发生在PHY内部，可能先纠正线路错误，直到余量进一步下降才出现不可纠正块、PCS错误或最终FCS。

### 2.3 为什么降到1G会“看起来好了”

降速不是只把吞吐数字从2.5改成1。它同时改变符号率、编码/FEC体系、接收DSP工作点、频谱占用、训练参数和部分器件功耗。假设同一条Channel在高频段IL、RL或串扰余量偏小，2.5G的200 MBd工作点可能先暴露问题；回到1G的125 MBd/对后，高频压力与接收算法都变了，错误暂时消失并不意外。

热态也不只影响“网线电阻”。可能同时变化的对象包括：

- 铜缆IL与连接器接触特性；
- PHY模拟前端噪声、时钟和DSP收敛余量；
- Magnetics损耗、droop、RL和共模；
- PHY电源纹波与稳压器热降额；
- Dock内USB/PCIe控制器、Hub和电源预算；
- Link Partner自身温度与算法状态。

所以降到1G是一个很强的**相关性证据**：故障与速率工作窗口有关；但它不是定位结论。真正有区分力的是单独加热、换Channel、换Link Partner、看每线对趋势，并验证哪一个变化总是早于FCS和Link事件。

![图3要证明：100M、1G、2.5G、5G和10G在用线对、双向方式、线路编码、符号率与布线条件上不是简单倍频关系](/images/47/ill03_generation.png)

### 2.4 AN、Training、Link Up和EEE的先后关系

正确关系是：

```text
物理连接
→ Auto-Negotiation：交换能力并选择共同模式
→ Startup / Training：主从、极性/线对识别、均衡与消除器收敛
→ Link Up
→ 正常业务
↔ 空闲时才可能进入/退出EEE Low Power Idle
```

Auto-Negotiation不是吞吐测试，Link Up也不是全Margin通过。EEE的LPI用于空闲节能；持续满载时本来就很少进入LPI。所以“关闭EEE后不掉线”只说明LPI转换、驱动、固件、供电瞬态或Link Partner互操作值得继续隔离，不能直接宣布EEE不合格。

![动图1要证明：1000BASE-T及以上四对均同时双向，AN结束后才训练回声/NEXT/FEXT消除与均衡，Link Up后业务与EEE LPI按空闲状态切换](/images/47/anim01_four_pair_training.gif)

## 三、正确使用与设计注意事项

### 3.1 把通道当成平衡系统，不是两根“各50 Ω”的普通线

BASE-T布线通常称100 Ω平衡差分系统，但这不等于任何位置、任何频率、任何测试法都应读到精确100 Ω。连接器、线缆绞距、Via、Magnetics、共模扼流圈和端接都会形成频率相关响应；正式MDI Return Loss测试还可能规定85/100/115 Ω等具体负载条件。写报告时应记录实际条款、负载与参考面，而不是只写“以太网永远100 Ω”。

### 3.2 Magnetics前后不能直接对表

隔离变压器前后有不同的：

- 端接与阻抗环境；
- 直流偏置和中心抽头网络；
- 共模参考；
- 幅度、droop与频谱；
- 安全隔离边界。

所以PHY芯片侧探到的波形、Magnetics线缆侧的MDI波形、RJ45外接线缆后的波形不能共用同一限值。更不能跨隔离变压器把普通单端探头地线接成“共同地”，这既可能短接隔离边界，也可能制造错误共模路径。正式测试优先使用标准夹具、匹配SMA路径或真正差分测量。

### 3.3 设计审查要同时看差模、共模和热

布局除了差分阻抗和长度，还应检查：

- PHY到Magnetics的MDI走线、Via与参考平面；
- Magnetics下方铜皮、机壳地/数字地边界；
- RJ45屏蔽、Bob Smith或适用共模端接；
- 四对间串扰、连接器针脚和焊接质量；
- PHY电源噪声、参考时钟和散热；
- 中心抽头与PoE相关直流路径。

PoE在本文只作为控制变量：对端是否供电、中心抽头是否承载直流、线束是否升温。除非DUT本身是PSE或PD，否则不要把PoE供电一致性扩成本文主线。

### 3.4 线缆标称类别不是本次Channel一定合格

“Cat 6短线”是料号标签，“按指定TIA/ISO limit完成认证”才是测量证据。压接、弯折、跳线头、配线架、耦合器、温度和线束Alien Crosstalk都可能改变结果。10GBASE-T尤其不能把Cat 6简化成无条件“55 m必过”；实际可用长度与外来串扰和安装环境有关。

## 四、以太网一致性测试到底测什么

完整结论至少拆成五栏：

| 测试域 | 回答的问题 | 常用结果 | 不能替代 |
|---|---|---|---|
| Tx / MDI | DUT发送波形是否满足对应速率和条款 | 模板、峰值、droop、抖动、时钟、失真、PSD、功率、共模、RL | 不能证明Rx容限 |
| 正式Rx | 接收器能否承受规定损耗、噪声、串扰和扰动 | BER或标准定义错误事件 | 不能用普通流量代替 |
| 功能流量 | 系统业务是否丢帧、错帧、掉链 | 吞吐、FCS、丢包、Link事件 | 不等于线路BER |
| PHY遥测 | DSP余量怎样变化 | 每对SNR/MSE、symbol、PCS、FEC | 厂商专有，不是通用限值 |
| Channel | 无源布线损耗、反射、串扰与平衡怎样 | IL、RL、NEXT、ACRF、TCL等 | 不能证明有源PHY合格 |

这五栏还要分成两类：

- **Characterization**：固定速率、关EEE、换线、换端口、加热、扫供电、读厂商遥测，用于找相关性和首错；
- **可签字结果**：在适用标准版本、正式test mode、夹具、校准、参考面和授权工具下得到的结果。

Debug动作不会自动升级成一致性结果。例如“仅广告2.5G后稳定”可能绕开了正常多速率AN路径；“关EEE后稳定”可能只改变状态转换；“换短线后通过”只证明组合变化。它们很有价值，但报告必须放在Characterization栏。

![图4要证明：Tx、正式受压Rx、功能流量、PHY遥测与Channel认证回答不同问题，Characterization证据不能自动冒充可签字一致性结果](/images/47/ill04_matrix.png)

## 五、Tx、Rx、Channel分别怎么测

### 5.1 Tx / MDI：先让PHY发对测试模式

正式Tx通常要求DUT进入对应PHY test mode，并明确速率、线对和主从角色。不同代际项目不同，公开工具常覆盖：

- 发射模板、峰值与droop；
- 主/从模式抖动和发射时钟频率；
- 失真、线性或非线性；
- PSD与总功率；
- 共模输出；
- MDI Return Loss。

例如1000BASE-T公开测试资料常按Test Mode 1做模板/峰值/droop，Mode 2/3观察主从抖动，Mode 4做失真、共模及相关项目；2.5/5/10G则应按对应IEEE条款和工具流程配置。不能拿1G的测试模式名称、负载或模板套给2.5G。

```text
DUT PHY test mode
→ 板上Magnetics
→ 标准MDI fixture / SMA
→ 示波器或频谱分析
→ 对应速率Compliance软件
```

![图5要证明：Tx签字必须从正确PHY test mode经标准MDI夹具移动到声明参考面，不能用普通业务包和任意RJ45分线板代替](/images/47/fig_setup_tx.png)

### 5.2 Rx：三类“接收测试”必须分开写

**正式受压接收**使用AWG/BERT/噪声源或专用测试系统，向DUT施加规定的损耗、噪声、串扰和扰动，再按标准定义统计BER或错误事件。输入压力要先在校准参考面建立，不能凭“线很长、网络很忙”代替。

**功能流量测试**用流量发生器、交换机或对端主机发送指定方向、包长和负载，统计吞吐、丢帧、FCS和Link中断。它最接近用户体验，但不能自动给出线路BER。

**PHY遥测**来自MDIO、驱动或厂商工具，例如每线对MSE/SNR margin、symbol error、LDPC corrected/uncorrectable。它适合抓首错趋势，但名称、单位、采样周期和门限必须引用具体器件资料；没有公开定义就只做趋势，不写IEEE Pass/Fail。

![图6要证明：正式受压接收、帧级流量/FCS测试和PHY内部遥测是三套结果，只有第一类按适用条款和校准才能承担Rx签字](/images/47/fig_setup_rx.png)

### 5.3 Channel：认证、表征和定位各用一把尺

Channel重点包括：

- **IL（Insertion Loss）**：信号随频率、长度和温度增加而衰减；
- **RL（Return Loss）**：阻抗不连续引起的反射；
- **NEXT / PSNEXT**：近端线对串扰及其功率和；
- **FEXT / ACRF**：远端串扰结合线路衰减后的解释；
- **TCL / ELTCTL**：差模到共模转换、平衡和抗噪能力；
- **Alien Crosstalk**：相邻线缆之间的串扰。

工具边界也要写清：

| 工具 | 最擅长 | 不能单独证明 |
|---|---|---|
| Cable analyzer | 按选定TIA/ISO limit做wiremap、长度、IL、RL、NEXT、ACRF等认证 | 不能证明PHY Tx/Rx |
| VNA | 差分/共模S参数、IL/RL、模式转换、夹具和Magnetics表征 | 不能自动给整条安装链路认证结论 |
| TDR | 定位开短路、阻抗突变、连接器和故障距离 | 不能代替全频段串扰与损耗认证 |
| Scope | 看时域发射、共模、电源与热态瞬态 | 不能代替Channel全套频域限制 |

![图7要证明：Cable analyzer负责布线认证，VNA负责S参数与模式转换，TDR负责位置定位，示波器负责有源时域；四者不能互相冒名](/images/47/fig_setup_channel.png)

## 六、测试环境和仪器怎么搭

一套能把主案例查清、又能产出正式结果的台面，建议分成三层。

### 6.1 系统复现层

```text
笔记本原生RJ45 / Dock
↔ 已认证短线或指定Channel
↔ 可控Link Partner / 流量分析仪

同步记录：
流量与FCS + Link/AN事件 + PHY遥测
+ PHY/Magnetics/线缆温度 + 电源轨 + 主机总线状态
```

Link Partner至少准备两种不同PHY实现，线缆准备“已认证短线、已认证边界线、嫌疑线”三类。若测Dock，同时记录USB或Thunderbolt拓扑、Dock电源和Hub/PCIe状态，避免把上游堵塞误判成MDI错误。

### 6.2 正式电气层

- 可进入PHY test mode的DUT与MDIO/厂商控制工具；
- 标准或测试方案支持的MDI fixture；
- 足够带宽和动态范围的示波器、差分探头或匹配SMA电缆；
- AWG、受压接收源、BERT或Ethernet分析仪；
- VNA、TDR、铜缆认证仪；
- 校准件、去嵌文件和可追溯的仪器校准状态。

### 6.3 环境与控制层

温箱不是唯一办法。主案例可先用局部可控加热，把变量拆开：

1. 只加热PHY附近；
2. 只加热Magnetics/RJ45；
3. 只升高线缆温度；
4. 整机热稳态；
5. 同温度下改变风扇和供电。

热电偶位置要写清，不能用“整机温度80 ℃”代替PHY结温、外壳温度和线缆温度。PoE对端若存在，也要固定其供电状态，避免中心抽头直流与线束温升成为隐变量。

### 6.4 台面本身也要先做健康检查

正式测DUT前，先证明台面没有制造故障：

1. 用已知良好DUT或校验件跑一遍连接与自动化流程；
2. 检查fixture四对端口映射、极性、SMA扭矩和电缆相位稳定性；
3. 对VNA确认校准类型、端口延伸、混合模转换和参考阻抗；
4. 对示波器确认通道deskew、探头共模范围及是否发生过载；
5. 对受压Rx先在校准夹具端验证压力，再接DUT；
6. 对系统流量确认统计点位于发送端、接收端还是交换机端口。

还有一个常见陷阱：为了接入fixture，拆掉原板Magnetics或换成外置Magnetics后，测到的已经不是量产路径。这样的板可以用于PHY芯片Characterization，但若要给整机MDI签字，必须证明测试路径、量产Magnetics和声明参考面之间的对应关系。

## 七、仪器关键设置

### 7.1 先锁定参考面

报告应明确测量点是：

- PHY芯片侧；
- Magnetics前；
- Magnetics线缆侧MDI；
- RJ45后；
- 某段Channel两端。

VNA只测校准参考面之间的网络；要移除夹具，必须使用对应S参数做de-embedding，并检查端口定义、频率范围、因果性和噪声放大。不同参考面的结果不能在同一张表里直接比分贝或幅度。

### 7.2 差分和共模都要用正确连接

BASE-T是平衡传输。普通单端探头长地线会引入环路、电感和共模转换；跨隔离变压器共地更是错误接法。使用差分探头时也要记录：

- 探头带宽、衰减和输入负载；
- 两输入端的deskew与共模范围；
- 夹具及电缆损耗；
- 是否应用带宽限制和去嵌；
- 测量的是差模、共模还是模式转换。

### 7.3 Test mode、主从、线对和负载缺一不可

Tx报告至少写：

```text
速率 / IEEE条款 / PHY test mode
线对A/B/C/D
Master或Slave
负载条件：例如适用流程规定的85/100/115 Ω
Fixture / Calibration / Reference plane
Scope带宽、采样率、记录长度
Compliance软件及配置版本
```

### 7.4 Rx校准与误码时间不能凭经验填

正式受压Rx的噪声、损耗、串扰、抖动、幅度和测试时长由适用条款决定。公开资料没有给出完整数值时，正确写法是“按IEEE 802.3适用版本与授权工具校准”，而不是编一个BER门限。流量测试则要明确包长分布、双向比例、线速定义、offload设置和统计点。

### 7.5 时间轴必须用同一时钟

系统日志、交换机计数、PHY寄存器、电源波形和温度采样若各用本地时间，秒级偏差就可能颠倒因果。应使用单调时钟或统一触发，至少保证：

```text
供电瞬态 → PHY错误趋势 → FCS → Fault → Link Down
```

的先后关系可信。若采样周期太慢，只能写“同一时间窗口相关”，不能写“某事件先导致另一事件”。

## 八、判据和标准从哪里来

正式判据按四层追溯：

1. **IEEE 802.3适用版本与条款**：确定该速率的PMA/PMD、MDI、AN、受压接收和测试模式要求；
2. **器件资料**：确定PHY test mode进入方式、寄存器语义、温度等级、供电和已知errata；
3. **授权测试工具与夹具文档**：确定连接、校准、85/100/115 Ω等负载、软件支持范围和自动报告；
4. **TIA/ISO布线标准与认证仪limit**：确定Channel或Permanent Link的认证边界。

IEEE工作组公开贡献稿、教程和厂商应用笔记可以解释200/400/800 MBd、PAM16/DSQ128、LDPC和测试项目，但不能替代最终规范。尤其不要从公开幻灯片抄一个mask、抖动或BER数字，跨标准版本直接签字。

还要防止两个常见越界：

- **OPEN Alliance BASE-T1**主要面向汽车单对以太网。它的模式转换、夹具和测试思路可学习，但限值与参考面不能套给RJ45 BASE-T。
- 自动“Ethernet compliance”软件可能只覆盖Tx与MDI Return Loss，不代表Rx、MAC、Channel、互操作和热态全通过。

## 九、报告怎么看

先检查报告是否回答了“谁、在哪、以什么条件测”：

| 类别 | 最小字段 |
|---|---|
| DUT | 笔记本/Dock、板号、PHY/NIC/Magnetics/RJ45料号 |
| 软件 | BIOS、驱动、NVM、PHY固件、OS与offload |
| 链路 | AN广告/解析、速率、双工、主从、EEE、Training耗时 |
| Channel | 线缆/连接器/端口、认证报告、长度与温度 |
| 台面 | Scope/BERT/VNA/TDR/认证仪、fixture、校准与参考面 |
| 流量 | 方向、包长、offered load、时长、Link Partner |
| 环境 | PHY/Magnetics/线缆温度、供电与散热 |
| 错误 | PCS/PMA、FEC、FCS、丢帧、Fault、Link事件 |
| 标准 | IEEE版本/条款、工具版本、未覆盖项 |

然后不要先看最终“1G稳定”，先找**第一处变化**：

1. 是温度还是供电先变化？
2. 是否某线对MSE/SNR先恶化？
3. LDPC corrected是否先增加，随后才有uncorrectable或FCS？
4. FCS是本端接收计数还是对端看到？
5. Fault、Training restart和Link flap谁先？
6. 重新AN时，本端广告是否改变，还是Link Partner解析不同？

如果PHY不公开FEC或每线对指标，报告应保留空栏并注明不可见。不能为了让图表完整，把MAC FCS填进“BER”栏。

### 9.1 用一段教学时间轴练习判读

假设同一轮测试记录到：

```text
00:00  2.5G AN完成，Training 1.8 s，Link Up
28:00  PHY外壳温度从46 ℃升到78 ℃，供电无可见跌落
34:00  Pair C厂商MSE趋势开始偏离其他三对
37:20  LDPC corrected计数加速
39:05  首个uncorrectable/PCS错误
39:06  对端Rx FCS开始增加
41:12  Remote fault，随后Link Down
41:16  重新AN，最终1G Link Up
60:00  同温度继续流量，1G未见新增FCS
```

这些数字仍是教学模型，不是门限。它支持的结论是：**Pair C相关PHY裕量趋势早于帧错误，帧错误又早于Link flap；降到1G后当前条件可工作。** 它还不能证明Pair C线缆坏，因为异常也可能来自本端/对端模拟前端、Magnetics或RJ45。

下一步应交叉验证：换一根已认证线后异常是否仍锁定逻辑Pair C；交换端口后是否跟随本机；TDR/RL是否在同一物理对出现位置一致的异常；局部加热本端PHY能否提前Tfirst。若供电采样只有每秒一次，则只能说“未观察到慢速跌落”，不能排除微秒级瞬态。报告的价值就在于把“看到什么”和“尚未证明什么”同时写清。

![图8要证明：统一报告要把温度、供电、AN/Training、每线对PHY指标、FEC、FCS和Link事件对齐，结论从首错顺序而非最终降到1G倒推](/images/47/ill05_report.png)

## 十、常见问题如何Debug

回到开场案例，建议按“先证明症状，再分层，再做正式测试”的顺序。

### 10.1 第一步：冻结复现条件

固定并保存：

- 原生RJ45还是Dock，若为Dock则记录USB/Thunderbolt枚举；
- PHY/NIC stepping、NVM、驱动和固件；
- Link Partner型号、端口和固件；
- 已认证线缆、长度和连接路径；
- AN广告/解析、主从、EEE和downshift策略；
- 单向/双向流量、包长、offload与持续时间；
- PHY/Magnetics/线缆温度、供电和风扇；
- 全部错误计数的清零时刻与采样周期。

### 10.2 第二步：确认错误在哪一层

```text
主机吞吐下降但无FCS/Link事件
→ 先查USB/PCIe、驱动、CPU与队列

FCS增加，但PHY遥测不可见
→ 保留帧层事实，继续做线缆/端口/LP A/B与正式电气测试

FEC corrected或每对MSE先恶化
→ PHY余量相关性上升，但阈值仍按器件定义

供电跌落先于PHY/FCS
→ 优先验证电源因果

Link flap后回到1G
→ 查重新AN广告、downshift、固件策略和LP解析
```

### 10.3 第三步：按优先级做A/B矩阵

| 变量 | A/B设计 | 能说明什么 | 不能直接说明什么 |
|---|---|---|---|
| 线缆 | 已认证短线/边界线/嫌疑线 | 错误是否随Channel压力变化 | 不能直接判PHY坏 |
| 端口 | 同线换交换机端口 | 对端端口相关性 | 不能替代线缆认证 |
| Link Partner | 两种PHY实现 | 互操作相关性 | 不能直接判一方不合规 |
| 速率 | Auto多速率/仅2.5G/1G | 工作窗口与状态机线索 | 固定速率通常不是签字模式 |
| EEE | 双端确认开/关 | LPI路径相关性 | 不能证明EEE本身有缺陷 |
| 流量 | Tx/Rx/双向，小包/大包/混合 | 方向、PPS与热负载相关性 | 不等于正式Rx |
| 温度 | 加热PHY/Magnetics/线缆/整机 | 热敏位置相关性 | 不等于器件超规格 |
| 供电 | 原装电源/受控边界，测PHY轨 | 电源先后关系 | 不能只看平均电压 |
| 每线对 | A/B/C/D遥测、RL/NEXT/TDR | 缩小到线对/位置 | 厂商遥测不是IEEE门限 |
| Magnetics | 线缆侧MDI与芯片侧分开测 | 参考面前后差异 | 不能套同一幅度限值 |

### 10.4 第四步：用结果组合，而不是单条现象定根因

- **错误跟着同一根线移动**：Channel、压接、连接器优先级上升，再用认证仪和TDR确认。
- **所有线与Link Partner都在本地PHY达到相似温度后首错**：本地PHY、Magnetics、供电、时钟、布局优先级上升。
- **只在某个Link Partner或EEE组合出现**：互操作、驱动、固件和LPI转换优先级上升。
- **某线对MSE恶化，并与RL/TDR异常位置一致**：该线对、RJ45焊点、Magnetics或通道缺陷成为强候选。
- **FEC corrected先升、再出现uncorrectable/FCS**：可描述为PHY余量先被消耗，但必须引用具体PHY计数语义。
- **1G稳定**：只能说明较低速率、不同编码和DSP工作点下窗口可用；不能独立判断线、PHY、Magnetics或EEE谁坏。

### 10.5 第五步：修复后回原条件复测

可能修复包括更换异常线缆或RJ45、改善焊接和Magnetics选型、修正MDI布局与共模路径、改善PHY供电/时钟/散热、更新驱动/NVM/固件、修复Link Partner互操作策略。

关闭问题必须恢复：

```text
原2.5G Auto-Negotiation正常模式
+ 原EEE要求
+ 原双向流量与包长
+ 原Link Partner与线缆压力
+ 原热稳态与供电边界
+ 原持续时间并留足首错观察窗
```

然后再补正式Tx、正式Rx和Channel签字项。只在1G、关EEE、固定速率或更短线下通过，最多算规避与Characterization，不算原问题关闭。

![动图2要证明：热态下应先捕获每线对/FEC等PHY首错，再对齐FCS、Fault、Training restart和Link flap；回到1G只是工作窗口变化](/images/47/anim02_first_error.gif)

## 十一、工程师速查

### 11.1 五个起手问题

1. **什么拓扑？** 原生RJ45、USB NIC Dock还是Thunderbolt/PCIe NIC Dock？
2. **哪一层先错？** 主机吞吐、MAC FCS、PCS/PMA、FEC、每线对遥测还是Link状态？
3. **哪个参考面？** PHY侧、Magnetics前、MDI、RJ45后还是Channel端点？
4. **什么模式？** AN广告/解析、主从、Training耗时、EEE和最终速率是什么？
5. **谁先变化？** 温度、供电、PHY趋势、FCS、Fault还是Link flap？

### 11.2 Tx / Rx / Channel最短边界

| 对象 | 关键动作 | 最容易犯的错 |
|---|---|---|
| Tx/MDI | PHY test mode、标准fixture、正确负载与参考面 | 用业务流量和普通分线板代替 |
| 正式Rx | 校准受压信号并统计标准规定错误 | 用iperf/FCS冒充BER |
| PHY遥测 | 同步读每对MSE/SNR、PCS/FEC趋势 | 把厂商读数当IEEE通用门限 |
| Channel | 认证仪+VNA+TDR按任务分工 | TDR正常就宣布通道全过 |
| 系统流量 | 固定方向、包长、负载和offload | 吞吐下降就直接怪网线 |

### 11.3 五代BASE-T速记

```text
100BASE-TX：2对，MLT-3，125 MBd
1000BASE-T：4对同时双向，4D-PAM5，125 MBd/对
2.5GBASE-T：4对同时双向，DSQ128/PAM16 + LDPC，200 MBd/对
5GBASE-T：4对同时双向，DSQ128/PAM16 + LDPC，400 MBd/对
10GBASE-T：4对同时双向，DSQ128/PAM16 + LDPC，800 MBd/对
```

### 11.4 不可越过的结论边界

- Link Up ≠ Tx/Rx/Channel和热态余量全部通过；
- 1G稳定 ≠ 线坏，也≠ PHY坏；
- FCS/CRC ≠ PHY BER，CRC不会“纠正”线路错误；
- 2.5/5/10G的LDPC计数 ≠ 100/1000BASE-T通用指标；
- 关EEE有效 ≠ EEE规范缺陷；
- 固定速率有效 ≠ 正常AN模式一致性通过；
- Magnetics前后波形 ≠ 可用同一限值直接比较；
- 100 Ω标称系统 ≠ 所有Return Loss测试只接100 Ω；
- OPEN Alliance BASE-T1限值 ≠ RJ45 BASE-T限值；
- 公开IEEE贡献稿 ≠ 最终标准正文。

### 11.5 Debug最短闭环

```text
冻结拓扑、版本、线缆、LP、流量、温度与供电
→ 对齐AN / Training / Link Up
→ 找PHY、FCS、Fault和Link中的首错
→ 换线 / 端口 / LP / EEE / 速率 / 温度 / 供电做单变量A/B
→ 按证据进入Tx / 正式Rx / Channel台面
→ 修复
→ 回原2.5G Auto、原EEE、原热态和原长稳条件复测
```
