先说个几乎人人都遇到过的现象。

你换了台新电视，标称 **4K 120Hz / 8K**，兴冲冲接上游戏机或电脑。有时候一切完美；有时候一插——**黑屏、雪花、闪一下就没信号，或者分辨率被硬压到 4K30、颜色发绿发暗**。换根"看起来一模一样"的 HDMI 线，居然又好了。

问题来了：**接口、插头、分辨率标称都一样，为什么行不行差这么多？**

答案藏在一个大多数人没意识到的事实里：**HDMI 这个口，内部悄悄换过一次"发动机"。** 老设备用 TMDS，HDMI 2.1 的高分辨率靠 FRL，两者的物理传输方式**根本不是一回事**。而测试工程师要保证"这个 HDMI 口 / 这根线跟全世界的电视都能通"，就得分别按这两套机制去测——**这，就是这一篇要讲的。**

## 一、先认清主角：HDMI 是什么、身边到处都是它

**HDMI（High-Definition Multimedia Interface，高清多媒体接口）** 是把**视频 + 音频 + 控制信息**打包，用一根线在一个"源"和一个"显示端"之间单向传输的接口。用协议里的话说，一端叫 **Source（源，如游戏机、电脑、机顶盒）**，另一端叫 **Sink（宿 / 显示端，如电视、显示器）**。

它有多普及不用多说：电视、显示器、游戏机、机顶盒、投影仪、笔记本的投屏口、相机的取景外接……**客厅和办公桌上最常见的那个梯形口，基本就是它。** 也正因为无处不在、面对全世界成千上万种电视和线材，它才必须做**一致性测试**——保证"跟谁都能通"。

和前面讲的 USB 相比，HDMI 有两个鲜明特点，直接决定了它怎么测：

- **它是"显示专用、基本单向"的**：Source 一个劲儿往 Sink 送像素，没有 USB 那种对等的双向数据。所以测试天然分成 **Source（发送端）测试**和 **Sink（接收端）测试**两大阵营。
- **它自带一整套边带小道**：两端靠这些低速通道互相"通报家底"——你支持什么分辨率、支持不支持 FRL、要不要切模式。它们虽然不跑一个像素，却是**能不能协商到高规格**的关键（很多"掉分辨率"就死在这里）。主要有四条：
  - **DDC**（I²C 类）：读对端的 **EDID**，知道它支持哪些分辨率 / 色深 / 特性。
  - **SCDC**（HDMI 2.0 引入，也走 DDC 物理层）：报链路状态、切 TMDS Bit Clock Ratio 与加扰、FRL 链路训练的握手，以及**读回 CED 错误计数**——接收端一致性测试的判据就从这儿来。
  - **HPD（Hot Plug Detect，热插拔检测）**：Sink 拉高告诉 Source"我在、我的 EDID 可以读了"。**HPD 抖动或时序不对，就是那种"插拔一下才好、忽好忽坏"的典型元凶**，比信号质量常见得多。
  - **CEC**：一根单线的低速控制总线，管遥控联动、一键开机这类事，和画面通不通没关系。

## 二、原理与演进：老发动机 TMDS，新发动机 FRL

HDMI 的物理层历史，可以粗暴地分成"FRL 之前"和"FRL 之后"。

### 2.1 老发动机：TMDS（HDMI 1.x / 2.0）

**TMDS（Transition Minimized Differential Signaling，最小化跳变差分信号）** 是 HDMI 从出生就用的方式，从 DVI 继承而来。它长这样：

- **3 条数据通道** + **1 条独立的时钟通道**。三条数据分别扛 R / G / B（或对应的分量），时钟通道**直接把像素时钟发过去**。
- 每条数据通道把 8-bit 像素数据编成 **8b/10b** 的 10-bit 符号（做 DC 平衡 + 控制字符），所以**数据通道的位速率 ≈ 10 × 像素时钟**。
- 时钟是"转发"过去的（forwarded clock / 源同步）：**接收端不用费劲从数据里恢复时钟，直接拿那条时钟通道去采样数据。**

速率上：**HDMI 1.4 总带宽约 10.2 Gbps（每通道 ~3.4 Gbps）；HDMI 2.0 提到 18 Gbps（每通道 6 Gbps）**，编码都是 8b/10b。到 HDMI 2.0，TMDS 基本摸到了天花板——再往上，靠"转发一根时钟 + 8b/10b"这套已经吃力了。

> 📌 **一个容易被简化掉的细节**：上面说"时钟通道把像素时钟发过去"，在 **HDMI 1.4 及 ≤3.4 Gbps/ch** 时是字面成立的（bit rate = 10 × TMDS clock）。但 HDMI 2.0 一旦超过 **3.4 Gbps/ch**，规范就把 **TMDS Bit Clock Ratio 改成 1/40**——时钟通道上跑的是**像素时钟的 1/4**，同时**强制打开加扰（scrambling）**来压 EMI 和 DC 漂移。这两件事都由 **SCDC 寄存器**控制——**这正是 SCDC 在 HDMI 2.0 被引入的直接原因**。
>
> 落到台面上很实际：测 6 Gbps/ch 时，那条时钟线上量到的是 **150 MHz** 而不是 600 MHz，别以为是设备坏了；而且**加扰没打开或两端不一致，画面就是花的**，这是 HDMI 2.0 时代一类很典型的翻车。

> ⚠️ 这里有个**最容易被误解**的点：TMDS 转发了时钟，是不是就不用看眼图了？**恰恰要看。** 时钟转发只是省了接收端恢复时钟的力气；可三条数据通道跑在 10× 像素时钟的高速上，一样会被抖动、码间串扰、线损搞坏。所以 **HDMI Source 一致性测试从 TMDS 时代起就是"数据通道的眼图 + 眼图模板"**——转发时钟解决的是"何时采样"，眼图解决的是"采样点上信号还睁不睁得开"。这两件事是分开的。

### 2.2 新发动机：FRL（HDMI 2.1）

HDMI 2.1 要上 **4K120 / 8K60** 这种量级，TMDS 那套撑不住了，于是引入了全新的 **FRL（Fixed Rate Link，固定速率链路）**：

- **把那条独立时钟通道也改成数据 lane**——从"3 数据 + 1 时钟"变成**最多 4 条数据 lane**，不再单独发时钟。
- **时钟埋进数据里，接收端靠 CDR（时钟数据恢复）自己捞出来**——这一步，HDMI 就跨进了 USB 3.x / PCIe / DisplayPort 那个"嵌入式时钟"的世界。
- 编码换成更省的 **16b/18b**（效率 ~88.9%，比 8b/10b 的 80% 高）。
- 传输前要先做 **link training（链路训练）**：Source 先从 EDID / SCDC 得知 Sink 支持到哪一档，然后**从目标档往低试**——训得上就用，训不上就降一档重来，看在这根线、这块板上最高能稳到哪一档；训练结果通过 **SCDC** 边带通报。一路降到底还不行，就退回 TMDS。

FRL 分 6 档，是一张要记住的表：

- **FRL1 = 3 lane × 3G = 9 Gbps**
- **FRL2 = 3 lane × 6G = 18 Gbps**
- **FRL3 = 4 lane × 6G = 24 Gbps**
- **FRL4 = 4 lane × 8G = 32 Gbps**
- **FRL5 = 4 lane × 10G = 40 Gbps**
- **FRL6 = 4 lane × 12G = 48 Gbps**（HDMI 2.1 顶格）

> 💡 注意 **FRL2 和 FRL3 的每 lane 速率是一样的（都是 6 G/lane）**，差别只在用 3 条还是 4 条 lane。**对眼图测试来说这两档没区别**——同一只眼、同一个模板。所以后面那张掉档动图里，判定是按**每 lane 速率**（12 / 10 / 8 / 6 / 3 G）做的，6 G/lane 过不了就只能直接掉到 3 G/lane 的 FRL1，看上去像"跳过了 FRL2"，其实是因为 FRL2 和 FRL3 在物理层根本是同一道坎。

> ⚠️ **48G ≠ 什么都能开**。上面 FRL6 常被说成"8K60"，但严格算一笔账：8K60 RGB 8bit 的净数据率约 47.8 Gbps，过 16b/18b 编码后要 ~53.8 Gbps 链路，**48G 装不下**。真要上 8K60，得靠 **DSC（Display Stream Compression，视觉无损压缩，HDMI 2.1 引入）** 或者降到 **4:2:0** 色度采样。DSC 是 HDMI 2.1 里和 FRL 并列的另一块拼图：**它让低档 FRL 也能顶高画质**——所以现实中"训到第几档"和"能开什么画质"之间，还夹着一层"对端支不支持 DSC"。排障时如果高刷开不了，除了查 FRL 档，也要查 DSC 有没有协商上。

> **为什么速率翻倍这么致命？** 线的时间常数只跟线本身有关，跟你在上面跑多快毫无关系；可码间串扰是**按 UI 记的**，而 UI = 1 / 速率。速率翻倍 → UI 减半 → 同样一根线造成的 ISI 就翻倍。这就是 **FRL 的判据必须扣在参考均衡之后**的物理根源：扣在裸眼上，这根线永远也过不了。

## 三、正确使用与设计要点：线材等级、走线、那条边带小道

在讲测试之前，先说清"用对"，因为一半以上的 HDMI 翻车根本不在芯片，在**线和边带**：

- **线材等级要对上速率**：跑 18G 需要 **Premium High Speed HDMI Cable**，跑 48G FRL 需要 **Ultra High Speed HDMI Cable**（带认证标）。一根标称"支持 8K"却没过认证的便宜线，link training 时上不了 FRL6，直接掉档——这就是"换根线又好了"的物理原因。
- **PCB 走线与连接器**：4 对差分（FRL 下全是数据 lane）要严格等长、控阻抗（差分 100Ω）、少过孔、控 lane 间 skew；连接器和 ESD 器件的寄生会吃掉高频，48G 下尤其敏感。
- **别忽视边带**：**DDC**（读 EDID）、**SCDC**（HDMI 2.0 引入，切 Clock Ratio / 加扰、FRL 报状态、读 CED）是低速 I²C 类信号，**HPD** 则是一根电平线。**它们一旦不稳，能力协商就崩**——现象往往不是花屏，而是"根本协商不到高分辨率""插拔一下才好""忽好忽坏"。长线、带转接头、过 KVM / 分配器的场合，这几条边带比高速 lane 更容易先出问题。
- **HDCP（内容保护）握手**：这不是信号质量问题，但握手失败会直接黑屏。排查"黑屏"时要能把 HDCP 和信号完整性分开看。

### 「插损差 8 dB」到底意味着什么：一张动图看逐级掉档

上面算过：同样 4 米，Ultra 认证线插损 12.3 dB、便宜线 20.4 dB。这 8.1 dB 的差距，落到用户眼里就是"能不能开 4K120"。下面这张动图把插损从 7 dB 一路扫到 30 dB，**对 FRL 的每一个候选速率都真跑一遍"过参考均衡之后的眼图判定"，取能过的最高档**——这就是 link training 在真机上做的事，不是查表，是真算。

## 四、测什么·三类：Source 眼图、Sink 压力测试、线材通道

HDMI 一致性测试（**CTS，Compliance Test Specification**；HDMI 2.1 及 FRL 由 **HDMI Forum** 维护，1.x/2.0 由 HDMI LA 维护）落到电气层，就是三类——和第 35 篇的 **Tx / Rx / Channel** 三分法一一对应：

**① Source（发送端 / Tx）——测"发得干不干净"，看眼图。**
- **TMDS 模式**：在规定测试点抓三条数据通道的波形，叠成眼图，扣 **TMDS 眼图模板**；同时测抖动、上升 / 下降时间、电平。
- **FRL 模式**：让 Source 进 FRL 测试模式、发 FRL 测试码型，抓每条 lane 的眼图，**先过 golden PLL 和参考接收器的 CTLE（本篇取 9 dB），再扣 FRL 眼图模板**——这套和 USB 3.x / PCIe 的发送端眼图测试**思路完全一致**（因为 FRL 就是嵌入式时钟那一路）。

> 注意：**Source 端有两套模板，而且扣法不一样**——TMDS 裸眼直接扣，FRL 要先过均衡再扣。这正是 HDMI 横跨两套架构最直接的体现，也是最容易扣错的地方。一台仪器、两套模板，测之前先想清楚这次到底在测哪一套。

**② Sink（接收端 / Rx）——测"脏信号还认不认"，做压力测试。**
- 用码型发生器 / BERT **造一只"最坏压力眼"**（叠加规定的抖动、幅度损耗、ISI），灌给 Sink，看它在这种恶劣条件下**还能不能正确接收、link 稳不稳**——即**抖动容限 / 接收灵敏度**。
- **判据不看画面花不花**，而是读 SCDC 里的 **CED 计数器**逐 lane 统计字符错误，压满规定时间不涨才算过。
- 还要验 Sink 的时钟恢复 / PLL 跟踪能力（FRL 下尤为关键）。这一步和第 38 篇 USB 3.x 的 **Rx jitter tolerance** 是同一套哲学。

**③ Cable / Channel（线材 / 通道）——测"这根线扛不扛得住"。**
- 衰减、lane 间 skew、阻抗 / 回损、串扰。**Ultra High Speed 线的认证**核心就是这块——保证 48G 下信号还能过。

![图6：HDMI 测什么·三类（对齐第 35 篇 Tx / Rx / Channel）。① Source / Tx 看眼图：并排两只真仿真眼——同一根 4 米线上，TMDS 裸眼（眼高 350 mV）与 FRL 均衡后的眼（裸眼 0 mV），TMDS 裸眼直接扣 TMDS 模板、FRL 要先过参考接收器 CTLE 9 dB 再扣，外加抖动 / 上升沿 / 电平，一句话「Source 端两套模板，别扣错」。② Sink / Rx 压力测试：中间是一只真挤出来的压力眼，170 mV × 0.40 UI、眼宽已贴住判据线；BERT 造最坏压力眼灌进 DUT，抖动 + 损耗 + ISI 一起加到规范量，测抖动容限 / 接收灵敏度 / PLL 跟踪，判据不看画面而是读 SCDC 的 CED（与 USB 3.x Rx 同哲学，见第 38 篇）。③ Cable / Channel：真算出来的插损 vs 线长曲线，三色图例 Ultra 认证线 / Premium / 没认证，4 米处一条虚线各点一个点，越长越陡、等级差的线更陡。底部：TMDS 时看老眼图、FRL 时看新眼图——Source 端两套眼图模板，这是 HDMI 跨两套架构最直接的体现](/images/40/ill06_test3.png)

## 五、怎么测：两张台子——源端一张、宿端一张

HDMI 的前两类测试，**台子是两张、长得完全不一样**。共同前提有两条（沿用第 35 篇的"测试点 + 夹具 + 一致性软件"套路）：

1. **测试点必须在规范定死的夹具参考面上**：DUT 的 HDMI 口通过标准测试夹具（fixture / TPA）引出到示波器 / BERT。
2. **边带 DDC / SCDC 先把 DUT 喊进测试模式、定到你要测的那一档**：Source 测试要它输出规定图案；FRL 测试还要**先把链路 link training 到目标档**（要测 FRL6，就得先训到 48G）。

### 5.1 源端台面（Source / Tx）

![图 Setup-1：HDMI 源端一致性测试台面。主机跑一致性软件（选版本、选这次要测的 FRL 档），被测 Source 的 HDMI 口经 TPA 测试夹具同轴引到实时示波器；旁挂 DDC / SCDC 边带控制盒，负责把 DUT 喊进 compliance mode 并把链路定到目标档。软件处理链横排流程条：去嵌测试夹具 → 叠加规范参考通道 → 分叉（TMDS 走上支路裸眼直接扣模板；FRL 走下支路先过 golden PLL 与参考接收器 CTLE 9 dB 再扣模板）→ 出 pass/fail。仪器屏内是本篇同源仿真出来的真眼。底部参数条列速率、UI、判据、参考均衡档位；四张坑位卡：夹具没去嵌会把眼量小一圈冤枉 DUT、测 FRL 却扣了 TMDS 模板（或反过来）、以为在最高档实际已悄悄掉档、先确认训在哪一档再开示波器](/images/40/fig_setup_src.png)

处理链里**最关键的是那个分叉**：同一台示波器、同一套软件，TMDS 走上支路裸眼直接扣模板，FRL 走下支路先过 golden PLL 和参考接收器 CTLE 再扣模板。三个最常见的坑：**夹具没去嵌**（眼被量小一圈，冤枉 DUT）、**模板扣错**（拿 TMDS 模板去扣 FRL，或反过来）、**以为在最高档、实际已经掉了档**。

所以源端测试的第一件事**永远不是开示波器**，而是先确认这个口现在训在哪一档、跑的是 TMDS 还是 FRL——这一步靠边带读回来，几秒钟的事，却决定了后面该扣哪套模板。顺序反了，后面量的每一个数都白量。

这里有条**铁律**：压力眼必须**先在校准参考面上校准好**，才能接被测设备。你要注入的抖动量、损耗量、眼张开多少，全都是规范写死的目标值，得先用示波器一项一项量到位。校不准，后面测出来的 pass / fail 都没有意义。

判据也和 USB 那边不一样：HDMI **不用 loopback**，而是读 SCDC 里的 **CED 计数器**，逐 lane 统计字符错误，压满一段时间不涨才算过——用数字判据代替肉眼看画面，这一点和第 38 篇 USB 3.x 的 Rx jitter tolerance 是同一套哲学。

## 六、⚙️ 关键仪器设置：把模块三的 SI 概念落到旋钮上

HDMI 的一致性软件里那些选项，全是前面模块三讲过的 SI 概念，这里只做映射、不复述原理：

- **去嵌 De-embed（见第 33 篇）**：把测试夹具 / 线缆的影响从测量里扣掉，还原 DUT 真实输出。
- **嵌入 Embed / 参考线缆模型**：有些项要在 DUT 输出上"叠加"一段标准信道 / 最坏线缆，模拟真实到达接收端的样子。
- **参考接收器均衡 CTLE / DFE（见第 34 篇）**：**FRL 测试**里，眼图往往要经过规范规定的参考均衡器再判——因为真实 Sink 就带均衡。这是 FRL 比 TMDS 明显"重"的地方，上面那张动图 2 已经把它跑给你看了：不过均衡，这根 4 米认证线的 FRL6 眼根本睁不开。
- **时钟恢复 golden PLL（见第 32 篇）**：FRL 是嵌入式时钟，眼图的时间基准来自按规范设定的时钟恢复环路（TMDS 则可用转发的那条时钟做参考）。
- **⚠️ TMDS 高速档要确认 Clock Ratio**：测 HDMI 2.0 的 6 Gbps/ch 时，时钟通道上是**像素时钟的 1/4**（Bit Clock Ratio = 1/40），拿它做参考时钟要按 SCDC 里的实际设置来换算，别当成 1/10 那套；同时确认**加扰是否已启用**——加扰状态不同，眼图的码型统计和 EMI 表现都不一样。
- **带宽 ≥ 关注谐波 / 按规范档（见第 29 篇、速查 02）**：示波器带宽按规范要求选；注意**别把"上升时间 5 倍谐波"那条时域规则，硬套到串行眼图的速率上**（详见速查 02——40G 级信号并不需要 200G 示波器）。
- **抖动分离 + eye mask（见第 31、32 篇）**：分离随机 / 确定抖动、加载眼图模板判 pass/fail。

## 七、判据从哪来：眼图模板 / 抖动预算不是拍脑袋

和第 35 篇一脉相承：HDMI 那些**眼图模板的开口大小、抖动限值、去加重档位**，不是随手画的，而是从**信道损耗模型 + 抖动预算**反推出来的——规范组织假定了最坏的线缆 / 板子损耗、最坏的接收端能力，倒推出"发送端至少要睁多大的眼、抖动不能超多少"，才能保证任意合规的 Source + Cable + Sink 组合都能通。所以你眼图擦到模板边缘 fail，本质是"留给线缆和接收端的余量不够了"。这套推导逻辑，第 35 篇讲过，这里直接引用。

FRL 相比 TMDS，判据里多了均衡后判定、link training 结果等——因为它是嵌入式时钟链路，天然继承了 USB3/PCIe 那套更复杂的接收机模型。

> ⚠️ **关于本篇图上的判据数值**：HDMI 的眼图模板具体数值需要 **HDMI Forum 会员资格**才拿得到，不像 USB 3.1 Gen2 的 70 mV × 0.30 UI 是公开值。所以本篇所有图上的判据都标了 **「教学判据」**，取的是业界常引用的量级（TMDS 150 mV × 0.60 UI，FRL 均衡后 100 mV × 0.40 UI），用来说明**判定是怎么翻转的**。真做项目，请以对应版本的 **CTS** 为准。三张动图里的物理模型（线材损耗、ISI、CTLE、抖动）是真实仿真，翻转趋势和量级关系成立；绝对数值请勿直接引用到报告里。

## 八、常见翻车与调试：黑屏 / 花屏 / 掉分辨率 / 训练失败，怎么分层揪

HDMI 翻车最忌讳"一上来就怀疑信号质量"。正确姿势是**分层**，和第 39 篇"先看协议层、再看电气层"一个思路：

- **协商层（先看这里）**：**HPD 有没有稳稳拉高**、读 EDID 对不对、DDC/SCDC 通不通、HDCP 握手成没成、FRL link training 训到了第几档、DSC 有没有协商上。**很多"黑屏 / 掉到 4K30 / 忽好忽坏"死在这一层，跟信号眼图无关。**
- **链路 / 电气层**：如果协商 OK 却花屏 / 雪花 / 闪断，再去量眼图、看是不是线材不够级（掉不到目标 FRL 档）、走线 skew、去加重不够、接收端均衡吃不下。
- **内容保护层**：纯黑屏但灯亮、能识别设备，优先怀疑 **HDCP 握手失败**，别跟信号完整性混。

对号入座几个高频现象：

| 现象 | 最可能的层 | 常见根因 |
|---|---|---|
| 一插就黑屏、灯亮能识别 | 内容保护 / 协商 | HDCP 握手失败 / EDID 读失败 |
| 掉到 4K30、颜色发暗 | 协商 | FRL 训不上（线材不够级）→回落 TMDS/低档 |
| 花屏、雪花、间歇闪断 | 电气 | 眼图擦模板 / 线损大 / skew / 均衡不足 |
| 忽好忽坏、插拔才好 | 边带 / 协商 | **HPD 抖动或时序不对**、DDC/SCDC 不稳、EDID 缓存脏 |
| 高刷开不了、只有低刷 | 协商 | Sink 不支持该 FRL 档 / EDID 没报该模式 / **DSC 没协商上** |

![图8：HDMI 常见翻车 → 分层揪真凶（别一上来就赖信号）。左侧自上而下三张卡：① 协商层（先看）——EDID / DDC / SCDC 通不通、HDCP 握没握上、FRL link training 训到第几档，黑屏 / 掉 4K30 / 忽好忽坏多死在这；② 电气 / 链路层——协商 OK 却花屏雪花闪断：眼图擦模板、线损大、lane 间 skew、均衡不足、线材等级不够；③ 内容保护层——纯黑屏但灯亮、能识别设备，优先怀疑 HDCP 握手失败，别跟信号质量混为一谈。右侧「现象 → 指向哪一层」五行横贯底纹对照表：黑屏灯亮能识别 → 内容保护 / 协商（HDCP、EDID）；掉到 4K30 颜色发暗 → 协商（FRL 训不上 → 回落）；花屏雪花闪断 → 电气（眼图 / 线损 / skew）；忽好忽坏插拔一下才好 → 边带（DDC / SCDC 不稳）；开不了高刷新率 → 协商（Sink 不支持 / EDID 没报）。右下口诀卡：① 先查协商（训在第几档、EDID 报了什么）② 再量电气（眼图、线损、skew、均衡）③ 最后才分 HDCP——它跟信号无关](/images/40/ill08_debug.png)

## 九、一句话总结

**HDMI 一个接口，把"转发时钟"和"嵌入式时钟"两套架构走了个来回：老的 TMDS（3 数据 + 1 时钟、8b/10b、≤18G）转发时钟但数据通道照样扣眼图模板；HDMI 2.1 的 FRL（4 lane、埋时钟靠 CDR、16b/18b、最高 48G）跨进了 USB3/PCIe 那个嵌入式时钟世界，眼图前要过参考均衡、上码型还得先 link training。测什么依旧是 Tx 眼图 / Rx 压力 / Cable 通道三类；调试永远先分层——协商训练在哪档、电气眼图睁没睁开、HDCP 握没握上，别混为一谈。**

![图9：HDMI·工程师速查一图。六张卡片两行排布——主角：视频 + 音频 + 控制，单向 Source → Sink，边带 DDC / SCDC 决定能不能协商到高规格；TMDS（≤ 2.0）：3 数据 + 1 时钟、8b/10b、转发时钟、≤ 18G（6 G/ch），转发时钟也照样扣眼图；FRL（2.1）：4 lane、嵌入式时钟 + CDR、16b/18b、9~48G，先 link training 再跑，训不上就掉档 / 回落 TMDS；版本 / 线材：1.4 = 10.2G、2.0 = 18G、2.1 FRL = 48G，Premium(18G) / Ultra High Speed(48G)，线材等级 = 每米损耗的倍数；测什么·三类：Tx 眼图（TMDS / FRL 两套模板）、Rx 压力眼与抖动容限（判据读 SCDC 的 CED）、Cable 衰减 / skew / 回损；调试分层：协商（EDID / SCDC / HDCP / FRL 档）→ 电气（眼图 / skew / 均衡）→ 内容保护（HDCP），顺序反了就会白查一天。底部延伸阅读：第 35 篇一致性测试总览 · 速查 02 串行接口全景地图 · 第 31、32 篇眼图与抖动 · 第 34 篇均衡 · 第 38 篇 USB 3.x 接收端压力测试](/images/40/ill09_quickref.png)

| 项 | 要点 |
|---|---|
| HDMI 是什么 | 视频 + 音频 + 控制打包、单向 Source→Sink 的显示接口；另带低速边带：**DDC**（读 EDID）/ **SCDC**（报状态、切 Clock Ratio 与加扰、FRL 训练握手、读 CED）/ **HPD**（在位与 EDID 就绪，"插拔才好"的常见元凶）/ **CEC**（单线控制总线，管遥控联动） |
| 两套传输机制 | **TMDS**（HDMI 1.x/2.0）：3 数据通道 + 1 独立时钟、8b/10b、转发时钟；**FRL**（HDMI 2.1）：4 lane 全数据、嵌入式时钟靠 CDR、16b/18b |
| 时钟架构（见速查 02） | TMDS=转发时钟（省接收端 CDR，但数据通道仍高速串行、仍扣眼图）；FRL=嵌入式时钟 + CDR（跨到 USB3/PCIe/DP 那一类） |
| 版本速率 | HDMI 1.4≈10.2 Gbps（3.4G/ch）；HDMI 2.0=18 Gbps（6G/ch）；HDMI 2.1 FRL 最高 48 Gbps |
| ⚠️ TMDS Clock Ratio | 字符率 >3.4 Gbps/ch 时 **Bit Clock Ratio = 1/40**（时钟线上是像素时钟的 1/4，测 6G/ch 时量到 150 MHz 而非 600 MHz），且**强制加扰 scrambling**，两者都由 SCDC 控制——这正是 SCDC 在 HDMI 2.0 被引入的原因；加扰没开或两端不一致 = 花屏 |
| FRL 速率阶梯 | FRL1 3lane×3G=9G｜FRL2 3×6G=18G｜FRL3 4×6G=24G｜FRL4 4×8G=32G｜FRL5 4×10G=40G｜FRL6 4×12G=48G。**FRL2 与 FRL3 每 lane 都是 6G，对眼图测试是同一道坎**（差别只在 lane 数），所以掉档链上它俩合并 |
| DSC | Display Stream Compression（HDMI 2.1，视觉无损压缩）。**48G 装不下 8K60 RGB 8bit**（净 47.8 Gbps，过 16b/18b 编码需 ~53.8 Gbps 链路），必须靠 DSC 或 4:2:0。DSC 让低档 FRL 也能顶高画质——排障"高刷开不了"时，除了查 FRL 档也要查 DSC 有没有协商上 |
| link training | FRL 传输前 Source 从目标档**往低试**（不是从低往高爬），训不上就降一档；结果走 SCDC；一路降到底还不行就退回 TMDS |
| 线材等级 | 18G→Premium High Speed；48G FRL→Ultra High Speed（须带认证标）。"换根线又好了"多半是线材不够级。同样 4 m @6 GHz 插损：Ultra 12.3 dB / Premium 16.0 dB / 没认证 20.4 dB |
| 掉档链（本篇动图 3） | 插损 7 dB→FRL6 48G｜12.9→FRL5 40G｜16.1→FRL4 32G｜18.8→FRL3 24G｜22.0→FRL1 9G｜28.4 之后回落 TMDS。用户看到的不是黑屏，是画质悄悄缩水 |
| 测什么·三类（见第 35 篇） | ①Source/Tx：数据通道眼图，TMDS 裸眼扣 TMDS 模板、FRL 先过参考接收器 CTLE 再扣 FRL 模板（+抖动/上升沿/电平）②Sink/Rx：BERT 造压力眼测抖动容限/接收灵敏度/PLL 跟踪，判据读 SCDC 的 CED（见第 38 篇 Rx jitter tolerance）③Cable：衰减/skew/回损/串扰（Ultra High Speed 认证核心） |
| 关键仪器设置 | 去嵌见第 33 篇 · 嵌入参考线缆 · 参考均衡 CTLE/DFE 见第 34 篇（FRL 必用）· 时钟恢复 golden PLL 见第 32 篇 · 带宽按规范档见第 29 篇 · 抖动分离 + eye mask 见第 31、32 篇 |
| 带宽误区（见速查 02） | 眼图带宽≈0.7×~1×波特率，别把"上升时间 5 倍谐波"套到串行速率上——48G 级不需要 200G 示波器 |
| 判据从哪来 | 眼图模板 / 抖动限值从信道损耗 + 抖动预算反推（见第 35 篇），不是拍脑袋；FRL 判据含参考均衡后判定 + 训练结果。⚠️ HDMI 模板具体数值需 HDMI Forum 会员资格，本篇图上一律标「教学判据」，实际以对应版本 CTS 为准 |
| 调试分层 | 先协商层（EDID/DDC/SCDC/HDCP/FRL 训到第几档）→ 再电气层（眼图/skew/均衡/线材级别）→ 分清内容保护层（HDCP 握手）；别一上来就赖信号 |
| 现象速查 | 黑屏灯亮=HDCP/EDID；掉 4K30 颜色暗=FRL 训不上回落；花屏雪花闪断=眼图/线损/skew（HDMI 2.0 下还要查加扰）；忽好忽坏插拔才好=HPD/DDC/SCDC 不稳；开不了高刷=Sink 不支持该 FRL 档 / EDID 没报 / DSC 没协商上 |
| 本篇不展开 | **ARC / eARC**（音频回传，eARC 借用 HPD 与 Utility 引脚，有独立的一致性测试）与 **CEC** 一致性——都属边带功能测试，与高速通道电气一致性是两条线 |
| 标准出处 | HDMI 2.1 Specification & CTS（HDMI Forum）；HDMI 1.x/2.0 CTS（HDMI Licensing Administrator）；Ultra High Speed HDMI Cable Certification |
