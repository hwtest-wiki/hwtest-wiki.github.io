# 同一块 Gen5 SSD，为什么这个槽跑满、那个槽会回退？

<div class="article-meta"><span class="badge">📘 模块六 · 高速接口一致性测试 · PCIe</span><span class="badge">⏱ 约 28 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


同一块 Gen5 SSD，插在 CPU 直连的 M.2 槽里可以跑满；换到另一个外形完全相同的 M.2 槽，系统却只协商到 Gen4。另一块 x16 网卡插进全长插槽，软件里又只显示 x4。

设备能识别、驱动也正常，为什么速率和宽度就是不对？

很多人第一反应是“SSD 体质差”或者“主板信号不好”。但 PCIe 最麻烦的地方，恰恰是**同一个掉速现象，可以由平台拓扑、lane 分配、连接器接触、通道损耗、参考时钟、均衡训练、供电、复位和固件共同造成。**

所以，PCIe 一致性测试的目标不是拍一张漂亮眼图，而是回答三个独立问题：

- 发送端发出来的信号合不合格？
- 接收端面对按适用规范校准的压力信号，能不能正确接收？
- 中间的封装、走线、过孔、连接器和插槽，是否仍在通道预算里？

![图1：同一设备在不同槽表现不同，是定位入口，不是根因结论。](/images/44/ill01_pain.png)

## 一、接口是什么、应用在哪里

PCIe，全称 PCI Express，是一种**点对点、分组传输、全双工的高速串行互连**。

“点对点”意味着一条 PCIe Link 连接两个端口，而不是像传统并行总线那样让一群设备同时挂在同一组线上。靠近处理器的一端通常叫 **Root Complex**；SSD、GPU、网卡和加速卡这些设备通常叫 **Endpoint**；需要扩展端口时，中间还可以经过 PCIe Switch。

一条 lane 不是一对线，而是两对差分线：

- 一对负责发送 Tx；
- 一对负责接收 Rx；
- 两个方向可以同时工作，因此是全双工。

x1、x4、x8、x16 表示一条 Link 由多少条 lane 组成。它说的是**宽度**；Gen3、Gen4、Gen5、Gen6 说的是每条 lane 的**代际和速率**。两者必须分开记录。

![图2：PCIe 的 Root Complex、Endpoint 与全双工 lane。](/images/44/ill02_link.png)

PCIe 的应用远不止桌面显卡：

| 应用 | 常见形态 | 现场最常见的问题 |
|---|---|---|
| NVMe SSD | M.2、U.2 / U.3、板载 | Gen 回退、x4 变 x2、压力下掉盘 |
| GPU / 加速卡 | CEM 插卡 | x16 变 x8/x4、训练失败、AER 错误 |
| 高速网卡 | x4/x8/x16 插卡 | 吞吐不足、单槽异常、热机误码 |
| 服务器背板 | Cable / Connector / Switch | 长通道损耗、Retimer 分段、互操作 |
| 嵌入式平台 | 板到板、板载 Endpoint | 复位时序、参考时钟、固件初始化 |

这里有一个特别容易踩的坑：**插槽有多长，不等于实际接了多少条 lane。**

一条外观是 x16 的插槽，电气上可能只连接 x8 或 x4；一个 M.2 槽也可能与 SATA、另一个 M.2、USB4 控制器或芯片组端口共享资源。看到“x16 外形”就默认“x16 电气”，是 PCIe 排障最常见的误判之一。

M.2 只是模块和连接器形态，不天然等于 PCIe。实际承载 PCIe、SATA 还是其他接口，以及支持多少条 lane，必须结合 Key、主机接口、平台原理图和产品规范确认。

## 二、传输原理和代际差异

### 2.1 数据线上没有单独时钟，但系统仍然有参考时钟

PCIe 的数据与时钟关系要拆成两层看。

第一层是高速数据。PCIe 数据线上没有额外的转发时钟，接收端通过 **CDR（Clock Data Recovery）** 从数据边沿恢复采样时钟。因此，PCIe 属于需要看串行眼图、抖动和接收容限的接口。

第二层是 **REFCLK**。常规 PCIe 平台中的 PHY / PLL 会使用参考时钟，但具体输入方式、SSC 分配和容差取决于代际、产品形态与器件实现。常见架构包括：

- **Common Clock**：两端使用同源参考时钟；
- **SRNS**：两端使用独立参考时钟，两边都不使用 SSC；
- **SRIS**：两端使用独立参考时钟，并分别使用扩频。

这三种架构不是简单的“一个好、两个差”，而是剩余频率误差、SSC 条件、CDR 跟踪能力和测试设置不同。测量软件里的 golden PLL、CDR 和 SSC 设置如果选错，仪器可能把本应跟踪的低频调制算成残余抖动。

![图3：Common Clock、SRNS、SRIS 的区别不在名字，而在两端参考时钟关系和接收端必须承受的误差。](/images/44/ill03_clock.png)

### 2.2 Gen、GT/s、GB/s 不是同一个数字

| 代际 | 线速率 | 信令与编码 | 关键变化 |
|---|---:|---|---|
| Gen1 | 2.5 GT/s | NRZ、8b/10b | PCIe 串行化起点 |
| Gen2 | 5 GT/s | NRZ、8b/10b | 速率翻倍 |
| Gen3 | 8 GT/s | NRZ、128b/130b | 编码效率大幅提高 |
| Gen4 | 16 GT/s | NRZ、128b/130b | 通道损耗与均衡压力明显增加 |
| Gen5 | 32 GT/s | NRZ、128b/130b | 单 lane 单向接近 4 GB/s |
| Gen6 | 64 GT/s | PAM4、FLIT、FEC | 四电平、固定流控单元与前向纠错 |

以 Gen5 为例：

**32 GT/s × 128 ÷ 130 ÷ 8 ≈ 3.94 GB/s**

这是每条 lane、单方向、扣除 128b/130b 编码后的理论值，还没有继续扣除 TLP、DLLP、流控和软件栈开销。x4 Gen5 的应用实测不可能简单等于“32 × 4”。

Gen6 又多了一层变化：它使用 PAM4。PAM4 每个符号有四个电平，可以携带两个 bit，因此 64 GT/s 对应的符号率仍是 32 Gbaud。与此同时，Gen6 引入 FLIT 和低延迟 FEC。若 DUT、测试工具和测试计划提供相应观测点，报告必须写清观察的是 FEC 前物理质量、FEC 后错误，还是应用层吞吐，不能把三个口径混成一句“没有报错”。

![图4：代际、编码、GT/s 与应用吞吐不是同一层数字。](/images/44/ill04_gens.png)

### 2.3 链路怎样从上电走到正常传输

设备上电后，PCIe 并不是直接进入最高速率。链路由 LTSSM 驱动，通常先完成 Detect、Polling 和 Configuration，建立基础速率下的可工作 Link 与宽度；当双方尝试切换到 Gen3 及以上目标速率时，还会经过 Recovery 中的速率切换和链路均衡。最终 Gen 与 xN 同时受双方能力、平台策略、固件限速和中间 Retimer 等条件影响。

协议均衡过程主要围绕 Tx preset 或发送系数的请求、评估与响应展开。接收器可以在本地采用 CTLE、DFE 等实现恢复信号，但这些内部结构并非所有 DUT 都必须相同，也不等于协议训练会直接配置接收器内部的 CTLE / DFE。

训练成功只说明：**这一对设备在当前温度、电压、通道和设置下找到了工作点。**

它不等于：

- 发送端所有合规项目都通过；
- 接收端容限已经通过；
- Channel 一定满足规范；
- 全温、全压、全批次都有足够余量。

![图5：LTSSM 和均衡训练负责找到当前工作点，但不能替代 Tx、Rx 与 Channel 合规测试。](/images/44/ill05_training.png)

## 三、正确使用与设计注意事项

### 3.1 先看拓扑，再看眼图

同一个设备换槽掉速，第一件事不是接示波器，而是查平台 Block Diagram 和 lane 分配表。

需要确认：

- 这个槽是 CPU 直连，还是经过芯片组或 PCIe Switch；
- 是否与另一个 M.2、SATA、USB4 或板载控制器共享 lane；
- x16 是否被 bifurcation 成 x8+x8 或 x4+x4+x4+x4；
- BIOS 是否真正支持并启用了目标拆分方式；
- 插槽外形宽度和电气宽度是否一致；
- 目标设备本身支持的最高 Gen 与 xN 是多少。

如果平台只给这个槽分配了 x4，那么信号再漂亮也不会变成 x16。

![图6：插槽外形、平台拓扑与实际电气宽度必须分开确认。](/images/44/ill06_topology.png)

### 3.2 PCIe 不是“所有线全部严格等长”的并行总线

每条接收 lane 通常都有独立的时钟恢复，接收端还会处理 lane 间 deskew。因此 PCIe 的布线重点不是把十六条 lane 修到像 DDR 数据线一样完全等长。

真正要优先控制的是：

- 每对差分线内部的 skew；
- 目标频段内的插损、回损和串扰；
- 过孔残桩与连接器不连续；
- 参考平面连续性；
- AC 耦合电容及其焊盘过渡；
- lane 间偏斜是否仍在适用规范的 deskew 能力内。

高代际下，少一个过孔、缩短一段走线、优化一个连接器过渡，常常比盲目追求所有 lane 完全等长更有价值。

![图7：封装、FR4、过孔、连接器和插槽共同组成 PCIe 通道。](/images/44/ill07_channel.png)

![动图1：连续增加目标 Gen5 的等效通道插损，用真实眼图指标观察余量从充足走向不足；教学判据不是 PCI-SIG 正式限值。](/images/44/anim01_channel.gif)

### 3.3 preset 不是“越大越强”

Tx FFE 会预先改变发送波形，用来补偿通道的高频损失。补偿太少，高频成分到不了接收端；补偿过头，过冲、振铃和噪声也会增加。实际 PCIe preset 是离散的系数组合，不是可以任意连续转动的 dB 旋钮；下方动图连续扫描的是**等效 FFE 补偿强度**，只用于解释欠补偿、工作窗口和过补偿的趋势。

所以正确动作是：

1. 先确认当前训练选择了什么；
2. 再扫描适用 preset 或系数；
3. 同时看 Tx 波形、接收端余量和训练日志；
4. 找到可重复的工作窗口，而不是挑一张最漂亮的截图。

![图8：等效 FFE 补偿存在欠补偿、合适和过补偿三个区域，不是数值越大越好；图中眼图为教学模型，不是 PCI-SIG 正式限值。](/images/44/ill08_eq.png)

![动图2：在固定教学通道中连续扫描等效 FFE 强度，眼图真实指标经历 FAIL、PASS、再回到 FAIL。](/images/44/anim02_preset.gif)

### 3.4 别漏掉 REFCLK、PERST#、CLKREQ# 和电源

PCIe 看起来是高速串行接口，但很多“偶发训不上”并不发生在高速数据线上。

- REFCLK 没稳定，PHY 无法正确工作；
- PERST# 释放时机不对，Endpoint 可能错过初始化窗口；
- CLKREQ# 与低功耗策略不匹配，可能造成恢复异常；
- 插卡瞬态电流或供电噪声过大，会把训练问题伪装成信号完整性问题；
- 连接器接触和机械应力，也可能只伤到某一条 lane。

因此，设计评审不能只审高速差分线，还要把时钟、复位、低功耗控制和电源完整性一起审。

### 3.5 Redriver 和 Retimer 不是同一种器件

Redriver 主要在模拟域补偿损耗；Retimer 会恢复时钟和数据，再重新发送，相当于把长链路拆成两个新的电气段。

它们都不是“加上就一定能跑高代”的万能药：

- Redriver 可能补过头，也可能放大噪声；
- Retimer 的两侧都要满足各自电气要求；
- Retimer 还会参与链路行为和固件配置；
- 器件位置、供电、参考时钟和配置错误，都会制造新的问题。

## 四、一致性测试测什么

PCIe 一致性测试首先要把**测试对象**分开。

| 测试对象 | 核心问题 | 主要输出 | 不能替代 |
|---|---|---|---|
| Tx 发送端 | DUT 发出的信号是否满足规定电气要求 | 每个 lane / preset 的波形、抖动及合规结果 | 不能证明 Rx 容限 |
| Rx 接收端 | DUT 面对按适用规范校准的压力信号还能否可靠接收 | BER、错误计数、容限或规定测试结果 | 不能证明 Tx 合规 |
| Channel 通道 | 封装、PCB、过孔、连接器和插槽是否仍在预算内 | S 参数、插损、回损、串扰、模式转换 | 不能证明协议互操作 |
| REFCLK | 参考时钟是否满足适用条件 | 频率、抖动、SSC及相关项目 | 不能替代数据链路测试 |
| 协议 / 互操作 | LTSSM、训练、错误和系统组合是否正确 | 日志、AER、Recovery、重放与吞吐 | 不能替代物理层合规 |

![图9：Tx、Rx、Channel、REFCLK 和协议日志回答的是不同问题，五类证据不能互相替代。](/images/44/ill09_test_objects.png)

还要先明确 DUT 是什么：

- 测主板 Root Port；
- 测 Add-in Card；
- 测 M.2 SSD；
- 测 Switch；
- 测 Retimer 两侧；
- 还是测一段独立 PCB Channel。

DUT 形态一变，测试点、夹具、参考面和适用规范都会变。不能拿 CEM 插卡的台面，直接套到板载 M.2 设备上。

## 五、Tx、Rx、Channel 分别怎么测

### 5.1 Tx：让 DUT 发规定码型，再在规定参考面分析

发送端测试的基本流程是：

1. 用合规工具、测试卡或平台命令，让 DUT 进入目标代际的测试状态；
2. 选择目标 lane、方向和适用 preset / 系数；
3. 通过对应夹具把高速信号引到示波器；
4. 将夹具影响按适用方法去嵌到规定参考面；
5. 使用对应版本的分析软件、参考接收器和 CDR 计算结果；
6. 保存原始波形、设置文件和每个 lane 的报告。

![图10：Tx 测试不是在正常业务流量里随便截一段，而是进入规定状态、规定码型和规定参考面。](/images/44/fig_setup_tx.png)

常见错误有四个：

- 只测链路自动选中的“最好 preset”；
- 只测 lane 0，不测其他 lane；
- 夹具换了，却继续使用旧去嵌文件；
- 正常跑业务时抓一段波形，就当成 Tx 合规结果。

### 5.2 Rx：先校准压力眼，再考 DUT

接收端测试不是看 DUT 自己发出的眼图，而是由 BERT 或合规测试设备生成并校准一个**满足适用测试方法规定的压力信号**，送到 DUT 接收端。“压力信号”不等于可以脱离具体 CTS 和产品形态自行定义一个所谓最差眼图。

基本流程是：

1. 不接 DUT，先在规定参考面校准压力信号；
2. 按适用方法加入通道损耗、抖动、噪声和其他规定压力；
3. 接入 DUT，让它进入适用接收测试或环回状态；
4. 确认实际运行在目标 Gen、lane 和时钟架构；
5. 运行规定的码型、bit 数或时间；
6. 记录 BER、错误计数、Recovery 和掉链事件。

![图11：Rx 台面先校准压力源，再接 DUT；协议日志只负责关联事件，不能代替接收容限。](/images/44/fig_setup_rx.png)

Tx 通过不能推出 Rx 通过。一颗芯片可以“发得很好、收得很差”，也可以反过来。

### 5.3 Channel：VNA看频域，TDR找位置

单条差分 lane 的插损、回损和模式转换，通常使用四端口 VNA 或等效多端口配置，先测得单端 S 参数，再按端口定义转换为混合模 S 参数。若要完整表征相邻差分 lane 的近端 / 远端串扰，还要把激励对和受扰对两端都纳入测量，通常需要更多端口、开关矩阵或受控重接，不能把单条 lane 的四端口台面当成完整串扰台面。

- 插损回答高频能量被吃掉多少；
- 回损回答阻抗不连续造成多少反射；
- 串扰回答相邻通道耦合有多强，但必须同时写清激励对、受扰对、近端 / 远端和端口终端；
- 模式转换回答在指定端口方向和频段内，差模与共模之间的转换有多强。

测量时必须明确：

- 通道从哪里开始、到哪里结束；
- 封装是否包含在内；
- 使用哪套夹具；
- 校准面和最终参考面在哪里；
- 去嵌或嵌入了什么模型；
- 测的是 CEM 插槽、M.2，还是自定义板级路径。

TDR 更适合 Debug：在传播速度、参考面和空间分辨率设置正确时，它能把时延换算成距离，帮助定位过孔、连接器、焊盘或断点。但 TDR 曲线“看起来平”不能替代完整 Channel 合规判定。

![图12：单条差分 lane 的四端口 Channel 台面；若测相邻 lane 串扰，还需扩展端口或开关矩阵。](/images/44/fig_setup_channel.png)

## 六、测试环境和仪器怎么搭

### 6.1 先按产品形态选夹具

PCIe 测试最先决定的不是示波器型号，而是 DUT 形态和对应夹具。

| DUT | 常见台面思路 | 重点 |
|---|---|---|
| 主板 / Root Port | 对应负载板或测试卡引出信号 | 槽位、lane映射、平台资源 |
| Add-in Card | 对应基板或合规夹具连接卡端 | 卡边参考面、供电与复位 |
| M.2 SSD | M.2专用夹具或interposer | x4 lane、连接器加载、尺寸形态 |
| 独立Channel | VNA + 两端夹具 | S参数、参考面、去嵌 |
| 系统互操作 | Root Complex + Endpoint + 协议分析/日志 | LTSSM、AER、Recovery和业务负载 |

PCI-SIG 的 CEM 产品、M.2 产品和板载器件，参考面并不相同。夹具名称相似，也不能默认可以互换。

### 6.2 三套电气台面

**Tx 台面：**

`DUT Tx → 合规夹具 → 高频同轴线 → 示波器 / 合规分析软件`

**Rx 台面：**

`BERT / 压力源 → 校准通道与夹具 → DUT Rx → 错误检测 / 环回 / 日志`

**Channel 台面：**

`VNA → 夹具A → 被测通道 → 夹具B → VNA`

协议分析仪、LTSSM 日志、AER 计数和系统压力工具是旁证台面。它们能告诉你错误发生在什么时候，却不能替代示波器、BERT 或 VNA 的正式结果。

### 6.3 环境条件必须固定

同一个 DUT 在实验室台面和整机内的表现可能不同。每轮测试至少固定：

- BIOS、固件和驱动版本；
- 目标 Gen、xN、lane 和 preset；
- 参考时钟架构与 SSC；
- 夹具、线缆、探头和去嵌文件版本；
- 电压、温度、风扇和业务负载；
- 插槽、插接次数和机械固定方式。

不固定这些条件，今天和明天的两份“同项目报告”可能根本不可比。

## 七、仪器关键设置

仪器自动测试软件能减少手工计算，但它不会自动替你选对测试对象。

| 设置 | 必须确认什么 | 选错后的典型后果 |
|---|---|---|
| 目标代际 | Gen3/4/5/6及对应测试方法 | 用错模板或分析模型 |
| lane / 方向 | 实际物理lane与Tx/Rx方向 | 测到错误通道 |
| preset / 系数 | 当前测试项目要求覆盖哪些档 | 只留下最好看的波形 |
| 测试码型 / 状态 | DUT确实进入规定状态 | 普通业务波形被误当合规波形 |
| 参考面 | 结果要归一到哪里 | 夹具损耗被算进DUT |
| 去嵌 / 嵌入 | 文件、端口和方向是否匹配 | 波形被“修好”或“修坏” |
| CDR / golden PLL | 与代际、时钟架构和SSC匹配 | 跟踪错误，抖动结果失真 |
| 示波器带宽 / 采样 | 按适用测试方法和工具配置 | 过度滤波或噪声放大 |
| Rx压力校准 | 在规定参考面校准并保存证据 | DUT被考得过轻或过重 |
| BER窗口 | bit数、时间、错误口径 | 不同报告无法比较 |
| VNA校准 | 端口映射、频率范围、混合模式、终端与夹具 | S参数方向、串扰口径或参考面错误 |

不要套“示波器带宽等于波特率多少倍”的万能口诀。PCIe 合规分析会涉及规定的带宽限制、参考接收器、CDR 和夹具处理，正确设置应来自适用规范、合规软件说明和实验室受控流程。

Gen6 还要额外确认：

- PAM4 四个电平和三只眼是否被正确识别；
- DUT、工具和测试计划是否提供所需的 FEC 前 / 后观测点；
- 当前测量与错误统计处于 FEC 前还是 FEC 后；
- FLIT / FEC 相关工具和版本是否匹配；
- 不能拿 Gen5 NRZ 单眼模板直接判 Gen6。

## 八、判据和标准从哪里来

PCIe 判据不是从网上找一张眼图模板，也不是从某块“Golden板”抄一个数。

正式依据通常分成几层：

| 文档层级 | 回答什么问题 |
|---|---|
| PCI Express Base Specification | 协议、链路训练、基础电气与架构要求 |
| PCI Express Card Electromechanical（CEM）Specification | 插卡、插槽、连接器和对应形态要求 |
| M.2等形态规范 | 特定连接器、尺寸和测试边界 |
| PCI-SIG适用Compliance Test Specification / Program | 合规项目、方法、夹具与认证流程 |
| 芯片手册与平台设计指南 | 器件能力、实现限制、推荐设置 |
| 仪器厂商应用资料 | 怎样把规范方法落到具体仪器 |

报告必须记录**规范名称、版本和适用产品形态**。只写“按 PCIe Gen5 标准测试”是不够的，因为同一代际仍可能涉及不同 DUT、不同测试点和不同文档。

公开文章无法替代会员规范、正式合规软件和认证实验室流程。因此本文不写受控的眼图、抖动、BER 或 Channel 限值；后续配图里的数字如果用于演示，只能明确标成教学值。

PCI-SIG 的 Compliance Program 还涉及互操作与合规活动。进入 Integrators List 或通过某次 Workshop，不等于任意平台、任意固件和任意环境都不会出问题；它证明的是规定范围内的结果。

![图14：正式判据必须沿规范、产品形态、测试计划和受控工具逐层追溯。](/images/44/ill11_standards.png)

## 九、报告怎么看

### 9.1 先确认这份报告是否有效

看到 PASS 或 FAIL 前，先检查：

- DUT、端口、固件和样品编号是否正确；
- 实际测试的是哪个 Gen、lane、方向和 preset；
- DUT 是否真正进入规定测试状态；
- 规范和合规软件版本是否匹配；
- 夹具、去嵌文件和校准是否有效；
- REFCLK 架构、SSC 和 CDR 设置是否正确；
- Rx 压力眼是否在规定参考面完成校准。

这些条件不成立，报告应标成**测试无效**，而不是 DUT FAIL。

### 9.2 PASS不等于余量充足

一条 x16 Link 有很多 lane、两个方向和多个测试项目。总结果显示 PASS，只代表被覆盖的项目没有越过规定边界。

仍要看：

- 哪条 lane 最差；
- 哪个方向最差；
- 哪个 preset 最差；
- 哪个项目最靠近限值；
- 温度和电压变化时趋势是否稳定；
- 不同样品和批次的离散度。

### 9.3 四类报告分别怎么看

| 报告 | 重点字段 | FAIL后第一步 |
|---|---|---|
| Tx | lane、方向、preset、测试项、margin、原始波形 | 复核模式、参考面、去嵌与时钟设置 |
| Rx | 压力校准、目标Gen、BER窗口、错误数、掉链事件 | 先确认压力眼有效，再看接收容限 |
| Channel | 端口、参考面、S参数文件、最差lane/频点 | 排除夹具，再用TDR定位不连续 |
| 协议/互操作 | Gen/xN、LTSSM、Recovery、AER、时间戳 | 与电气、时钟、供电事件对齐 |

### 9.4 报告结论应该怎样写

不合格的写法：

> Gen5 眼图通过，链路没有问题。

更可靠的写法：

> 在指定Root Port、目标Gen5、规定lane/方向/preset、对应夹具和参考面下，Tx规定项目通过；该结果只覆盖发送端，不替代Rx、Channel和系统互操作测试。最小margin出现在某lane的某项目，需纳入温度与批次复测。

结论写得越具体，下一位工程师越容易复测。

## 十、常见问题如何 Debug

PCIe Debug 最有效的顺序是：

1. **先读实际状态**：Gen、xN、LTSSM、Recovery、AER与错误时间；
2. **再查平台拓扑**：CPU直连、芯片组、Switch、lane共享和bifurcation；
3. **做单变量A/B**：Golden Endpoint、Golden槽位、换lane、换温度、换供电条件；
4. **按现象选测试对象**：Channel、Tx、Rx、REFCLK或协议；
5. **找到根因后再改**，不要边换器件边改BIOS；
6. **修复后回到原始Gen、宽度、温度和负载复测。**

### 10.1 现象到定位动作

| 现象 | 优先检查 | 下一步动作 |
|---|---|---|
| Gen5掉到Gen4，但宽度不变 | 双方能力、固件限速、Retimer、通道、均衡、REFCLK、供电 | 先确认能力与策略；再保存训练日志、测Channel并复核时钟 |
| x16变x8或x4 | 平台拓扑、bifurcation、lane接触或单lane异常 | 查Block Diagram；交换卡和槽；看错误是否固定lane |
| 只在某个槽失败 | 该槽走线、连接器、共享资源和固件配置 | Golden卡A/B；检查槽位电气宽度与通道 |
| 反复进入Recovery | 电气margin、时钟、均衡、供电扰动 | 对齐LTSSM时间戳与AER、REFCLK、电源波形 |
| 正确Gen/xN但压力下报错 | 边缘Channel、Rx容限、PI、温度 | 拉长测试；分lane；做Rx与Channel测试 |
| 冷启动失败、重启后正常 | PERST#、REFCLK、电源稳定与固件时序 | 同步抓复位、时钟、电源和LTSSM |
| 高温才回退 | 损耗、抖动、接收余量或供电漂移 | 固定温度阶梯，关联最差lane与训练参数 |
| 合规PASS但系统仍异常 | 协议、固件、电源管理或特定互操作组合 | 做协议分析和系统矩阵，不重复只抓眼图 |
| 系统能跑但合规FAIL | 真实业务没有覆盖规范最差条件 | 先确认测试有效，再修设计margin，不能以“能用”否定FAIL |

![图16：先按掉 Gen、掉宽度、Recovery、冷启动或高温等现象选择证据，不把所有异常都归咎于眼图。](/images/44/ill13_debug.png)

### 10.2 回到开头那块SSD

“CPU直连槽跑满、另一个槽回退”至少有四条分支：

**分支一：平台只给第二个槽分配Gen4或更少lane。**

这是设计与配置结果，不是信号质量故障。解决办法是调整平台资源、BIOS配置或更换正确槽位。

**分支二：第二个槽经过更长走线、更多过孔或连接器。**

训练日志可能显示高代均衡失败。下一步应测Channel，并对比Golden槽位的插损、回损和最差lane。

**分支三：只有某条lane接触不良。**

系统可能从x4回到x2。交换SSD、清洁连接器、检查机械固定，并确认异常是否始终跟着同一物理lane。

**分支四：REFCLK、复位或电源时序只在冷启动时异常。**

这时换一块SSD可能暂时恢复，但根因仍在平台。应同步抓REFCLK、PERST#、电源和LTSSM，而不是继续调FFE。

降到Gen4或x2只能作为临时绕过和诊断动作，不能作为“问题已解决”的证据。

## 十一、工程师速查

### 11.1 一致性测试最小矩阵

| 类别 | DUT状态 | 核心仪器 | 必留证据 |
|---|---|---|---|
| Tx | 目标Gen、lane、方向、preset、规定码型 | 示波器 + 合规软件 | 原始波形、设置、校准、报告 |
| Rx | 目标Gen、接收测试/环回状态 | BERT / 合规压力源 | 压力眼校准、BER窗口、错误与掉链 |
| Channel | 明确端点与参考面 | VNA，必要时TDR | Touchstone、夹具、去嵌、最差lane |
| REFCLK | Common/SRNS/SRIS与SSC状态 | 时钟测量设备 / 示波器 | 时钟架构、SSC、抖动与设置 |
| 协议 | 实际业务或受控训练场景 | 协议分析 / LTSSM / AER日志 | Gen/xN、状态、错误、时间戳 |

### 11.2 开测前Checklist

- ☐ DUT、端口、样品和固件版本正确；
- ☐ 目标Gen、xN、lane、方向和preset明确；
- ☐ 产品形态与规范版本匹配；
- ☐ 夹具、同轴线、探头和S参数文件编号一致；
- ☐ 校准有效，参考面和去嵌边界写清；
- ☐ REFCLK架构、SSC、CDR/golden PLL设置正确；
- ☐ Rx压力信号已在规定参考面校准；
- ☐ 温度、电压、负载和测试时间已记录；
- ☐ 原始波形、Touchstone和日志不会只剩截图。

### 11.3 报告最小字段

| 项目 | 必须写清 |
|---|---|
| DUT | 产品形态、样品编号、端口、固件/BIOS |
| 依据 | 规范名称、版本、测试项目与工具版本 |
| 状态 | Gen、xN、lane、方向、preset、码型 |
| 台面 | 仪器、夹具、线缆、参考面、校准、去嵌 |
| 环境 | 温度、电压、供电模式、负载与持续时间 |
| 结果 | 单项PASS/FAIL、margin、最差lane/方向/频点 |
| 证据 | 原始波形、S参数、压力校准、BER与协议日志 |
| 结论 | 覆盖范围、未覆盖项、复测条件与下一步 |

### 11.4 Debug口诀

> **先读Gen/xN → 查拓扑资源 → Golden A/B → 分Tx/Rx/Channel → 对齐时钟与日志 → 修复后回原条件。**

### 11.5 标准与资料入口

- PCI-SIG Specifications：确认PCI Express Base、CEM及产品形态相关规范；
- PCI-SIG Compliance Program：确认适用合规计划、测试活动与正式流程；
- 适用版本的PCI-SIG Compliance Test Specification；
- 芯片厂商Datasheet、Platform Design Guide与公开勘误；
- 示波器、BERT、VNA和合规软件厂商的对应代际应用资料；
- 正式判定以项目持有的受控规范、授权工具和认证实验室流程为准。
