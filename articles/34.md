# 均衡EQ怎么调：不是越强越好，怎样找到眼图和BER的最优点

<div class="article-meta"><span class="badge">📘 模块三 · 信号完整性 SI · 均衡 EQ</span><span class="badge">⏱ 约 23 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


一条16 GBd NRZ差分链路在实验室里出现了典型现象：

- 默认设置下，脉冲响应拖尾明显，判决裕量不足；
- 加大TX后游标和RX CTLE后，眼图先变好；
- 继续把均衡开到最大，噪声、振铃和发送端摆幅代价开始压缩裕量；
- 打开更多DFE抽头后，随机误码减少，但受扰动时出现更长的错误串。

这时最危险的处理方式是：

> 眼图还不够大，就把TX加重、CTLE和DFE全部开到最大。

均衡不是“越强越好”，也不是把信道频响机械恢复到0 dB。真正目标是：在发送摆幅、噪声、串扰、抖动、抽头数量、功耗和训练稳定性等约束下，让接收机在正确采样时刻获得最大的**判决裕量**。

本文使用一条**16 GBd NRZ合成教学链路**贯穿全文。所有波形、游标、参数热图和“裕量分数”均为教学模型，不是PCIe、USB、Ethernet或DDR的真实DUT数据，也不能替代任何接口的合规软件和规范限值。

![图1：同一条教学链路存在欠均衡、最优均衡和过均衡三个区域。均衡不足时残余ISI过大；均衡过强时噪声、振铃、发送摆幅和错误传播代价反而压缩裕量。](/images/34/ill01_case_v2.png)

读完本文，你应该能够：

1. 用游标解释均衡到底在消除什么；
2. 分清TX FFE、CTLE、RX FFE和DFE的作用及代价；
3. 正确理解pre-emphasis、de-emphasis和preshoot的边界；
4. 判断什么场景需要均衡，而不是套用固定速率门槛；
5. 按接口找到TX、Channel、RX和训练判据；
6. 设计一次可复现的均衡参数扫描；
7. 区分欠均衡、过均衡、训练失败和DFE错误传播；
8. 在原条件下完成整改复测，并证明最优点对PVT和批次仍然稳定。

## 一、均衡的目标：不是恢复0 dB，而是优化采样判决

高速互连通常具有频率相关损耗、反射和串扰。高频成分衰减后，脉冲响应在时间上展宽，前后符号的能量进入当前采样时刻，形成码间干扰ISI。

均衡器通过发送端预整形或接收端滤波，改变**信号、ISI和噪声到达判决器的相对关系**。

一个常见但过度简化的说法是：

`信道向下倾斜 + 均衡器向上倾斜 = 0 dB平坦频响`

这个图可以帮助初学者理解方向，却不能作为调参目标，原因包括：

- 信道可能存在深坑、反射纹波和群时延起伏，有限抽头无法精确求逆；
- 在深衰减处强行反演会显著增强噪声和数值误差；
- TX输出摆幅、抽头范围和功耗有限；
- RX线性均衡会同时滤波信号、噪声和串扰；
- 最终判定通常来自眼图、COM、BER、抖动容限或协议规定的接收测试，而不是“频响是否等于0 dB”。

因此更准确的目标是：

`在规定约束下，使采样点的有效信号相对于残余ISI、噪声、串扰和抖动获得最大裕量`

![图2：均衡的工程目标。频响补偿只是中间手段，最终要优化的是规定采样条件下的眼高、眼宽、SNR、COM或BER裕量，同时满足摆幅、噪声和抽头约束。](/images/34/ill02_objective_v2.png)

下面的动画从欠均衡逐步增加强度。眼图不是一直变好，而是先张开、到达最优区域、随后因过均衡再次收缩。

![图2b动图：均衡强度从不足扫到过强，判决裕量先改善后恶化，说明“最大档位”不等于“最优档位”。](/images/34/ill02b_sweep_anim.gif)

## 二、用游标描述ISI：均衡究竟在消除什么

设符号周期为`T`，在选定采样相位`t0`对链路脉冲响应采样：

`p_k = p(t0 + kT)`

规定：

- `p0`：main cursor，当前符号希望保留的主响应；
- `p−1、p−2...`：precursor，主游标之前的响应；
- `p1、p2...`：postcursor，主游标之后的拖尾。

接收机判决第`n`个符号时，可以写成：

`r[n] = p0·a[n] + Σp_m·a[n−m] + Σp_−m·a[n+m] + w[n]`

其中：

- 第一项是当前符号；
- 第二项是历史符号通过postcursor留下的干扰；
- 第三项是后续符号通过precursor影响当前采样；
- `w[n]`包含噪声及其它未建模干扰。

均衡后的目标不是让所有旁游标在任何条件下都严格等于0，而是让main cursor相对于**残余ISI和噪声**足够大。

![图3：游标和ISI。必须先声明采样原点和符号周期，才能定义main、pre和post；均衡调优比较的是主游标、残余旁游标及噪声的综合结果。](/images/34/ill03_cursor_v2.png)

本文教学模型在未均衡时使用以下离散游标：

`[-0.035, -0.095, 0.620, 0.310, 0.180, 0.095, 0.050, ...]`

其中`0.620`是main，右侧较大的`0.310、0.180`是主要postcursor。该数据只用于演示参数扫描，不代表任何接口或板卡。

## 三、TX FFE：先在噪声进入接收机之前整形

TX FFE是发送端有限冲激响应滤波器。采用本文的索引约定：

`x[n] = Σ c_k·a[n−k]`

三抽头可以写成：

`x[n] = c_pre·a[n+1] + c0·a[n] + c_post·a[n−1]`

它通过precursor、main和postcursor抽头预先塑造发送波形，使“TX + Channel”的组合脉冲响应更利于接收机判决。

### 1. pre-emphasis、de-emphasis和preshoot不要混用

- **TX FFE / transmitter equalization**：最稳妥的总称；
- **de-emphasis**：通常描述跳变后的首个符号保持较高幅度，而同极性后续符号降低，主要关联postcursor；
- **preshoot / pre-shoot**：由precursor抽头在跳变之前形成额外幅度；
- **pre-emphasis**：更宽泛地表示相对增强跳变相关高频成分，不应直接等同于某一个抽头。

只有在非常简单的一抽头模型中，“抬高跳变”和“压低稳态”才可以作为相对效果理解。正式测试必须使用对应规范对摆幅、preshoot、de-emphasis、preset或抽头系数的定义。

### 2. TX FFE的代价

TX FFE不会直接滤波后来进入RX的前端噪声，但它不是免费增益：

- 总输出摆幅和驱动电流有限；
- 侧抽头越大，main cursor可用幅度通常越少；
- 可能增加过冲、EMI、功耗和非线性；
- 长连码电平不能低到接收机无法识别；
- 抽头范围、量化步长和合法组合由接口或芯片规定。

不存在跨标准通用的“抽头之和必须等于1”。有的实现固定main，有的固定峰值，有的使用preset表；报告必须注明归一化方法。

为便于二维扫描，本文教学模型单独采用峰值预算约束：

`|c_pre| + c0 + |c_post| = 1`

这只是本文分配发送摆幅余量的方法，不是任何接口都必须遵守的标准约束。

## 四、RX线性均衡：CTLE和RX FFE都会同时处理信号与噪声

### 1. CTLE

CTLE是接收前端的连续时间线性滤波器。它可以：

- 相对衰减低频，形成高频峰化；
- 提高过零点附近的斜率；
- 减少部分残余ISI和数据相关抖动。

CTLE不一定需要提供大于0 dB的绝对高频增益。很多实现通过降低低频增益获得相对峰化。

对于输入噪声功率谱`Sn(f)`，输出噪声与：

`∫ |H_CTLE(f)|² · Sn(f) df`

有关。更强峰化和更宽带宽可能让更多高频噪声、串扰和前端噪声进入判决器；但如果它显著降低ISI，净SNR和净抖动仍可能改善。因此不能只凭“CTLE峰化几dB”判断好坏。

### 2. RX FFE

RX FFE在采样后进行线性数字滤波，可以处理pre和postcursor，但它同样会滤波已经混入的噪声。对白噪声近似：

`σ²_out ≈ σ² · Σc_k²`

所以RX FFE和TX FFE的噪声边界不同：

- TX FFE在前端噪声进入之前整形；
- RX FFE对信号和已进入接收机的噪声一起处理。

![图5：CTLE和RX FFE的收益与代价。线性均衡可以降低残余ISI、提高过零斜率，但也改变积分噪声带宽、振铃和群时延；最佳设置必须看采样裕量。](/images/34/ill05_linear_eq_v2.png)

## 五、DFE：不做线性噪声增强，但仍然会被噪声击穿

理想符号间隔DFE可以写成：

`u[n] = r[n] − Σ b_m·â[n−m]`

它利用已经判决的历史符号`â[n−m]`，估算这些符号产生的postcursor，并从当前采样中减掉。

在**系数正确、历史判决正确**时，反馈量由离散判决值产生，不会像CTLE或RX FFE那样对当前模拟噪声执行高频逆滤波。因此准确表述应是：

> 理想DFE不会产生线性均衡器那种噪声增强。

但它绝不是“完全不受噪声影响”：

- 当前采样噪声仍然存在；
- 噪声可能先造成错误判决；
- 错误历史位会生成错误抵消量；
- 错误可能继续进入反馈，形成错误传播；
- slicer、反馈DAC、时钟和自适应环都有实现误差；
- 因果DFE只能直接处理postcursor，不能直接消除precursor。

“误码成串”与DFE错误传播相符，但不是唯一证据。CDR失锁、电源扰动和突发串扰也会造成burst error，仍需受控A/B。

![图6：DFE的工作边界。正确判决时可以抵消postcursor而不做线性噪声增强；一次错误判决却可能把错误抵消量反馈到后续符号。](/images/34/ill06_dfe_v2.png)

## 六、训练和自适应不能跨接口混成一套流程

“现代接口都会自动调TX、CTLE和DFE”这句话过于笼统。不同接口的训练对象和合规方法不同。

### PCI Express

PCIe Gen3及以后支持trainable equalization。公开资料说明：

- 接收方向远端TX请求规定的preset；
- 也可以请求远端TX调整具体FFE系数；
- 请求对象是**对端发送器**；
- RX内部采用CTLE、DFE、眼监视器、LMS或其它算法属于实现细节，不会通过PCIe训练序列交换内部RX抽头。

### USB 3.2

USB 3.2应按照USB-IF Electrical CTS分别执行规定的TX和RX流程。不能把PCIe的P0～P10、coefficient request或训练阶段直接套到USB。

### IEEE 802.3 COM

COM使用规定的reference Tx、S参数信道、reference Rx、噪声和串扰模型计算统计裕量。它可以包含TX FFE、CTLE和DFE模型，但COM是**参考模型计算**，不等于真实芯片RX合规，也不等于实际链路训练。

### DDR5

DDR5是DQ/DQS源同步并行存储器接口，需要区分读写方向、控制器和DRAM、Vref及训练流程。DDR5引入DFE，但不存在PCIe式远端TX preset back-channel流程。

![图7：四类接口的均衡边界。PCIe动态请求远端TX，USB按CTS分项测试，IEEE COM使用参考收发机模型，DDR5按读写方向和存储器训练处理，不能共用一套步骤。](/images/34/ill07_boundaries_v2.png)

## 七、什么时候需要关注均衡，判据从哪里来

不存在“超过5 Gbps就必须均衡、低于5 Gbps就不需要”的通用门槛。

是否需要均衡取决于：

- 接口规范是否定义TX/RX均衡；
- 奈奎斯特频率附近的插入损耗、反射、串扰和群时延；
- 脉冲响应的pre/postcursor；
- 接收架构、目标BER和可用摆幅；
- 通道长度、连接器、过孔、封装和PVT；
- NRZ、PAM4或源同步接口的不同判决模型。

正式判据应拆成四个域：

| 验证域 | 主要对象 | 常见判据来源 | 不能替代 |
|---|---|---|---|
| TX合规 | preset、FFE抽头、摆幅、抖动、波形 | Base/PHY规范、Electrical CTS | RX能力 |
| Channel / reference receiver | S参数、IL/RL、串扰、COM或参考接收机眼图 | Channel spec、IEEE/接口规范 | 真实DUT RX |
| RX stressed input | 校准后的ISI、抖动、噪声、幅度和BER | Electrical CTS、RX test spec | TX和通道合规 |
| Link training / functional | 训练请求、重试、降速、错误计数、互操作 | 协议规范、平台要求 | 分项电气测试 |

![图8：均衡验证应拆成TX、Channel/reference receiver、RX stressed input和Link training四个域。软件均衡后的示波器眼图不能替代真实RX的压力输入BER。](/images/34/ill08_validation_v2.png)

报告中每个数值都要绑定：

`接口/代际｜速率和调制｜方向｜测试模式｜参考面｜pattern｜reference receiver｜滤波/CDR｜标准版本和章节`

没有适用规范时，应建立系统预算和设计目标，不能编造通用的“CTLE至少几dB”或“DFE必须几抽头”。

## 八、怎样搭建一次可复现的均衡验证

### 1. 保存未调参基线

记录：

- TX原始波形和preset；
- Channel S参数及参考面；
- RX输入压力条件；
- 当前TX/RX均衡设置；
- 训练日志、最终速率和lane；
- BER、累计bit数、错误分布；
- 温度、电压、参考时钟和固件版本。

### 2. 分域验证

**TX：**

- 在规定参考面和pattern下逐preset采集；
- 按规范处理fixture和reference receiver；
- 检查抽头、摆幅、抖动和转换特性。

**Channel：**

- 测完整复数S参数；
- 执行对应的channel mask、COM或参考接收机算法；
- 不把channel结果写成真实RX已经通过。

**RX：**

- 先在RX参考面校准幅度、ISI、RJ/SJ、噪声和pattern；
- 再接DUT，进入规定loopback或测试状态；
- 累计足够bit数并记录错误。

**Link：**

- 抓训练请求和响应；
- 记录重训练、降速、lane repair、LTSSM状态及错误计数；
- 区分“训练协议失败”和“训练成功后BER失败”。

![图9：均衡验证台面和记录项。TX、Channel、RX压力输入和Link训练使用不同观察点；每次扫描必须保存参考面、参数、BER计数和训练日志。](/images/34/ill09_bench_v2.png)

### 零误码不是BER等于0

观察`N`个bit且没有错误时，95%置信上限近似为：

`BER_95% ≈ 3 / N`

例如只观察`10^9` bit且零错误，只能说明95%置信上限约为`3×10^-9`，不能写成“BER=0”。

## 九、怎样扫描参数：先粗扫，再局部细扫

回到本文16 GBd NRZ教学案例。

我们固定：

- 相同通道游标；
- 相同噪声；
- TX precursor为`−0.05`；
- DFE最多3个postcursor抽头；
- 只扫描TX postcursor和CTLE强度。

教学模型综合考虑：

- main cursor；
- 残余ISI；
- RX线性均衡的噪声代价；
- DFE反馈系数过大的启发式风险惩罚；
- TX侧抽头占用的摆幅；
- CTLE过强的带宽和振铃代价。

结果不是“越往右上越好”，而是出现一个最优区域：

- TX post约`−0.184`；
- CTLE归一化强度约`0.25`；
- DFE使用3个postcursor抽头。

这些数值只属于本文模型，不能作为芯片设置推荐值。

其中DFE风险项只是根据反馈系数大小加入的教学性惩罚。该游标模型没有slicer状态、注错和BER仿真，因此不能计算真实错误传播概率。

![图10：TX postcursor与CTLE二维参数扫描。最优点位于中间区域；左下是欠均衡，右上因摆幅、噪声和反馈代价进入过均衡。](/images/34/ill10_heatmap_v2.png)

下面的动画演示一种更可靠的搜索方式：先粗扫找到高裕量区域，再局部细扫，不在所有变量上同时盲调。

![图10b动图：参数搜索从粗网格进入局部最优区域，并保留周围余量，而不是只记住一个偶然最优点。](/images/34/ill10b_search_anim.gif)

### 实际项目建议流程

1. 固定测试点、pattern、速率、温度和噪声条件；
2. 先按标准允许范围粗扫TX preset或FFE；
3. 在每个候选TX设置下扫描CTLE或RX FFE；
4. 再逐步加入DFE抽头，观察收益和错误传播；
5. 每个点重新训练多次，记录收敛结果分布；
6. 对最佳区域进行更长BER测试；
7. 选择有余量的稳定区域，而不是单次最高点。

每个点至少记录：

`TX抽头｜CTLE/RX FFE｜DFE抽头｜BER和累计bit｜眼裕量｜训练时间｜重试次数｜最终系数｜是否撞到上下限｜功耗/温升`

| 现象 | 优先假设 | 下一步证据 |
|---|---|---|
| 多块板、短信道也在同一TX preset下失败 | TX、时钟、电源或fixture | 换RX、测TX合规、功率/温度A/B |
| TX通过，但Channel mask/COM失败 | PCB、连接器、过孔、封装或参考面 | S参数、TDR、第二夹具和结构A/B |
| RX压力输入已正确校准，仍然BER失败 | RX EQ/CDR或接收裕量 | 更换DUT、固定输入、扫压力和参考时钟 |
| 训练阶段卡死或反复降速 | 协议、固件、请求响应、复位/时钟 | 抓训练序列和状态机，不先归因CTLE |
| 最优点撞到TX或CTLE最大档 | 通道预算不足或架构余量不足 | 缩短通道、换材料/连接器、降低速率A/B |
| 单次能过，多次重训结果离散 | adaptation稳定性、初值、噪声或温漂 | 冷启动/热启动多次统计最终系数 |
| DFE打开后随机误码下降，但burst变长 | 可能存在错误传播 | 注入受控错误、DFE on/off、检查CDR和电源 |
| 软件均衡眼图通过，真实RX仍失败 | reference receiver与DUT RX不一致 | 以真实RX压力输入BER为准 |

### 观察不是根因

- “CTLE开到最大”只是设置状态；
- “DFE抽头很大”只是相关线索；
- “眼图变大”只说明某个参考模型的结果改善；
- “burst error”也不能单独证明DFE错误传播。

必须通过替换、开关、参数扫描、改频、温度或结构A/B建立证据。

## 十一、整改与原条件复测

| 根因 | 对应整改 | 必须复查 |
|---|---|---|
| TX摆幅或preset不合规 | 修TX配置、电源、时钟或驱动 | 全部必测preset和PVT |
| 通道损耗/反射超预算 | 缩短路径、优化过孔/连接器、材料和参考面 | S参数、COM/参考接收机、其它lane |
| CTLE过强 | 降峰化或带宽，重新分配TX/RX均衡 | 噪声、抖动、眼高和温升 |
| TX侧抽头过大 | 收回side tap，保留main和长连码摆幅 | EMI、过冲、TX合规 |
| DFE错误传播 | 降低反馈依赖，先改善TX/线性EQ和输入SNR | burst error、CDR和噪声A/B |
| adaptation不稳定 | 调整训练时间、初值、固件或搜索策略 | 多次冷/热启动和重训练 |
| 训练协议异常 | 修preset/coeff请求、状态机、复位或时钟 | 协议日志和互操作 |

整改后必须恢复原来的：

`接口/速率｜lane和方向｜参考面｜pattern｜压力条件｜TX/RX参数范围｜训练流程｜温度/电压｜时钟｜固件`

然后执行：

1. 原失败条件复现；
2. 修复前后单变量A/B；
3. 所有相关速率、lane、方向和必测preset；
4. 多次冷启动、热启动和retrain；
5. 温度、电压和参考时钟角落；
6. 多块板和多器件批次；
7. 延长BER观察时间；
8. 确认最佳点周围仍有可用余量。

## 十二、🔧 工程师速查

### 1. 核心目标

`均衡 ≠ 恢复0 dB`

`均衡目标 = 在摆幅、噪声、串扰、抖动、抽头和功耗约束下最大化判决裕量`

### 2. 四类均衡

| 类型 | 作用 | 主要代价 |
|---|---|---|
| TX FFE | 在RX噪声进入前预整形，可处理pre/post | 占用摆幅、main、功耗和EMI预算 |
| CTLE | 连续时间线性频响补偿 | 同时滤波输入噪声/串扰，可能振铃 |
| RX FFE | 数字线性处理pre/post | 滤波已混入的噪声 |
| DFE | 用历史判决抵消postcursor | 错误传播、反馈时序和实现误差 |

### 3. 标准边界

`PCIe请求远端TX ≠ 交换RX内部抽头`

`USB CTS ≠ PCIe preset流程`

`COM参考模型 ≠ 真实RX合规`

`DDR5训练 ≠ SerDes back-channel`

### 4. 参数扫描

`保存基线 → 粗扫TX → 扫线性RX → 加DFE → 多次重训 → 长BER → 选择稳定区域`

### 5. Fail定位

`TX合规｜Channel/COM｜RX压力输入BER｜Link训练日志`四域分开，不能只看均衡后眼图。

### 6. 复测

`原失败条件｜全lane/方向/速率｜多次冷/热启动｜PVT｜多板/批次｜长BER｜最优区域余量`
