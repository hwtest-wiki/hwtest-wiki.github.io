# 眼图不是一张“眼睛”：先把 UI、时间参考、码型和判据锁定，再谈余量

<div class="article-meta"><span class="badge">📘 模块三 · 信号完整性 SI · 眼图</span><span class="badge">⏱ 约 21 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


实验室里最危险的眼图，不一定是闭得最狠的那张，而是**看起来很漂亮，却没有写清怎么得到的那张**。

同一条链路，只要换了时间参考、码型、参考面、带宽、滤波、去嵌或接收器模型，眼高、眼宽和mask结果都可能变化。截图上的“眼睛”只是最终显示；真正能支撑结论的是测试条件、适用标准和证据链。

本文完成一条完整工程路径：

`理解眼图 → 判断何时需要 → 选择指标 → 找到标准 → 正确测试 → 解读结果 → 定位Fail → 对应整改 → 原条件复测`

---

## 1. 眼图是什么，为什么要看

眼图是把连续数字波形按照某个时间参考切片、对齐并重复叠加后形成的统计图。它把三类信息压在同一张图里：

- **电压维度**：高低电平、噪声、摆幅和判决阈值；
- **时间维度**：边沿位置、眼宽、交叉区和抖动；
- **数据相关维度**：前后比特、ISI和不同转换路径形成的轨迹密度。

接收器必须在有限的时间和电压窗口内做出判决。眼口越小，代表在当前测试条件和接收模型下，可用采样余量越少。

但眼图不是BER本身，也不是根因检测器。它能回答：

- 当前条件下还剩多少水平和垂直开口；
- 哪些轨迹正在侵入判决区域；
- 哪些lane、方向、速率或工作角落更差；
- 下一步应该检查抖动、通道、噪声还是测量台面。

它不能单独证明：

- 眼图漂亮就一定没有低概率误码；
- mask通过就代表整套接口合规；
- 眼宽变窄就一定是时钟故障；
- 眼高下降就一定来自串扰。

### UI先按符号率计算

UI（Unit Interval）是一个符号占用的时间：

`UI = 1 / Symbol Rate`

NRZ，也可写作PAM2，每个符号承载1 bit。5 GBd NRZ对应5 Gb/s，1 UI为200 ps。

PAM4每个符号有四个电平，可承载2 bit。同样是5 GBd，线路比特率为10 Gb/s，但1 UI仍然是200 ps。把PAM4的10 Gb/s直接代入`1 / bit rate`，会把UI错算成100 ps，折叠窗口、抖动归一化和mask横坐标都会跟着出错。

![图1：UI、NRZ和PAM4的关系。5 GBd教学示例中，NRZ每符号1 bit、PAM4每符号2 bit；两者UI都为200 ps。](/images/31/ill01_symbol_ui.png)

## 2. 眼图怎样形成，NRZ和PAM4有什么不同

眼图不是从一条“代表性波形”画出来的。基本过程是：

1. 确定符号率和UI；
2. 建立适用的时间参考；
3. 按固定窗口截取连续波形，常见显示窗口为2 UI；
4. 把不同时间位置的窗口对齐到同一横坐标；
5. 累积足够多的轨迹，用颜色或亮度表示出现密度。

在理想的2 UI NRZ显示中，符号边界位于0、1、2 UI，判决中心位于0.5和1.5 UI。显示两只重复眼口只是为了方便观察左右边界，不代表协议一定以2 UI为测量单位。

![图2：连续码流按时间参考切成多个2 UI窗口，再折叠到同一坐标。红点是判决中心，橙线是符号边界。](/images/31/ill02_folding.png)

轨迹数量太少时，眼图只是一组稀疏线条。累积增加后，常见路径逐渐变亮，低概率尾部才可能出现。因此显示密度、采集数量、命中数和分段方式必须一起保存。

### NRZ一只眼，PAM4三只眼

NRZ只有高、低两个电平，因此只有一个判决阈值和一只眼。PAM4有四个电平，需要三个判决阈值，对应上、中、下三只眼。

PAM4不能简单地把NRZ mask复制三次。还要分别关注：

- 三只眼的高度、宽度和中心；
- 四个电平的线性度；
- 不同跨级跳变和转换方向；
- 三只眼中最差的一只；
- 参考接收器、FEC和BER定义。

![图3：同一5 GBd教学模型下，NRZ形成一只眼，PAM4形成三只眼；PAM4需要分别观察三只眼及电平线性。](/images/31/ill03_nrz_pam4.png)

报告不能只写“眼高120 mV”。至少还要说明调制方式、测的是哪只眼、读取位置、统计定义和接收器处理。

## 3. 什么时候需要关注眼图

眼图最适合回答“接收器在当前条件下还剩多少联合电压—时间余量”，常见场景包括：

| 场景 | 为什么使用眼图 | 还需要配合什么 |
|---|---|---|
| 嵌入时钟高速串行链路 | 观察参考接收机下的Tx波形和水平/垂直开口 | 规范CDR、mask、抖动、BER或Rx JTOL |
| 转发时钟链路 | 观察数据相对规定时钟处理后的采样空间 | clock-data skew、PLL和deskew设置 |
| DDR/LPDDR源同步接口 | 观察DQ相对数据选通的有效采样窗口 | setup/hold、skew、burst筛选和读写方向 |
| 通道或均衡调试 | 比较损耗、反射、串扰和均衡变化后的综合结果 | S参数、TDR、TIE、频谱和BER |
| PVT或量产角落 | 找出最差lane、方向、速率、温度或电压条件 | 原始数据、统计分布和重复性 |

DDR/LPDDR必须按代际、读写方向和工作模式选择参考。传统DDR数据通常相对DQS采样；LPDDR5/5X写方向的DQ通常相对WCK，读方向的DQ通常相对RDQS，并受WCK2CK、RDQS训练和门控状态影响。CK主要是命令/地址CA时序参考，不能把CK和数据选通笼统当成同一种对象。

以下情况不应只靠眼图：

- I2C、SPI、UART等低速接口，通常先检查电平、setup/hold、脉宽和协议时序；
- 长时间偶发错误，短记录眼图可能抓不到，需要BER、错误日志或长时间触发；
- 通道故障位置需要TDR，频域损耗和模式转换需要VNA/S参数；
- 电源或参考时钟相关性需要同步采集和频谱证据。

因此，眼图不是所有接口的固定动作，也不是所有问题的最终答案。

## 4. 眼图应该看哪些指标

一张眼图里的常见观察量包括：

| 指标 | 回答的问题 | 不能单独代表 |
|---|---|---|
| 眼高 | 指定时间和统计定义下的垂直开口 | 完整噪声预算或最终BER |
| 眼宽 | 指定电平或BER条件下的水平开口 | 全部抖动来源 |
| 交叉区 | 边沿时间和幅度分布 | 唯一时钟或DCD根因 |
| 轨迹厚度 | 噪声、抖动、ISI和处理后的综合结果 | 单一物理来源 |
| 密度分布 | 常见路径和低概率尾部出现情况 | 无限时间可靠性 |
| mask hit | 已采集样本是否进入规范禁区 | 整套接口合规或BER保证 |
| 浴盆曲线 | BER随采样相位变化 | 根因位置 |

![图4：眼图解剖。符号边界、判决中心、眼高、眼宽、交叉区和轨迹密度分别对应不同测量问题。](/images/31/ill04_anatomy.png)

眼高和眼宽都依赖测量定义：在哪个时间或电平读取、允许多少命中、是否使用外推、采样数量是多少、是否经过参考滤波和接收器均衡。

下面的动画只演示综合链路损伤增加时，轨迹如何侵入判决区域。参数扫描同时改变边沿展宽、ISI、数据相关抖动和噪声，没有加载接口mask，也不输出合规结论。

![动图1：综合链路损伤连续增加，眼口逐步失去采样空间；非CTS、非真实DUT。](/images/31/ill04b_channel_anim.gif)

## 5. 眼图多少算合格，标准从哪里来

不存在脱离接口、代际、测试点、码型和参考接收器的通用眼高或眼宽限值。

查判据时按下面的顺序：

1. 确认接口、代际、速率、产品形态和DUT角色；
2. 确认测的是Tx、经过参考通道的远端波形、系统眼图还是源同步时序；
3. 查Base/PHY规范、CTS、JEDEC标准、器件手册或系统预算；
4. 核对测试点、test mode、码型、参考PLL/CDR、滤波、均衡和去嵌；
5. 找到对应mask、眼高/眼宽或时序判据；
6. 在报告中记录标准名称、版本、章节或测试项。

### 一个真实例子：USB 3.2发送端眼图

USB 3.2 Specification Revision 1.1的§6.7.3 Table 6-20给出了TP4处的规范发送端眼图判据：

| USB 3.2 Tx项目 | Gen1 5 GT/s | Gen2 10 GT/s |
|---|---:|---:|
| UI | 200 ps | 100 ps |
| Eye Height minimum | 100 mV | 70 mV |
| Tj maximum | 0.660 UI | 0.671 UI |

这些数字有明确条件：

- Gen1使用CP0/CP1，Gen2使用CP9/CP10；
- 眼高在连续`10^6 UI`上测量；
- 眼高读取中心附近`±0.05 UI`范围内的最小开口；
- 在TP4处判定；
- 按CTS指定的端口角色、夹具、参考通道和参考均衡处理；报告必须说明参考通道是实体包含、后处理嵌入还是去嵌的一部分，不能重复计入，并记录所用S参数、CTLE/DFE模型、参数和版本；
- 抖动按规定方法外推到`BER = 10^-12`。

换成连接器近端、其它码型、其它参考均衡、Rx测试或另一代接口后，不能继续沿用这组数字。

USB 3.2 Electrical Compliance Test Specification Rev 1.8的§3.3和§3.8说明Gen1/Gen2 Data Eye and Jitter怎样执行。Base规范给判据，CTS规定程序，两者不能只看其中一份。

### mask结果的边界

mask是标准定义的禁区。只有版本、角色、速率、码型、参考面、对齐、参考接收器和采集条件都正确，mask结果才能支撑对应测试项。

无hit应写成：

> 在本次已采集的N个样本或波形中无mask hit。

不能写成：

> 链路永远不会误码，或者整套接口已经合规。

## 6. 怎样正确测试眼图

### 第一步：定义对象

写清接口版本、DUT角色、方向、lane、速率、调制、工作模式和温压条件。

### 第二步：确定测试点和参考面

明确是在芯片焊盘、连接器、夹具端、近端还是经过规定参考通道后的测试点。夹具、线缆、探头和interposer是否包含在判据内必须先确定。

### 第三步：选择正确时间参考

| 链路类型 | 常见时间参考 | 必须记录 |
|---|---|---|
| 嵌入时钟串行链路 | 规范规定的参考PLL/CDR | 环路带宽、阶数、峰化、SSC和参考接收器版本 |
| 转发时钟链路 | 时钟通道经过规定PLL、恢复和deskew处理 | 数据/时钟探测位置、路径匹配和处理模型 |
| DDR/LPDDR源同步数据 | 传统DDR通常使用DQS；LPDDR5/5X写DQ通常相对WCK，读DQ通常相对RDQS；CA时序主要相对CK | read/write、byte lane、burst、门控、WCK2CK/RDQS training、WCK:CK模式和参考信号配置 |

![图5：三类时间参考。时间参考必须匹配接口架构和标准规定，不能所有链路都写成“CDR触发”。](/images/31/ill05_time_reference.png)

HDMI TMDS等转发时钟链路有独立时钟通道，但也不能直接拿原始clock lane折叠数据；仍需按对应规范进行PLL恢复、deskew和参考处理。

### 第四步：搭建测量台面

确认：

- 仪器、探头/夹具和校准状态；
- 端接、探头负载和差分deskew；
- 带宽、采样率、记录长度和采集模式；
- 去嵌文件、参考接收器滤波和CTLE/DFE处理；
- 仪器噪声、时基和测量不确定度。

![图6：眼图测试台面和参考面。DUT、夹具/探头、示波器或BERT之间必须明确参考面、校准、deskew、带宽、去嵌和接收器处理。](/images/31/ill06_bench.png)

### 第五步：选择测试码型

| 码型 | 适合回答的问题 | 不能替代 |
|---|---|---|
| 规范指定一致性码型 | 正式合规测试 | 不能被更方便的自选码型替换 |
| PRBS7/PRBS31等 | 通道表征、BER、压力和调试 | 不自动等于正式CTS码型 |
| 1010或重复时钟码 | 幅度、频率、边沿和基线检查 | 覆盖不了复杂数据相关ISI |
| 业务流量 | 系统复现、互操作和偶发问题 | 不能替代可控合规激励 |

![图7：四类码型的用途边界。正式一致性优先规范指定码型，PRBS、1010和业务流量分别回答不同问题。](/images/31/ill07_patterns.png)

### 第六步：采集并保存原始证据

记录总UI数、波形数、mask hit数、分段方式和错误事件。保存原始波形、setup、mask、去嵌文件、协议或错误日志、环境和时间戳。

一份可复现记录可以这样写：

> DUT Tx lane 0，5 GBd NRZ；Ref A位于连接器焊盘；差分有源探头；20 GHz带宽；48 GS/s；记录2 M UI；使用规范指定参考PLL；夹具S参数去嵌到Ref A；温度25 °C；测试码型为规范指定pattern。

这比“眼图通过，余量不错”更有价值。

## 7. 怎样解读眼图结果

结果应分成三层：

1. **观察**：眼高、眼宽、交叉区、密度、mask hit和最差条件；
2. **判据结论**：当前测试项是否满足声明标准；
3. **根因假设**：需要哪些专用证据继续验证。

### Q到BER的换算有前提

对二电平、垂直噪声近似高斯、上下电平可用均值和标准差描述，并采用给定判决阈值的模型，常用Q估计为：

`Q = (μ1 - μ0) / (σ1 + σ0)`

`BER = 0.5 × erfc(Q / √2)`

按常见等尾或最佳阈值假设，`Q = 6`时`BER ≈ 9.87 × 10^-10`，`Q = 7`时`BER ≈ 1.28 × 10^-12`。若上下电平方差、先验概率或误判代价不同，必须同时报告判决阈值和BER计算模型。

这些不是接口通用判据。严重ISI、确定性抖动、非高斯尾部、低概率突发和PAM4多阈值问题，都不能只靠这一公式得出最终BER。

### 浴盆曲线要区分实测和外推

横向浴盆表示BER随采样相位变化。它可以来自真实BER扫描，也可以来自统计模型外推。报告必须说明拟合模型、目标BER、参考接收器和置信边界。

![图8：Q-BER模型、横向浴盆和mask的证据边界。Q换算需要模型假设；浴盆要写明实测或外推；mask依赖正确测试条件。](/images/31/ill08_evidence.png)

## 8. 眼图Fail后怎样定位

先确认Fail有效：

- DUT模式、码型和速率正确吗？
- 参考面、去嵌和参考接收器正确吗？
- 时间参考、带宽、阈值和均衡符合标准吗？
- 探头、夹具、时基和噪底是否足够？
- 同一条件下能够重复出现吗？

确认测量有效后，再根据外观选择下一条证据：

| 眼图观察 | 候选方向 | 下一条证据 |
|---|---|---|
| 上下轨迹增厚、眼高下降 | 电源噪声、串扰、探测噪底、阈值变化 | 同步采电源/邻线、测仪器本底、换探头 |
| 交叉区横向散开、眼宽下降 | 时钟、PLL/CDR、PJ、DDJ | TIE track、频谱、改CDR或改候选源频率 |
| 数据相关拖尾或多条路径 | 通道损耗、反射、ISI、均衡不足 | S参数、TDR、固定码型和均衡扫描 |
| 只在某lane、方向或速率出现 | 局部通道、连接器、Tx/Rx设置 | 换lane、交换路径、改变方向或速率 |
| 换夹具后异常移动 | 夹具、探头、deskew或去嵌 | 端口交换、重新校准、已知良品对照 |

![图9：四类病态眼图线索。垂直增厚、横向散开、数据相关拖尾和综合闭眼分别指向不同的下一步证据。](/images/31/ill09_fingerprints.png)

眼图外观只能分诊。“眼图变矮就是串扰”“眼宽变窄就是时钟坏了”都过度简化。探头加载、带宽限制、错误去嵌、参考PLL和接收器均衡可能制造相似外观。

下面的动画依次增加垂直噪声、时序抖动和ISI，用来练习观察方向。真实问题通常是多因素叠加，最终仍要靠频谱、TIE、S参数、近端探测或受控A/B确认。

![动图2：依次增加垂直噪声、时序抖动和ISI；外观只提供线索，不代替根因证据。](/images/31/ill09b_impairments_anim.gif)

## 9. 定位根因后怎样解决

整改必须与根因证据对应：

| 根因方向 | 常见整改 | 必须复查 |
|---|---|---|
| 测量台面 | 校准、deskew、更换探头/夹具、修正去嵌 | 重复装夹、已知良品和仪器本底 |
| 时间参考或PLL/CDR | 恢复规范模型、优化参考时钟、环路或供电 | 锁定、SSC、wander和抖动其它频段 |
| 通道损耗、反射和ISI | 优化走线、过孔、连接器、端接和通道材料 | S参数、TDR、不同码型和PVT |
| 串扰或电源噪声 | 增距、缩短并行、改善回流/去耦和隔离 | 其它victim、EMI和负载瞬态 |
| 发送端摆幅或边沿 | 调整驱动、预加重/去加重和差分对称 | 功耗、过冲、接收端范围和全档位 |
| 接收端均衡或阈值 | 调整CTLE/DFE、训练和判决阈值 | 噪声放大、错误传播和训练稳定性 |

均衡能补偿部分通道损耗，但不能恢复已经丢失的信噪比。CTLE可能放大高频噪声，DFE可能出现错误传播，发送端预加重也会改变摆幅和功耗。不能只因为单张眼图变好就宣布方案完成。

## 10. 怎样证明问题真正解决

![图10：眼图工程闭环。从定义对象、锁定条件、采集证据、结果分层、根因定位到回原条件复测。](/images/31/ill10_workflow.png)

完成整改后：

1. 恢复原来的速率、码型、参考面、时间参考、带宽、去嵌、均衡和温压条件；
2. 重跑同一测试项目和相同采集数量；
3. 比较修改前后的原始波形、眼高、眼宽、mask hit、浴盆或BER；
4. 检查最差lane、方向、速率和PVT角落；
5. 复查功耗、锁定、EMI和其它相关项目是否退化；
6. 把结论限制在本次声明的测试项。

一份合格报告至少包含：

- 测试对象、模式、速率、调制和环境；
- 仪器、探头/夹具、校准和连接图；
- 参考面、时间参考、码型、带宽、去嵌和接收器模型；
- 采集UI数、原始眼图、量化结果和判据出处；
- 异常证据、受控A/B、修复动作和原条件复测结果。

眼图最有价值的地方，不是替你宣布“信号好不好”，而是把电压、时间和数据相关行为压到同一张统计图里，帮助你决定下一步应该拿什么证据。

## 🔧 工程师速查

### 1. 基本关系

| 项目 | 正确写法 |
|---|---|
| UI | `1 / Symbol Rate`，是符号周期 |
| NRZ/PAM2 | 1 symbol = 1 bit，5 GBd = 5 Gb/s |
| PAM4 | 1 symbol = 2 bit，5 GBd = 10 Gb/s，形成三只眼 |
| 2 UI显示 | 边界0/1/2 UI，理想判决中心0.5/1.5 UI |

### 2. 什么时候测

| 场景 | 首选动作 |
|---|---|
| 嵌入时钟高速串行 | 规范参考接收机下的Tx eye/mask，并配合抖动、BER或JTOL |
| 转发时钟接口 | 按规范处理clock lane、PLL和deskew后观察数据眼 |
| DDR/LPDDR | 传统DDR观察DQ相对DQS；LPDDR5/5X写DQ通常相对WCK、读DQ通常相对RDQS；CA时序主要相对CK |
| 通道/均衡调试 | 眼图配合S参数、TDR、TIE和BER |

### 3. 判据查找

`接口/代际 → DUT角色和测试项 → 测试点/码型/参考接收机 → Base/PHY或JEDEC表格 → CTS执行程序 → 报告记录版本和章节`

### 4. 码型选择

| 目的 | 码型 |
|---|---|
| 正式一致性 | CTS指定码型 |
| BER/通道表征/调试 | PRBS或规范要求的压力码型 |
| 幅度、频率、边沿基线 | 1010或重复时钟码 |
| 系统复现 | 真实业务流量，同时保存协议和错误日志 |

### 5. 结论边界

- Q-BER换算仅用于对应模型假设成立的场景。
- 浴盆要注明真实扫描还是外推，并写目标BER和模型。
- mask必须绑定标准版本、角色、速率、码型、参考面、对齐和采集条件。
- 无mask hit只覆盖本次已采集样本，不代表BER保证或完整接口合规。
- 合成教学眼图不得写成真实DUT实测或CTS通过结论。

### 6. 报告必填字段

DUT/角色/方向/lane｜速率与调制｜测试点/参考面｜探头/夹具/校准｜带宽/采样率｜时间参考｜码型｜去嵌/参考接收机/均衡｜采集UI数｜mask/判据出处｜原始波形｜A/B记录｜修复与复测

### 7. Fail闭环

`确认报告有效 → 写观察 → 选择专用证据 → 单变量A/B → 隔离根因 → 对应整改 → 恢复原条件 → 重跑同一测项 → 检查最差角落 → 限定结论范围`

> 本文所有合成眼图和参数扫描均为教学模型；USB 3.2表格只适用于文中声明的版本、测试点、码型和参考处理条件。
