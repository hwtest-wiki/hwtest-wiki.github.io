## 一、PCIe是什么、应用在哪里

### 1.1 PCIe不是“一组跑得很快的差分线”

PCIe，全称 **Peripheral Component Interconnect Express**。

从硬件视角看，它是一条高速串行差分链路；从系统视角看，它又是一套完整的分层协议和设备枚举体系。

一条PCIe连接通常包含：

- **Root Complex**：连接CPU/SoC与PCIe设备的根；
- **Root Port**：Root Complex向外提供的端口；
- **Endpoint**：NVMe SSD、网卡、GPU等终端设备；
- **Switch**：在一个上游端口与多个下游端口之间转发PCIe流量；
- **Link**：两个相邻PCIe Port之间的点到点连接；
- **Lane**：一组Tx差分对加一组Rx差分对。

这几个词不能混：

- NVMe是存储协议，不是PCIe电气规范；
- M.2是Form Factor和连接器体系，不等于PCIe协议；
- SSD能被系统识别，不等于PCIe Tx/Rx/Channel通过一致性测试；
- 顺序读写跑分高，不等于LTSSM、Recovery、低功耗切换和长稳都有Margin。

### 1.2 笔记本里哪些设备会用PCIe

常见对象包括：

- M.2 NVMe SSD；
- 独立GPU；
- Wi-Fi/蓝牙模组中的PCIe功能；
- 2.5G/5G/10G网卡；
- Thunderbolt/USB4 Host Router；
- SD Express等扩展控制器。

本文选择M.2 NVMe，是因为它同时具备：

- 明确的Root Complex与Endpoint；
- 常见的x4宽度；
- 真实的热、功耗和长稳压力；
- 容易观察到的枚举、AER、降速、降宽与掉盘现象；
- 可用M.2 Interposer同步协议、物理层和Sideband。

### 1.3 PCIe是全双工

每条Lane包含两个方向：

```text
Root Complex Tx ─────→ SSD Rx
Root Complex Rx ←───── SSD Tx
```

这意味着“PCIe Gen4 x4”不是四根单向线，而是：

- 4组Root Complex Tx → SSD Rx；
- 4组SSD Tx → Root Complex Rx；
- 两个方向可以同时传输。

所以Debug时必须先问：

> 到底是哪个发送端、哪个接收端、哪条Lane先出现异常？

### 1.4 为什么“短跑正常”仍可能长稳失败

短跑通常证明：

- 设备完成枚举；
- Link曾进入L0；
- 当前速度与宽度曾协商成功；
- 在那段时间、温度和负载下能够传输。

它没有证明：

- 热态仍有接收Margin；
- ASPM进入和退出都稳定；
- REFCLK长期稳定；
- SSD电源瞬态没有触发错误；
- 某条Lane不会随温度恶化；
- Recovery后仍能恢复原速度和宽度；
- Interposer、Socket与板级通道没有逼近边界。

因此PCIe系统验证的核心不是“一次跑通”，而是：

> 在规定代际、宽度、时钟架构、温度、电压、负载和电源状态下，持续保持可重复、可审计的链路行为。

## 二、传输原理和代际差异

### 2.1 一条Lane为什么能同时收发

一条Lane由两组独立差分对组成：

- 一组负责本端Tx；
- 一组负责本端Rx。

多Lane Link可以聚合成：

- x1；
- x2；
- x4；
- x8；
- x16。

**Speed** 与 **Width** 必须分开记录。

例如：

- Gen4 x4：16GT/s，4条Lane；
- Gen3 x4：速度下降，宽度未变；
- Gen4 x2：速度未变，宽度下降；
- Gen3 x2：速度和宽度都下降。

这四种状态代表的证据不同，不能统一写成“PCIe降频”。

### 2.2 PCIe三层分别做什么

PCIe通常分为三层：

#### Transaction Layer

负责事务语义和TLP，例如：

- Memory Read/Write；
- Configuration；
- Completion；
- Message。

#### Data Link Layer

负责相邻Link的可靠传输，例如：

- Sequence Number；
- LCRC；
- ACK/NAK；
- Replay；
- Flow Control相关管理。

#### Physical Layer

负责真正的链路建立和电气传输，例如：

- Lane；
- 编码与Scrambling；
- Electrical Idle；
- TS1/TS2；
- LTSSM；
- Link Training；
- Equalization；
- Tx/Rx电气行为。

当系统看到Bad TLP、Bad DLLP、Replay Timer Timeout或Receiver Error时，要先判断证据落在哪一层，再决定是否进入Tx、Rx或Channel调查。

### 2.3 从Gen1到Gen8发生了什么

| 代际 | 速率 | 信号与编码框架 | 公开定位 |
|---|---:|---|---|
| Gen1 | 2.5GT/s | NRZ、8b/10b | 早期PCIe |
| Gen2 | 5.0GT/s | NRZ、8b/10b | 速率翻倍 |
| Gen3 | 8.0GT/s | NRZ、128b/130b | 编码效率显著提高 |
| Gen4 | 16.0GT/s | NRZ、128b/130b | 当前M.2主流场景之一 |
| Gen5 | 32.0GT/s | NRZ、128b/130b | 高端M.2与平台验证 |
| Gen6 | 64.0GT/s | PAM4、FLIT、FEC、CRC | 以数据中心等场景为主 |
| Gen7 | 128.0GT/s | PAM4、FLIT、FEC、CRC | 2025年正式发布 |
| Gen8 | 目标256.0GT/s | 制定中 | Draft 0.5，目标2028年发布 |

这里有两个常见错误。

**错误一：把PAM4再乘2。**

PCIe Gen6的公开速率已经写成64GT/s，Gen7已经写成128GT/s。这个GT/s数值已经反映PAM4每个UI承载更多信息的效果，不能再额外乘2。

**错误二：拿Gen3～5的128b/130b公式直接套Gen6/7。**

Gen6/7进入FLIT、FEC与CRC框架，公开文章可以解释架构，但不能拿旧代际简式冒充正式有效吞吐或合规判据。

![图2：Root Complex、Endpoint、三层协议、全双工Lane与M.2 Sideband](/images/45/ill02_architecture.png)

### 2.4 Gen4 x4理论编码后带宽

Gen4为16GT/s，x4，使用128b/130b：

```text
单向编码后bit rate
＝ 16GT/s × 4 × 128 ÷ 130
≈ 63.015Gb/s

单向byte rate
＝ 63.015 ÷ 8
≈ 7.877GB/s
```

这个7.877GB/s还没有扣除：

- TLP与DLLP；
- Flow Control；
- Replay；
- NVMe命令与队列开销；
- SSD控制器和NAND限制；
- 文件系统、Driver和测试软件。

所以它不是“Gen4 SSD必须达到的跑分”。

### 2.5 Gen5 x4理论编码后带宽

```text
32GT/s × 4 × 128 ÷ 130 ÷ 8
≈ 15.754GB/s 单向
```

同理，这仍不是应用层保证值。

## 三、正确使用与设计注意事项

### 3.1 先保证每一条Lane真的完整

PCIe多Lane Link不是“总带宽够就行”。

每一条Lane都要检查：

- Tx P/N连线；
- Rx P/N连线；
- AC Coupling位置；
- Lane Mapping；
- 规范允许范围内的Polarity Inversion；
- 多Lane设计中的Lane Reversal支持边界；
- Via、Connector与Breakout；
- 参考平面连续性；
- Lane-to-Lane Skew；
- 串扰与间距。

如果某一条Lane Margin不足，系统可能：

- 从x4降到x2；
- 训练失败后回退低速；
- 热态才出现Receiver Error；
- Recovery后宽度变化；
- 只在特定SSD或特定主板组合失败。

### 3.2 AC Coupling通常放在Tx侧，并尽量靠近发送端

PCIe高速Lane通常使用AC Coupling，耦合电容一般放在发送端Tx侧，并尽量靠近发送端。具体设计仍要回到当前Base、CEM/M.2等Form Factor规范和器件资料确认，因为有些器件或模块可能已经集成耦合电容。

设计时要确认：

- 每个发送方向只保留一组所需的耦合电容，避免重复串接；
- 容值与封装符合当前代际和产品形态要求；
- 焊盘和过孔没有形成过大的阻抗突变；
- 不重复放置；
- Fixture、Interposer和DUT没有把同一方向串成多组意外耦合。

公开文章不提供受控容值或布局表，正式设计回到当前Base和Form Factor规范。

### 3.3 REFCLK架构必须在设计和报告里写清

常见架构包括：

- **Common Clock**；
- **SRNS**；
- **SRIS**。

它们会影响：

- SSC关系；
- Tx/Rx相对频偏；
- Elastic Buffer；
- SKP处理；
- 时钟抖动预算；
- 测试模式和仪器设置。

如果报告只写“Gen4 x4”，却不写Clock Architecture和SSC状态，很多结果无法复现。

### 3.4 Sideband不能只在开机时看一次

笔记本M.2场景应同步关注：

- REFCLK；
- PERST#；
- CLKREQ#；
- PEWAKE#；
- SSD主电源；
- 平台相关辅助电源；
- 温度；
- ASPM状态。

例如：

- PERST#异常会表现为设备重新初始化；
- CLKREQ#与REFCLK门控不匹配，可能只在低功耗退出失败；
- SSD电源瞬态可能先于AER或掉盘；
- 热态通道损耗和接收Margin变化，可能让问题只在长稳后出现。

### 3.5 Equalization不是“选一个最好看的Preset”

Gen3及以后需要链路均衡。

Tx侧可能使用：

- De-emphasis；
- Pre-shoot；
- Preset；
- Cursor。

Rx侧可能包含：

- CTLE；
- DFE；
- CDR相关适应。

Link Training会通过TS1/TS2等Ordered Set交换能力和请求，并在Recovery.Equalization中完成相关阶段。

工程上要避免：

- 只在示波器里挑一个眼睛最大的Preset；
- 忽略协议实际训练到的Preset；
- 修改Firmware强制Preset后不记录；
- 一端报告Preset，另一端实际输出不一致；
- 把一次训练结果当作所有温度和通道条件下的永久最优值。

### 3.6 Retimer和Redriver不是一回事

**Retimer：**

- 协议感知；
- 含CDR与重新定时；
- 将长路径分为两个独立电气段；
- 前后段分别训练和评估；
- 不能写成PCIe Switch。

**Redriver：**

- 不理解PCIe协议；
- 主要做模拟增益和均衡；
- 不形成新的协议可见Link边界；
- 不能提供Retimer同等的分段证据。

普通笔记本M.2链路不一定有Retimer。本文只把它用于工作站、服务器或长通道扩展场景。

### 3.7 设计阶段就要规划测试访问

至少要考虑：

- M.2 Interposer空间；
- Scope Probe落点；
- REFCLK、PERST#、CLKREQ#、PEWAKE#测试点；
- SSD电源电流与电压测量；
- 可重复的Thermal加载；
- Protocol Analyzer触发；
- Interposer与Probe去嵌或加载评估；
- Root Complex Rx附近是否存在可达点。

等问题发生后再问“BGA下面能不能探”，往往已经太晚。

## 四、PCIe一致性测试到底测什么

PCIe测试不能只剩一张眼图，也不能只剩一份NVMe跑分。

完整覆盖至少分六域：

| 测试域 | 回答的问题 | 常用工具 |
|---|---|---|
| Tx | 发送端输出是否满足规定信号质量 | 高带宽示波器、Fixture、Compliance软件 |
| Rx | 接收端能否承受规定的受扰输入 | BERT/Pattern Generator、Stress Channel、Error Counter |
| Channel | 无源路径是否在损耗与反射预算内 | VNA、TDR、Fixture、De-embedding |
| Protocol/LTSSM | Link如何训练、恢复、降速和重放 | Protocol Analyzer、系统Trace、AER |
| Clock/Reset/Power | 时钟、复位、电源状态是否与异常相关 | Scope、Power Analyzer、Logic/Protocol工具 |
| System Stress/Interop | 热、负载、ASPM与不同设备组合是否稳定 | I/O压力、温箱、功耗与日志系统 |

### 4.1 Tx Pass不代表Rx Pass

Tx测试回答：

> 发送端在规定参考面、测试模式和处理方法下是否合格？

它不能证明：

- 接收器JTOL足够；
- 板级通道合格；
- 协议训练稳定；
- ASPM没有问题；
- SSD电源健康。

### 4.2 Rx Pass不代表系统一定不掉盘

Rx测试回答：

> 接收端在规定Stressed Signal下能否保持规定错误性能？

它不能证明：

- 实际Tx输出合格；
- M.2 Socket没有损耗突变；
- REFCLK和Power稳定；
- Firmware不会触发错误状态；
- Protocol Recovery一定正确。

### 4.3 Channel Pass不代表Active Link一定Pass

Channel测试回答：

> 断电、隔离、参考面明确的无源路径是否满足损耗、回损、串扰和阻抗要求？

它不能证明：

- Tx抖动与幅度；
- Rx容限；
- Equalization策略；
- Clock Architecture；
- LTSSM行为。

### 4.4 Benchmark Pass更不能替代Compliance

NVMe Benchmark主要反映：

- 设备能力；
- NAND与缓存；
- Controller；
- Queue Depth；
- Driver与OS；
- 温度与功耗策略；
- PCIe Link状态。

它是系统性能测试，不是PCIe PHY一致性测试。

## 五、Tx、Rx、Channel分别怎么测

### 5.1 Tx：两个方向必须分开

#### 方向A：Root Complex Tx → SSD Rx

正式Tx测试的对象是Root Complex发送端。

需要：

- 规定的Test Mode或Compliance Pattern；
- 当前代际适用的Fixture；
- 明确Reference Plane；
- Scope与Compliance软件；
- 正确的Preset、Clock Architecture和SSC；
- Fixture Loss与De-embedding记录。

系统Debug时，靠近SSD Rx的可达点很有价值，因为它能看到：

```text
Root Complex Package
+ 主板走线
+ Via
+ M.2 Socket
+ SSD入口前路径
```

但这个点看到的是“系统接收端波形”，不能自动替代正式Root Complex Tx Compliance参考面。

#### 方向B：SSD Tx → Root Complex Rx

正式Tx测试的对象换成SSD发送端。

系统Debug优先靠近Root Complex Rx观察，但笔记本SoC通常是BGA，接收端附近可能不可达。

可选方法：

- 主板预留测试点；
- 可表征的表层Trace；
- Multi-lead Probe；
- M.2 Interposer上的物理层探测；
- 项目专用测试板。

报告必须写清：

- 实际探点；
- 未覆盖的Package/Trace段；
- Probe与Interposer加载；
- 是否去嵌；
- 该结果是Debug还是正式Compliance。

![图5：Root Complex与SSD双方向Receiver端Debug点、正式参考面和Retimer分段](/images/45/ill05_points.png)

![Setup：PCIe Root Complex Tx与Endpoint Tx正式测试台面](/images/45/fig_setup_tx.png)

### 5.2 Rx：先校准Stressed Signal，再接DUT

Rx测试的核心不是给DUT一条“很漂亮”的信号，而是给它一条经过校准的受扰输入。

典型流程：

1. Pattern Generator/BERT输出规定Pattern；
2. 加入规定的Jitter、Noise和Loss；
3. 通过Fixture/Stress Channel；
4. 连接校准Scope；
5. 校准DUT输入参考面的信号；
6. 保存Calibration ID与结果；
7. 撤掉Scope；
8. 将同一路径连接DUT Rx；
9. 通过Loopback、Exerciser、Receiver Error Counter或授权流程统计错误；
10. 记录总bit数、错误数、温度、电压和Equalization条件。

需要分别测：

- Root Complex Rx；
- SSD Rx。

校准Scope只证明输入压力是否到位。

真正的Rx结果来自：

- DUT内部可审计Error Counter；
- Loopback；
- Protocol Exerciser；
- 当前CTS认可的测试流程。

不能拿Scope自己的Serial Decode代替正式BER结果。

![Setup：PCIe Rx Stressed Signal校准与DUT接收测试台面](/images/45/fig_setup_rx.png)

### 5.3 Channel：只测无源结构

Channel测试常见对象：

- 主板Trace；
- Via；
- M.2 Socket；
- Connector；
- Breakout；
- Fixture；
- Interposer；
- Retimer前后独立无源段。

常见指标：

- Insertion Loss；
- Return Loss；
- Near/Far-end Crosstalk；
- Differential/Common-mode Conversion；
- Impedance Profile；
- Delay与Skew。

VNA/TDR连接前必须确认：

- DUT断电；
- Active Device隔离；
- 参考面明确；
- Port数量足够；
- Fixture可去嵌；
- 测量不会穿过SoC、SSD、Retimer或Redriver。

不能让VNA“穿过”正在工作的芯片。

## 六、测试环境和仪器怎么搭

### 6.1 Tx正式台面

核心链路：

```text
DUT Tx
  → 当前产品形态的Compliance/Test Fixture
  → 定义Reference Plane
  → 高带宽差分探测/同轴连接
  → Oscilloscope
  → PCIe Compliance Application
```

台面必须明确：

- Root Complex Tx还是Endpoint Tx；
- CEM还是M.2/其他Form Factor；
- Gen4、Gen5还是PAM4代际；
- Lane编号；
- Clock Architecture；
- SSC；
- Pattern与Preset；
- Fixture型号；
- De-embedding文件；
- Scope带宽、采样率和软件版本。

### 6.2 Rx正式台面

```text
Pattern Generator / BERT
  → Jitter / Noise / Stress
  → Loss Channel / Fixture
  → Calibration Scope
  → DUT Rx
  → Loopback / Error Counter
```

校准和正式测试要使用：

- 同一组线缆；
- 同一路径；
- 同一参考面；
- 同一Stress配置；
- 可追溯的Calibration ID。

### 6.3 笔记本M.2系统Debug台面

```text
Laptop Root Complex
  ↔ Motherboard PCIe Lane
  ↔ M.2 Protocol Interposer
  ↔ NVMe SSD

Interposer / Test Point
  → Protocol Analyzer
  → Oscilloscope
  → REFCLK / PERST# / CLKREQ# / PEWAKE#
  → SSD Power
  → Temperature
```

这个台面的关键不是仪器多，而是 **统一时间**。

至少要让下面这些事件可以对齐：

- I/O压力开始；
- SSD温度变化；
- 第一个AER；
- 第一次Replay异常；
- LTSSM进入Recovery；
- Link Speed变化；
- Link Width变化；
- REFCLK变化；
- PERST#动作；
- SSD Power变化；
- 最终掉盘或系统重启。

![Setup：笔记本M.2 PCIe协议、物理层、Sideband、电源和温度同步台面](/images/45/fig_setup_system.png)

### 6.4 Interposer不是“透明空气”

M.2 Interposer会带来：

- 额外Connector；
- 额外Trace；
- 额外Via；
- 额外Loss与Reflection；
- Probe Stub；
- 机械应力和接触变化。

所以必须做三组对照：

1. SSD直插；
2. 插入Interposer但不连接额外Probe；
3. 插入Interposer并连接完整仪器。

如果问题只在第3组出现，先评估测量加载，不要立即宣布原系统失败。

### 6.5 有Retimer时怎么搭

有Retimer时至少拆成：

```text
Segment A：Root Complex ↔ Retimer
Segment B：Retimer ↔ Endpoint
```

两段分别记录：

- Link Speed；
- Link Width；
- Equalization；
- LTSSM；
- Error Counter；
- Clock Architecture；
- Temperature；
- Power。

如果只看Endpoint一侧，就可能把Segment A的问题误判到SSD。

## 八、判据和标准从哪里来

### 8.1 判据层级

PCIe正式判据应按以下层级查找：

1. **PCI Express Base Specification**；
2. **CEM或适用Form Factor规范**；
3. **PHY Test / Compliance Test Specification**；
4. **PCI-SIG Compliance Program**；
5. **授权Compliance软件与Fixture说明**；
6. **项目内部Design Target与System Characterization规则**。

不能拿：

- 某篇博客的示意眼图；
- 某家仪器的旧版截图；
- CEM夹具数据；
- M.2系统Interposer结果；
- 某个SSD跑分；

直接替代当前产品形态的正式判据。

### 8.2 Gen6、Gen7和Gen8的公开边界

截至2026-08-19：

- PCIe 6.0：64GT/s，PAM4、FLIT、FEC、CRC；
- PCIe 7.0：2025年正式发布，128GT/s，延续PAM4与FLIT；
- PCIe 8.0：Draft 0.5，目标256GT/s，计划2028年正式发布。

所以本文：

- 不把Gen7写成普通笔记本M.2当前主流；
- 不把Gen8写成已发布；
- 不公开重构Gen6/7完整PAM4 Compliance Limit；
- 不把Gen4/5 NRZ眼图方法直接套到PAM4。

### 8.3 CEM与M.2不能互相冒充

CEM公开测试资料常见：

- Compliance Base Board；
- Compliance Load Board；
- Add-in Card；
- CEM定义的Reference Plane。

笔记本M.2系统常见：

- M.2 Protocol Interposer；
- M.2专用测试板；
- Multi-lead Probe；
- Sideband、REFCLK和Power同步。

两者都能帮助测试PCIe，但适用产品形态、连接器、Reference Plane和判据不同。

### 8.4 Compliance Pass与系统放行

正式Compliance Pass通常还需要：

- 正确DUT类型；
- 正确代际；
- 正确Fixture；
- 正确Reference Plane；
- 正确Test Mode；
- 正确CTS；
- 正确软件版本；
- 完整Calibration；
- 完整报告；
- 适用的PCI-SIG流程。

系统放行还要额外考虑：

- 热；
- 电源；
- ASPM；
- BIOS/Firmware；
- Driver；
- 互操作；
- 长稳；
- 机械装配；
- 实际M.2 Socket与主板通道。

## 九、报告怎么看

### 9.1 先确认这份报告是否有效

读任何结果前先检查：

- DUT名称、版本和序列号；
- Root Complex还是Endpoint；
- Tx还是Rx；
- Lane与方向；
- Generation；
- Link Speed与Width；
- Clock Architecture；
- SSC；
- Test Mode；
- Pattern/Preset；
- Fixture；
- Reference Plane；
- De-embedding；
- Calibration ID；
- Temperature/Voltage；
- BIOS/Firmware/Driver；
- 软件与CTS版本。

缺这些信息的“Pass”，很难复现。

### 9.2 AER报告不能只数总数

常见AER观察包括：

- Receiver Error；
- Bad TLP；
- Bad DLLP；
- Replay Timer Timeout；
- Replay Number Rollover；
- Correctable；
- Non-Fatal；
- Fatal。

分析时要问：

1. 哪个Root Port或Function报告？
2. 第一条错误是什么？
3. 错误发生前Link处于什么状态？
4. 哪个方向、哪条Lane先异常？
5. 是否同时发生Recovery？
6. Speed或Width何时改变？
7. REFCLK、PERST#、CLKREQ#、Power和Temperature是否先变化？

单看“AER有100条”意义有限。

### 9.3 找第一条异常，不从最后掉盘倒推

典型时间线可能是：

```text
T0  Gen4 x4 / L0 / AER=0
T1  持续混合I/O，SSD温度上升
T2  第一条Receiver Error
T3  Replay或Bad DLLP增加
T4  LTSSM进入Recovery
T5  恢复为Gen3 x4或Gen4 x2
T6  I/O超时
T7  SSD掉盘
T8  系统Reset或重启
```

真正有价值的是T2附近，不是T7。

![图6：脱敏工程示意——AER、LTSSM、Speed、Width、REFCLK、Power和温度统一时间轴](/images/45/ill06_report.png)

![动图：持续负载后第一条错误、Recovery、降速/降宽和掉盘的因果边界](/images/45/anim02_first_error.gif)

### 9.4 如何解读降速与降宽

| 结果 | 说明了什么 | 还不能证明什么 |
|---|---|---|
| Gen4 x4 → Gen3 x4 | 高速相关证据增强 | Gen4 Tx一定Fail |
| Gen4 x4 → Gen4 x2 | Lane相关证据增强 | 某Lane一定开路 |
| Gen4 x4 → Gen3 x2 | 速度与Lane都受影响 | 一定是PCB通道 |
| 关闭ASPM后稳定 | 电源状态相关证据增强 | ASPM实现一定有Bug |
| 冷机正常、热机失败 | 温度相关证据增强 | 一定是热设计 |
| 换SSD后正常 | SSD/互操作相关证据增强 | 原SSD本体一定损坏 |
| 加Interposer后失败 | 测量加载相关证据增强 | 原系统一定没有问题 |

### 9.5 报告里要把“事实”和“假设”分开

推荐写法：

**事实：**

- Gen4 x4在第37分钟出现第一条Receiver Error；
- 240ms后进入Recovery；
- 恢复后Negotiated Link为Gen3 x4；
- REFCLK未观察到中断；
- SSD电源在现有带宽下未观察到掉压；
- 插入Interposer后复现时间缩短。

**假设：**

- 热态Receiver Margin不足；
- Interposer额外Loss放大边界；
- 某Lane均衡结果不稳定；
- SSD Firmware在Recovery路径处理异常。

这两段不能混成一句“确认主板SI问题”。

## 十、常见问题如何Debug

### 10.1 固定总流程

#### 第一步：冻结变量

固定：

- 主板版本；
- BIOS；
- SSD型号与Firmware；
- Driver；
- OS；
- 测试脚本；
- Queue Depth；
- Read/Write比例；
- ASPM；
- Power Mode；
- 环境与器件温度。

#### 第二步：建立统一时间轴

同步采集：

- AER；
- LTSSM；
- Link Speed；
- Link Width；
- REFCLK；
- PERST#；
- CLKREQ#；
- PEWAKE#；
- SSD Power；
- Temperature；
- I/O负载。

#### 第三步：找第一个异常

不要从“SSD消失”开始猜。

先找：

- 第一条Receiver Error；
- 第一次Replay；
- 第一次Recovery；
- 第一次Clock/Power变化；
- 第一条I/O Timeout。

#### 第四步：确定方向和Lane

```text
Root Complex Tx → SSD Rx
SSD Tx → Root Complex Rx
```

结合：

- 哪个Port/Function报告；
- Protocol Trace；
- Lane行为；
- 接收端附近波形；
- 交换设备与主板结果。

#### 第五步：做最小A/B

- Gen5/Gen4/Gen3；
- x4/x2；
- 冷/热；
- ASPM开/关；
- SSD A/B；
- 主板 A/B；
- 直插/Interposer；
- 默认Preset/受控Preset；
- Retimer前段/后段。

#### 第六步：证据指向PHY后再拆Tx/Rx/Channel

- Tx正式测试；
- Rx Stressed Signal；
- Passive Channel；
- Clock；
- Power；
- Protocol；
- Firmware。

#### 第七步：原条件复测

修复后必须恢复：

- 原Generation；
- 原Width；
- 原ASPM；
- 原温度；
- 原负载；
- 原测试时长；
- 原设备组合。

不能用“锁Gen3后不掉盘”当最终修复。

### 10.2 开机不识别

优先顺序：

1. Power；
2. PERST#；
3. REFCLK；
4. CLKREQ#；
5. Detect；
6. Polling；
7. Lane连通；
8. SSD与Socket；
9. BIOS枚举；
10. Protocol Trace。

如果连Detect都没建立，不要先分析Gen4眼图。

### 10.3 只能训练到低速

检查：

- 两端Advertised Capability；
- BIOS限速；
- Firmware限速；
- Recovery与Speed Change；
- Equalization是否完成；
- Gen4/5 Tx；
- 对端Rx；
- Channel Loss；
- REFCLK架构；
- Interposer加载。

降到Gen3后稳定，只说明“高速相关”，不等于已经证明Tx或Channel不合格。

### 10.4 x4变x2

重点看：

- 哪两条Lane保留；
- Lane Mapping；
- Connector接触；
- 某条Lane的Via/Breakout；
- Lane-to-Lane差异；
- Rx Margin；
- Equalization；
- 是否在Recovery后发生宽度变化。

如果总是相同Lane组合消失，物理Lane证据增强；如果Lane组合随设备或温度变化，就要继续排查互操作、训练和测量加载。

### 10.5 AER Correctable持续增加

流程：

1. 记录AER类型；
2. 确认报告对象；
3. 对齐LTSSM；
4. 对齐Replay与协议错误；
5. 对齐Direction与Lane；
6. 对齐温度、Clock和Power；
7. 再决定测Tx、Rx还是Channel。

Correctable不等于“可以忽略”。它可能是Margin恶化最早、最有价值的预警。

### 10.6 睡眠或低功耗退出后掉盘

优先看：

- ASPM状态；
- L1相关进入/退出；
- CLKREQ#；
- REFCLK门控与恢复；
- PERST#；
- SSD Power State；
- BIOS/Firmware时序；
- LTSSM Recovery；
- NVMe Controller Reset。

关闭ASPM后问题消失，只是把调查范围收窄到Power State路径，不是最终根因。

### 10.7 热态长稳失败

同时记录：

- SSD Controller温度；
- NAND温度；
- SoC温度；
- M.2区域板温；
- SSD Power；
- AER；
- Speed/Width；
- LTSSM；
- 风扇与系统Power Mode。

可能的方向包括：

- 热态Tx/Rx Margin变化；
- Channel Loss随温度变化；
- SSD限温策略；
- 电源转换效率和瞬态；
- Firmware超时；
- Interposer接触或加载变化。

不能只贴一个“Thermal Issue”标签结束。

### 10.8 加Interposer后问题才出现

先做：

- Interposer S参数/校准检查；
- 直插与插入对照；
- Probe连接与断开对照；
- Connector清洁和机械压力；
- Cable/Port Mapping；
- De-embedding；
- 降速对照。

如果Interposer引入额外Loss把链路推过边界，它既可能暴露原系统Margin不足，也可能制造测试伪影。报告要同时保留这两种解释，直到有更多证据。

### 10.9 有Retimer的系统

分别回答：

- Root Complex↔Retimer是否稳定？
- Retimer↔Endpoint是否稳定？
- 哪一侧先Recovery？
- 两侧Speed/Width是否一致？
- Retimer Firmware、温度和Power是否相关？
- 加Retimer后问题消失，是重新定时改善，还是Equalization策略改变？

不要把Retimer前后当成一条连续无源Channel。

### 11.1 代际速查

| 代际 | 速率 | 信号/编码 | 公开提醒 |
|---|---:|---|---|
| Gen1 | 2.5GT/s | NRZ、8b/10b | 20%编码开销 |
| Gen2 | 5.0GT/s | NRZ、8b/10b | 20%编码开销 |
| Gen3 | 8.0GT/s | NRZ、128b/130b | 开始高速Equalization |
| Gen4 | 16.0GT/s | NRZ、128b/130b | M.2主案例 |
| Gen5 | 32.0GT/s | NRZ、128b/130b | 高端M.2/平台 |
| Gen6 | 64.0GT/s | PAM4、FLIT、FEC、CRC | 不能再乘2 |
| Gen7 | 128.0GT/s | PAM4、FLIT、FEC、CRC | 2025年正式发布 |
| Gen8 | 目标256.0GT/s | 制定中 | Draft 0.5，目标2028 |

### 11.2 双方向与测试点

| 方向 | 发送端 | 接收端 | 系统Debug优先点 | 关键边界 |
|---|---|---|---|---|
| RC → SSD | Root Complex Tx | SSD Rx | 靠近SSD Rx | 不能冒充RC Tx正式参考面 |
| SSD → RC | SSD Tx | Root Complex Rx | 靠近RC Rx | BGA不可达时写清未覆盖段 |

### 11.3 Tx/Rx/Channel速查

| 项目 | 核心工具 | 正式结果来自 | 不要做什么 |
|---|---|---|---|
| Tx | Scope、Fixture、Compliance软件 | 当前CTS与规定参考面 | 用系统探点替正式参考面 |
| Rx | BERT、Stress Channel、Calibration Scope | DUT Error Counter/Loopback/授权流程 | 用Scope Decode替BER |
| Channel | VNA/TDR、Fixture | 断电无源参考面 | 穿过上电芯片测S参数 |

### 11.4 AER证据速查

| 观察 | 能说明 | 不能直接说明 |
|---|---|---|
| Receiver Error | 接收方向出现可纠正物理层异常证据 | 接收器一定损坏 |
| Bad TLP | TLP完整性异常证据 | 一定是Transaction Layer Bug |
| Bad DLLP | DLLP完整性异常证据 | 一定是Data Link逻辑Bug |
| Replay Timer Timeout | 链路重放/响应路径异常证据 | 一定是单向Tx问题 |
| Non-Fatal/Fatal | 严重度与恢复边界 | 唯一根因 |

### 11.5 LTSSM速查

```text
Detect → Polling → Configuration → L0
                          ↑          ↓
                          └─ Recovery
                               └─ Recovery.Equalization（Gen3+）
```

注意：

- 进入L0不等于长稳；
- Recovery不等于PHY已确认Fail；
- 降速/降宽是恢复结果；
- L0p是PCIe 6.0规范引入、仅在FLIT Mode启用的低功耗活动状态，不能套到传统Gen4/Gen5非FLIT链路。

### 11.6 Linux只读观察命令

查看能力、当前速度、宽度和AER：

```bash
lspci -vv -s 0000:01:00.0
dmesg -T | grep -Ei 'pcie|aer|nvme'
cat /sys/bus/pci/devices/0000:01:00.0/current_link_speed
cat /sys/bus/pci/devices/0000:01:00.0/current_link_width
```

若Kernel与平台公开AER sysfs统计，可检查：

```bash
cat /sys/bus/pci/devices/0000:01:00.0/aer_dev_correctable
cat /sys/bus/pci/devices/0000:01:00.0/aer_dev_nonfatal
cat /sys/bus/pci/devices/0000:01:00.0/aer_dev_fatal
```

路径与文件是否存在取决于Kernel、设备和AER支持。文章只推荐只读观察，不建议为了测试随意改写PCIe配置寄存器。
