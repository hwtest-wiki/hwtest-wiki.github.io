# 同样一根 USB-C 线，为什么有的 100W 快充、有的只有 5V？——从 CC、PD 报文到 VBUS 的一致性测试

<div class="article-meta"><span class="badge">📘 模块六 · 高速接口一致性测试 · 第 5 篇 · USB 家族第 3 篇 · USB Type-C / USB PD</span><span class="badge">⏱ 约 27 分钟</span><span class="badge qr">🔧 含工程师速查</span></div>


先看一个常见现象。

同一台笔记本、两个都标称 100W 的充电器，只换一根 USB-C 线：一套能进入 20V 大功率档，另一套却始终停在 5V。原因不一定是“线差”或“充电器功率虚标”，而可能发生在四个不同层级：

1. **Type-C 连接没建立好**：Rp/Rd、方向、CC1/CC2 或接触有问题。
2. **线缆能力没识别出来**：VCONN、e-marker、SOP′ 通信或线缆额定电流/电压不满足。
3. **PD 协议没谈成**：PDO 与 RDO 不匹配，消息超时、CRC、MessageID 或状态机异常。
4. **合同谈成但电没送对**：VBUS 转换、稳态精度、负载瞬态、限流或 PS_RDY 时序失败。

因此，**“只有 5V”只是现象，不是根因**。调试时不能直接换线碰运气，而要先确认失败发生在哪一层。

## 一、USB-C 与 USB PD 到底分别定义什么

把 USB-C 简化成“插座”、把 USB PD 简化成“谈判”，适合入门记忆，但不够工程化。

**USB Type-C 是一套连接器与连接管理规范。** 它不仅定义 24 针、正反插和线缆结构，还定义：

- CC1/CC2 上的 **Attach、Detach、方向识别和去抖**；
- Source、Sink、DRP 的初始连接行为；
- Default、1.5A、3A 的 **Type-C 电流广播**；
- 哪一端提供 VCONN，以及如何发现需要 VCONN 的线缆或附件；
- 数据路径翻转，以及进入 USB4 / Alternate Mode 等高级功能所需的基础连接行为。

**USB PD 是运行在已建立的 Type-C CC 通道上的电源与控制协议。** 它定义：

- BMC 物理层和报文格式；
- Source_Capabilities、Request、Accept、PS_RDY 等消息；
- PDO、RDO、SPR、EPR、PPS、AVS 等供电能力；
- GoodCRC、重试、Soft Reset、Hard Reset 和错误恢复；
- Power Role、Data Role、VCONN Source 的交换，以及其他扩展控制能力。

所以二者关系不是“外壳和软件”这么简单，而是：

> **Type-C 先建立一条合法连接，PD 再在这条连接上协商并管理更高功率。**

同一个 USB-C 口完全可能只接 USB 2.0 数据、只提供 5V，也可能支持 USB4 和 240W；**接口长得一样，不代表数据能力、供电能力和线缆能力一样。**

还要避免把三种充电机制画成必然逐级回退的楼梯：

| 机制 | 使用通道 | 解决的问题 | 典型边界 |
|---|---|---|---|
| USB BC1.2 | D+ / D− | 传统 USB 充电端口识别 | 5V，DCP/CDP 可到 1.5A |
| USB Type-C Current | CC 上的 Rp / Rd | 未建立 PD 合同时广播 Default / 1.5A / 3A | 5V，最高 3A |
| USB PD | CC 上的 BMC 报文 | 协商更高电压、功率和角色 | SPR 最高 100W，EPR 最高 240W |

它们可以共存，但**不是所有产品都按“PD失败→Type-C→BC1.2”一路回落**。PD 失败后的可用电流要看端口类型、Rp 广播、USB 模式和产品策略，不能只写成“统一退回5V慢充”。

## 二、CC1 / CC2：先建立连接，再谈功率

### 1. Rp 与 Rd 决定初始 Source / Sink 关系

连接前，Source 在 CC1、CC2 上呈现 Rp；Sink 在 CC1、CC2 上呈现 Rd。插头插入后，Source 在其中一路检测到 Rd，据此确认 Sink 已连接并识别方向；另一侧 CC 位置可用于 VCONN。

这里要注意三个工程边界：

- “纯电阻分压”描述的是**电气模型**，真正产品仍需要比较器、Type-C/PD 控制器和去抖状态机。
- Source 侧允许电阻上拉或等效电流源实现，不能把“56kΩ”当成任何上拉电压下都通用的唯一阻值。
- 当前 R2.5 中，能够检测 Type-C 电流档位的 Sink 电阻实现是 **5.1kΩ ±10%**；**5.1kΩ ±20%** 仍可用于连接检测，但不保证能可靠区分三档电流广播。

当前 Type-C R2.5 给出的 Source 端典型实现为：

| 广播能力 | 等效电流源 | Rp接4.75～5.5V | Rp接3.3V±5% |
|---|---:|---:|---:|
| Default USB Power | 80µA ±20% | 56kΩ ±20% | 36kΩ ±20% |
| 1.5A @ 5V | 180µA ±8% | 22kΩ ±5% | 12kΩ ±5% |
| 3.0A @ 5V | 330µA ±8% | 10kΩ ±5% | 4.7kΩ ±5% |

因此，只写“Rp=56k/22k/10k”是不完整的；**先看上拉电源和实现方法，再选阻值。**

### 2. Sink 读取的不是三个理想点，而是三个容差带

对采用 5.1kΩ ±10% Rd、并支持电流档位检测的 Sink，R2.5 示例计算给出的 CC 电压范围是：

| Sink 识别结果 | vRd 范围 |
|---|---:|
| Default USB Power | **0.277～0.612V** |
| 1.5A @ 5V | **0.746～1.164V** |
| 3.0A @ 5V | **1.369～2.042V** |

0.613～0.745V、1.165～1.368V 是判决阈值可放置的区间，不应被写成另一档有效电压带。0.41V、0.92V、1.68V只是 80/180/330µA 乘以 5.1kΩ 得到的**理想示例点**，不能代替容差判据。

更重要的是：这张表是 **Sink 读取 Source 电流广播**的范围，不能反过来拿它直接判断 Source 看见的是 Ra、Rd 还是 Open。Source 端 Attach / Cable 检测有自己的阈值模型。

### 3. VCONN、Ra 与 e-marker

对有电子器件的线缆或附件，未被用作端口间 CC 通信的另一侧 CC 位置可由 VCONN Source 提供 VCONN。Powered Cable 在 VCONN 侧呈现 Ra，R2.5 的 Ra 等效阻抗范围为 **800Ω～1.2kΩ**。

几个容易混淆的结论：

- **5A 线缆必须电子标记**，端口需要读取其电流能力。
- 进入 EPR 还要确认线缆报告 **5A、50V、EPR Capable** 等能力；不是“有 e-marker 就一定能跑240W”。
- 没有电子标记并不等于“线一定差”，但不能把它当作 5A / EPR 线使用。
- SOP′ 面向靠近发起端的 Cable Plug；SOP″ 面向另一端 Cable Plug，常见于具有两端电子器件的有源线缆。不能把 SOP′ / SOP″都笼统写成“给同一颗 e-marker 说话”。

## 三、PD 协议：不只是四条消息

### 1. BMC 是真实的物理层，也要过眼图

USB PD 在 CC 上使用 BMC 编码，标称位速率 **300kb/s**。当前规范的发送位速率范围为 **270～330kb/s**，对应 UI 约 **3.70～3.03µs**；3.33µs只是标称值。

BMC 的基本编码规则仍然是：

- 每个位边界发生翻转；
- 逻辑1在位中间额外翻转一次；
- 逻辑0在位中间不翻转。

但一致性测试远不止拿示波器量一个 3.33µs：

- 位速率与包内漂移；
- 发送眼图掩模；
- 上升/下降沿与摆幅；
- 接收测试信号；
- Collision Avoidance；
- 两个插入方向和适用的 VCONN 条件。

PD CTS Q3 2026 的 `TEST.PD.PHY.ALL.2` 就是 **Transmitter Eye Diagram**。所以这篇准确的定位应是：

> **高速数据眼图不再是主角，但低速 BMC 物理层仍然要看眼图。**

### 2. PDO、RDO 与 Explicit Contract

Source 用 PDO 描述能力，Sink 用 Request 中的 RDO 选择对象并声明需求。最常见的供电类型包括：

- **SPR Fixed PDO**：按端口 PDP 遵守 Power Rules。当前规则不是所有产品都无条件提供5/9/15/20V，而是随端口功率逐级要求相应固定档。
- **SPR PPS APDO**：电压编程步进为20mV，PPS RDO电流按50mA粒度请求，并支持可编程限流。
- **SPR AVS / EPR AVS**：可调电压供电，但行为和 PPS 不完全相同，不能都叫 PPS。
- **EPR Fixed PDO**：加入28V、36V、48V，最高可到240W。

PD 3.1在2021年引入EPR；本文审校使用的当前基线已经是 **USB PD R3.2 v1.2（2026-05-20）**。工程报告必须写清实际采用的规范版本，不能只写“PD 3.1”后把所有新旧时序混在一起。

一次典型 SPR Fixed 合同建立可以简化成：

1. Source 发送 `Source_Capabilities`。
2. Sink 发送 `Request`，RDO 指向某个 PDO。
3. Source 校验请求后回复 `Accept`、`Reject`、`Wait` 或其他适用响应。
4. 若接受，Source 按要求转换 VBUS。
5. 电源达到有效范围后，Source 发送 `PS_RDY`。

`Accept + PS_RDY` 之后才建立或更新 Explicit Contract。只看到 Accept，不代表20V已经到位。

### 3. GoodCRC、协议重试与策略响应不是同一个计时器

原文把 `tReceive=1.1ms`、`tSenderResponse=24～30ms` 和“重发3次”放在一张表里，容易造成三个误解。按 R3.2 v1.2：

| 机制 | 当前关键值 | 正确含义 |
|---|---:|---|
| `tTransmit` | **≤195µs** | 接收方收到消息后，应在该时间内开始发送 GoodCRC 前导码 |
| `tReceive` | **0.9～1.1ms** | 发送方 CRCReceiveTimer 的实现容差；不是“DUT可以等1.1ms才回GoodCRC” |
| `nRetryCount` | **2** | 普通消息在收不到匹配GoodCRC时最多重试2次；Cable Plug和部分扩展消息有例外 |
| `tReceiverResponse` | **≤15ms** | 收到需要策略响应的消息后，响应方应在该时间内开始发送响应 |
| `tSenderResponse` | **27～50ms** | 请求发送方的等待计时器容差；不是DUT的“27～50ms合规响应窗” |

最关键的测试原则是：

> **测响应方是否合规，要看 `tReceiverResponse`；分析请求方何时可能放弃，才看 `tSenderResponse`。**

15～27ms内才发Accept，可能仍能与某些对端通信，但响应方已经违反15ms要求；到了27ms后，请求方的计时器可能开始到期；50ms后仍未收到预期响应，则任何合规的该计时器实现都已超时。超时后的动作还要看具体消息和状态，不能一概写成“立刻Hard Reset”。

如果收不到 GoodCRC，协议层在重试用尽后通常先进入 **Soft Reset**；Soft Reset 仍失败，才进一步进入 Hard Reset 或相应错误恢复。Hard Reset 会让供电回到 USB Default Operation，但过程包含 VBUS 到 vSafe0V、再恢复 vSafe5V，不能画成“电压从头到尾一直停在5V”。

## 四、VBUS：合同谈成以后，电还要真的送对

以20V Fixed PDO为例，当前规范中 `vSrcNew` 是 PDO 电压的 **±5%**，即在 Source receptacle 测得 19.0～21.0V。这只是供电检查的一部分，还要同时看：

- 切换开始前是否给 Sink 留出 `tSrcTransition`；
- 正、负压摆率是否满足 `vSrcSlewPos / vSrcSlewNeg`，当前上限为 **±30mV/µs**；
- 过渡期间是否留在 `vSrcValid` 允许范围；
- Source 是否在 VBUS 有效之前错误地发送 `PS_RDY`；
- Fixed PDO请求后，Source 是否在 `tSrcTransReq` 内开始发送 `PS_RDY`：
  - SPR：**≤325ms**
  - EPR或涉及EPR的转换：**≤760ms**
- Sink 的 `PSTransitionTimer` 是否正确作为等待 PS_RDY 的保护计时器：
  - SPR：450～550ms
  - EPR：830～1020ms
- 负载阶跃、线缆压降、PPS限流和持续供电是否满足适用测试。

这解释了为什么“550ms内到20V”不是一个完整判据：**325ms是Source发送PS_RDY的要求，450～550ms是Sink等待超时计时器的容差，二者测试对象不同。**

原文中的 **0.12V/ms甜点区、22V OVP、5.5A OCP** 不是USB PD通用一致性限值：

- 0.12V/ms只是某个教学环路模型的设计点，不是规范推荐值；
- Sink是否实现OVP以及其触发点属于端口/系统设计，不能统一写成22V；
- OCP或Current Limit要依据供电类型、PDO/RDO、VIF、DUT额定值和产品安全要求，不能统一写成5.5A。

它们可以作为某个具体DUT的设计验证条件，但必须标成 **产品规格值**，不能放进“USB-IF通用判据”栏。

## 五、到底测什么：按 CTS 分成物理层、协议层、供电层

当前 USB PD CTS 的主体就是三类测试；Type-C 端口还要结合 Type-C Functional CTS 和产品矩阵确定适用项。

### 1. Physical Layer

- BMC位速率和漂移；
- Transmitter Eye Diagram；
- 上升/下降沿、摆幅；
- 接收能力；
- Collision Avoidance；
- 适用时覆盖两种插入方向、VCONN电压和线缆端。

### 2. Protocol

- Header、MessageID、CRC、GoodCRC；
- PDO/RDO内容与对象位置；
- 正常AMS消息顺序；
- Reject、Wait、Not_Supported等分支；
- 重试、Soft Reset、Hard Reset、Cable Reset；
- PR_Swap、DR_Swap、VCONN_Swap；
- SOP、SOP′、SOP″各自状态机；
- EPR进入、保持、退出及线缆发现。

### 3. Power Supply

- Fixed / PPS / AVS / EPR各自电压与电流能力；
- 电压转换、压摆率、PS_RDY顺序；
- 负载阶跃和稳态精度；
- PPS Current Limit；
- Source、Sink和线缆压降相关要求；
- Hard Reset、角色交换和异常状态下的VBUS行为。

## 六、怎么测：先冻结能力声明，再跑两种方向和正常/异常路径

### 第0步：先确认“测的到底是什么”

测试前先冻结：

- UUT是Port、Cable、VPD还是eMarker；
- Source Only、Sink Only、DRP中的哪一种；
- Data Role、Power Role、VCONN Source能力；
- PD Revision、SPR/EPR、PPS/AVS；
- Source/Sink PDO、APDO、最大PDP；
- Captive Cable还是可拆线；
- 支持的Swap、Alternate Mode和异常恢复能力。

这些信息进入 **VIF（Vendor Info File）**。CTS根据VIF决定测试适用性；VIF填错会导致：

- 本来不适用的项目被错误执行；
- 应测项目被跳过；
- DUT真实报文与声明不一致；
- 报告全绿，但产品能力并未被完整覆盖。

### 第1步：Type-C连接与线缆矩阵

至少覆盖：

- 插头两个方向；
- 已知良好的3A线和5A电子标记线；
- 若支持EPR，再加入合格EPR线；
- Source/Sink/DRP适用的Attach、Detach和角色组合；
- CC1、CC2、VCONN和SOP′发现。

### 第2步：PD物理层

使用合规测试仪/夹具和示波器，执行BMC位速率、发送眼图、沿、接收和Collision Avoidance。夹具附加电容、接地点和CC分接方式都会直接影响结果。

### 第3步：协议正常路径

让测试仪扮演对端，按VIF遍历PDO/APDO和角色。协议分析仪记录：

- 原始报文；
- SOP类型；
- MessageID和CRC；
- GoodCRC；
- 每条消息的起止时间；
- 状态机分支和Reset。

### 第4步：供电与负载

把协议Log与示波器的CC/VBUS波形做时间关联，验证：

- Accept之后何时开始切换；
- VBUS何时进入有效范围；
- PS_RDY是否过早或过晚；
- 各合同下的稳态电压、电流和负载瞬态；
- PPS限流或适用的产品保护。

### 第5步：异常路径

主动注入：

- 不支持的RDO或越界请求；
- 丢失/错误GoodCRC；
- 重复MessageID、错误CRC、乱序消息；
- 响应超时；
- Soft Reset、Hard Reset；
- 拔插、翻转方向、换3A/5A/EPR线；
- PR_Swap、DR_Swap、VCONN_Swap；
- 若支持FRS，再执行专用FRS测试。

## 七、Fail怎么Debug：先找Log停止点，再做单变量区分实验

### 现象1：插上完全不供电

**先看：** VBUS是否始终为0、CC1/CC2哪一路检测到Rp/Rd。

**区分实验：**

1. 翻转插头。如果只坏一个方向，优先查单侧CC、连接器、ESD器件或控制器引脚。
2. 换已知良好的被动3A线。如果仍不Attach，问题更可能在端口Rp/Rd或VBUS开关。
3. 直接量CC电压并对照Source/Sink端各自阈值，不要拿Sink的vRd电流带判断Source Attach。

### 现象2：Attach成功，但始终没有Source_Capabilities

**先看：** 协议分析仪有没有BMC前导码、错误CRC或重复重发。

**区分实验：**

1. 看PD发送眼图、位速率、沿和摆幅；如果物理层失败，先不要查PDO。
2. 降低夹具附加电容或换认证夹具，排除测量系统把CC沿拖慢。
3. 分别测试两个方向，定位CC1/CC2通道差异。

### 现象3：有Source_Capabilities，但Sink不发Request

**先看：** Source提供了哪些PDO/APDO，Sink期望的电压、电流和功率是否真的存在。

**区分实验：**

1. 用已知良好的标准Source驱动该Sink。
2. 比较VIF、抓包中的PDO与产品声明。
3. 检查Sink算法是否错误选择Object Position，或因Cable Current能力降低请求。

### 现象4：Request之后收到Reject / Wait / Not_Supported

**先看：** RDO是否超出目标PDO，EPR模式和线缆发现是否完成。

**区分实验：**

1. 把请求降到5V/3A或其他确定支持的SPR档；若通过，问题在高功率能力链。
2. 依次换3A线、5A e-marked线、EPR线，并看SOP′ Discover Identity结果。
3. 检查5A、50V、EPR Capable等Cable VDO字段，而不是只看“有没有e-marker”。

### 现象5：Accept之后没有PS_RDY，或VBUS不对

**先看：** VBUS是否开始切换、何时进入vSrcNew、PS_RDY何时发送。

**区分实验：**

1. 空载和额定负载各跑一次；只在负载下失败，优先查电源能力、线损和限流。
2. 在DUT receptacle与负载端同时量电压，分离DUT误差和线缆压降。
3. 对照 `tSrcTransition`、压摆率、`tSrcTransReq`，并确认PS_RDY没有早于VBUS有效。

### 现象6：大量重试、Soft Reset或偶发掉线

**先看：** 哪条消息收不到匹配MessageID的GoodCRC，错误是否固定在某一方向或某一种线。

**区分实验：**

1. 看原始BMC波形与发送眼图，而不只看解码后的“CRC Error”。
2. 换短线、已知良好线和低容性夹具。
3. 检查MessageID、Duplicate Message处理、Collision Avoidance和重试次数。
4. Soft Reset能恢复而Hard Reset才恢复，分别指向协议同步问题和更深的状态/电源恢复问题。

### 现象7：5A / EPR失败，3A SPR正常

**先看：** VCONN是否建立、SOP′线缆发现返回了什么。

**区分实验：**

1. 同一DUT仅换线缆能力，保持负载和请求不变。
2. 测VCONN电压和Cable Discover Identity。
3. 确认线缆电流、最大VBUS电压、EPR能力与DUT声明一致。

### 现象8：角色交换失败

不要只写“DRP死锁”。先明确失败的是：

- `PR_Swap`：Source / Sink交换；
- `DR_Swap`：DFP / UFP数据角色交换；
- `VCONN_Swap`：VCONN Source交换。

三个维度相互独立。一次Swap失败，不代表另外两个角色也应改变。

## 八、复测闭环：怎样证明“真的修好了”

修完一个Fail后，至少完成四层复测：

1. **原失败用例复测**：同方向、同线缆、同PDO/RDO、同负载和同异常注入。
2. **相邻边界复测**：另一个插入方向、前后一个功率档、3A/5A线、空载/满载。
3. **异常恢复复测**：Soft Reset、Hard Reset、Detach/Reattach及适用的Swap。
4. **声明一致性复测**：VIF、产品规格、抓包能力和最终报告一致。

报告中必须能回答：

- 测的是哪个端口、哪个方向、哪根线；
- UUT当时的Power Role、Data Role和VCONN Source是谁；
- 使用哪个PDO/APDO与RDO；
- Fail停在哪条报文或哪个VBUS时刻；
- 做了什么单变量实验；
- 修改后原用例与邻近用例是否都通过。

## 九、一句话总结

USB Type-C / USB PD一致性测试，不是“看见20V就算快充成功”，也不是“只抓四条协议消息”。

> **Type-C先建立合法连接，PD再通过BMC物理层、协议状态机和供电转换建立合同。真正有效的测试，是把VIF、CC1/CC2、线缆身份、SOP类型、PDO/RDO、GoodCRC、Reset和VBUS波形放到同一条时间线上。**
