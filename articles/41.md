# 同样一台高刷显示器，为什么厂商都让你"用 DP 线、别用 HDMI"？——DisplayPort：天生就是嵌入式时钟 + 打包传输，一致性测法和 HDMI 差在哪

先说个很多人都纳闷过的现象。

你买了台高刷电竞显示器，标称 **2K 165Hz** 或 **4K 144Hz**。说明书、客服、甚至显示器背后的贴纸都在提醒你：**"高刷请用 DP 线，HDMI 口可能只能到 60Hz / 120Hz"**。你半信半疑地插了 HDMI，果然——刷新率选项里最高就卡在 60Hz，怎么都上不去；换上附带的那根 DP 线，165Hz 一下就出来了。

再比如，办公室里有人用**一根线从显示器 A 又接出一根到显示器 B**，两台屏都正常显示不同画面——这在 HDMI 上是做不到的。还有你手上这台笔记本，合盖不断电、静态桌面时特别省电、屏幕却一直亮着……

这些看似不相干的现象，背后其实是**同一个接口**在撑：**DisplayPort**。它和 HDMI 长得像、都能投屏，但**骨子里是另一套架构**。而测试工程师要保证"这个 DP 口 / 这块笔记本屏，跟全世界的显示设备都能通、都能跑到标称的高规格"，用的又是和 HDMI 部分重叠、部分不同的一套测法——**这，就是这一篇要讲的。**

不过在讲测法之前，先把第一个现象的玄学去掉。**2K 165Hz、8bit 色深，算下来需要 16.0 Gbps 的有效带宽。**HDMI 1.4 有效带宽只有 8.2 Gbps，不够；HDMI 2.0 是 14.4 Gbps，还差一点；DP 的 HBR2 有 17.3 Gbps，够了；HBR3 更是 25.9 Gbps，富余很多。**厂商让你用 DP，是一道减法题算出来的结果。**（这几个数字后面第三节还会再出现一次，它们全部来自同一份带宽模型，不是从产品页上抄的。）

![图1：DisplayPort 翻车/能力现场。左：同一台 2K165 电竞显示器，插 HDMI 口→刷新率被锁 60/120Hz 上不去；插 DP 线→165Hz 一把拉满。中：一根线从显示器 A 串接到显示器 B，两屏各显示不同画面（HDMI 做不到）——这是 DP 的 MST 菊花链。右：笔记本合盖不断电、静态桌面屏幕常亮却特别省电——那是屏里那条看不见的 eDP 在做 Panel Self Refresh。下半部分把第一个现象的玄学换成一道减法题：2K165、8bit 色深算下来需要 **16.0 Gbps** 有效带宽（图上那条虚线），四根柱子分别是 HDMI 1.4 的 8.2 Gbps ✗、HDMI 2.0 的 14.4 Gbps ✗、DP HBR2 的 17.3 Gbps ✓、DP HBR3 的 25.9 Gbps ✓。厂商让你用 DP，是算出来的，不是玄学。一句话：DP 和 HDMI 长得像，骨子里是另一套架构，测法也另成一路](/images/41/ill01_pain.png)

## 一、先认清主角：DisplayPort 是什么、身边到处都是它

**DisplayPort（DP）** 和 HDMI 一样，是把**视频 + 音频 + 控制信息**打包、在一个"源"和一个"显示端"之间传输的显示接口，由 **VESA（视频电子标准协会）** 制定。术语上同样分 **Source（源，如显卡 / 笔记本）** 和 **Sink（宿 / 显示端，如显示器 / 内屏）**。

它到底有多常见？其实比你以为的还多：

- **台式机显卡 + 电竞 / 专业显示器**：高刷、高分辨率、多屏，基本走 DP。
- **笔记本外接屏**：无论是 Mini DP 口，还是现在最普遍的 **USB-C 口投屏（DP Alt Mode）**，底层跑的都是 DisplayPort〔见第 39 篇 USB-C：DP Alt Mode 就是把 DP 塞进 USB-C 口〕。
- **笔记本 / 平板 / 手机自己的那块内屏**：几乎全是 **eDP（Embedded DisplayPort，嵌入式 DP）** 驱动的——你天天盯着看，却从没见过那根线，因为它直接焊在主板到屏之间。

和刚讲完的 HDMI 相比，DP 有三个鲜明特点，直接决定了它怎么测：

- **它天生就是"嵌入式时钟"的**：DP 从第一版起就**没有独立时钟线**，接收端一律靠 **CDR（时钟数据恢复）** 从数据里捞时钟。这一点 HDMI 到 2.1 的 FRL 才做到，DP 一出生就是。
- **它是"打包（packet）传输"的**：DP 把像素、音频、控制切成一个个微包（micro-packet）在链路上跑，不是 HDMI TMDS 那种"逐像素连续流"。正因为打包，它才能玩 **MST 菊花链**（一根线带多屏）和 **DSC 压缩**。
- **它自带一条能读能写的边带 AUX**：两端靠这条低速**双向**通道读 EDID、读写寄存器（DPCD）、做 link training、协商 HDCP——很多"掉刷新率 / 认不出屏"就死在 AUX 上。

![图2：认清 DisplayPort 主角。中间一条 DP 链路连 Source（显卡/笔记本）→ Sink（显示器/内屏）。三件套画清楚：①Main Link（主链路，最多 4 lane、高速差分、单向送像素+音频+控制）②AUX（辅助通道，低速双向：读 EDID、读写 DPCD 寄存器、link training、HDCP 协商）③HPD（热插拔检测线）。旁边标身边场景：电竞/专业显示器、USB-C 投屏（DP Alt Mode，见第39篇）、笔记本内屏 eDP。底部点出三大结构特征：①天生嵌入式时钟→靠 CDR；②打包传输→能玩 MST/DSC；③AUX 双向→能力协商与训练都走它，很多"掉刷新率"死在这条道上](/images/41/ill02_whatis.png)

## 二、原理与演进：从出生就是"嵌入式时钟 + 打包"

### 2.1 三件套：Main Link + AUX + HPD

一条 DP 链路，物理上就三部分：

- **Main Link（主链路）**：**1 / 2 / 4 条 lane**（每条一对高速差分），**单向** Source→Sink，扛所有像素 + 音频 + 控制。lane 越多、每 lane 速率越高，能带的分辨率 / 刷新率就越高。
- **AUX Channel（辅助通道）**：一条**低速、双向（半双工）**的小道，负责读 **EDID**（显示器报家底）、读写 **DPCD**（DP 配置状态寄存器）、跑 **link training**、协商 **HDCP** 内容保护。它跑不了视频，却是"能不能协商到高规格"的命门。
- **HPD（Hot Plug Detect，热插拔检测）**：一根信号线，告诉 Source"屏插上 / 拔了 / 有事要报"。

### 2.2 关键分水岭：一直是嵌入式时钟 + CDR（对比 HDMI TMDS）

这是 DP 和 HDMI 最本质的区别，也是它测法路数的根源：

- **HDMI 老的 TMDS**：单独拉一根时钟线转发过去，接收端拿这根时钟直接采样（源同步）。到 HDMI 2.1 的 FRL 才改成嵌入式时钟。
- **DisplayPort：从 DP 1.1 第一版起，就没有独立时钟线。** 时钟是**埋在数据里**的，接收端全靠 **CDR** 从数据流的跳变里把时钟"捞"出来，再拿它采样。

一句话：**DP 一出生就站在"嵌入式时钟 + CDR"这一岸**，也就是 USB 3.x / PCIe 那一路。这直接决定了——**DP 的接收端一定有 CDR、有均衡，一致性测试一定看眼图、要做抖动分离、要用参考均衡还原**，从 HBR 时代就是如此，跟速率高低无关。

> 💡 回到速查 02 的地图：HDMI 是**在分水岭上走了个来回**（TMDS 在"看时序"这侧、FRL 跨到"看眼图"那侧）；**DP 则从头到尾都在"嵌入式时钟 + CDR + 看眼图"那一侧**。所以你会发现，DP 的测法几乎就是 HDMI FRL 那一半的"完整版 + 从头贯彻"。学会一个，另一个就通了大半。

### 2.3 打包传输 → 菊花链 MST 与压缩 DSC

因为 DP 是**打包（micro-packet）**传输而不是连续像素流，它天生能干两件 HDMI 早期干不了的事：

- **MST（Multi-Stream Transport，多流传输）**：一条链路上可以塞**多路独立的视频流**，配合 Hub 或支持菊花链的显示器，**一根线串接多台屏**、各显示各的画面。办公室"一根线带俩屏"就是它。
- **DSC（Display Stream Compression，显示流压缩）**：VESA 定义的**视觉无损**压缩，把像素流压小后再传。带宽不够上 8K / 高刷时，靠 DSC 把数据塞进有限的 lane 里。**注意：一致性测试里，开不开 DSC、压缩比多少，是链路层要单独验证的一项。**

![图3：DP 的两大骨架。上半——时钟架构分水岭对比：HDMI TMDS = 3 数据 + 1 根独立时钟线转发（源同步，接收端不用 CDR）；DisplayPort = 只有数据 lane、时钟埋在数据里、接收端靠 CDR 捞（嵌入式，从 DP 1.1 起就是）。用一条竖虚线把两者分在"看时序 vs 看眼图/CDR"两岸，标注"DP 一直在右岸、HDMI 到 FRL 才过河"。下半——打包传输带来的能力：micro-packet 微包流 →①MST 菊花链（一根线 A→B→C 串多屏，各显各的）②DSC 视觉无损压缩（像素流压小塞进有限 lane，上 8K/高刷靠它）](/images/41/ill03_arch.png)

## 三、版本与速率：从 HBR 到 UHBR，编码换了、还加了 FEC

DP 的速率演进，可以按"编码方式"劈成两段：**8b/10b 的 HBR 时代**和 **128b/132b 的 UHBR 时代**。

| 版本 | 链路速率档 | 每 lane 速率 | 编码 | 4 lane 原始 / 有效带宽 |
|---|---|---|---|---|
| DP 1.1 | HBR | 2.7 Gbps | 8b/10b | 10.8 / 8.64 Gbps |
| DP 1.2 | HBR2 | 5.4 Gbps | 8b/10b | 21.6 / 17.28 Gbps |
| DP 1.3 / 1.4 | HBR3 | 8.1 Gbps | 8b/10b | 32.4 / 25.92 Gbps（+DSC 上 8K） |
| DP 2.0 / 2.1 | UHBR 10 | 10 Gbps | 128b/132b | 40 / 38.79 Gbps |
| DP 2.0 / 2.1 | UHBR 13.5 | 13.5 Gbps | 128b/132b | 54 / 52.36 Gbps |
| DP 2.0 / 2.1 | UHBR 20 | 20 Gbps | 128b/132b | 80 / 77.58 Gbps |

几个要点：

- **HBR / HBR2 / HBR3 用 8b/10b**，每 10 bit 里 8 bit 是数据，20% 开销——和 HDMI TMDS、USB 3.0 Gen1 一个套路。HBR3（8.1G/lane）是 8b/10b 时代的顶，配 DSC 才够上 8K。
- **UHBR（DP 2.0 起）换成 128b/132b**，开销从 20% 骤降到约 3%（效率 ~97%），和 USB4 / PCIe 6.0 之前那类思路一致。**UHBR20 四条 lane = 80 Gbps 原始、77.58 Gbps 有效**，是目前 DP 的天花板，够 **8K60 HDR 10bit（约 61.8 Gbps）/ 双 4K** 这种夸张规格。
- **UHBR 强制上 FEC（前向纠错）**：速率高到这个份上，误码难免，FEC 让接收端能**当场纠错、不用重传**。测试时 FEC 的行为也要单独验。

> ⚠️ 老规矩，**带宽别套错公式**（见速查 02 / 第 29 篇）：UHBR20 的 20 Gbps/lane 是**串行波特率**，测眼图的示波器带宽按"约 0.7～1 倍波特率"选（十几到几十 GHz 档），**不是**拿"上升时间 5 倍谐波"去套出个吓人的两三百 GHz。串行高速看眼图，不是看方波谐波。

![图4：DP 版本与速率阶梯。横向时间轴从左到右：DP1.1 HBR 2.7G/lane → DP1.2 HBR2 5.4G → DP1.3/1.4 HBR3 8.1G（这三档统一 8b/10b、20% 开销，虚线框「8b/10b 时代」；HBR3 配 DSC 才够 8K）→ 一道竖分界线「换编码 + 加 FEC」→ DP2.0/2.1 UHBR10 10G / UHBR13.5 13.5G / UHBR20 20G（实线框「UHBR 时代：128b/132b、~3% 开销、强制 FEC」）。每档旁标 4 lane 总带宽：10.8/21.6/32.4G → 40/54/80G。右端大字标 UHBR20×4=80G 原始、约 77.4G 有效（8K120/双 4K）。底部一句：编码从 20% 开销降到 3%，是 DP 冲上 80G 的关键](/images/41/ill04_versions.png)

### 3.1 速率翻上去，判据也换了一把尺子

光看表格容易得出一个错觉：**"速率越高越好，无非是眼睛小一点"**。真跑一遍就知道不是这样。

下面这张动图，**线不换、摆幅不换、预加重不换，只把速率档从 HBR 一路推到 UHBR20**，同时给出两只眼：左边是探头直接抓到的**裸眼**，右边是**过了规范写死的参考接收器（CTLE 4 dB + DFE 2 抽头）之后**的眼。

一根 1.5 m 的普通线，跑出来是这样的：

| 速率档 | 裸眼高 / 眼宽 | 过参考接收器后 | 该用哪把尺子 | 结果 |
|---|---|---|---|---|
| HBR 2.7 G | 593 mV / 0.85 UI | 同左 | HBR：280 mV × 0.45 UI | PASS |
| HBR2 5.4 G | 597 mV / 0.74 UI | 同左 | HBR：280 mV × 0.45 UI | PASS |
| HBR3 8.1 G | 371 mV / 0.65 UI | 同左 | HBR：280 mV × 0.45 UI | PASS |
| **UHBR10 10 G** | **207 mV / 0.47 UI** | **356 mV / 0.53 UI** | UHBR：55 mV × 0.30 UI | **PASS** |
| UHBR13.5 13.5 G | 0（闭死） | 149 mV / 0.18 UI | UHBR：55 mV × 0.30 UI | FAIL（眼宽不够） |
| UHBR20 20 G | 0（闭死） | 0（闭死） | UHBR：55 mV × 0.30 UI | FAIL |

看 **UHBR10 那一行**：裸眼 207 mV —— 如果你顺手拿 HBR 那把 280 mV 的老尺子去扣，**它当场不合格**。（顺带留意一个细节：它的裸眼**眼宽** 0.47 UI 其实是过 0.45 那条线的，**真正判死它的只有眼高这一项**——所以图上这两个数是分开上色的，一红一绿。）可它其实是好的：过一遍参考接收器，眼高变成 356 mV，用 UHBR 自己那把 55 mV × 0.30 UI 的尺子扣，**裕量大得很**。

**这就是 DP 一致性测试最容易被搞错的一件事**：HBR 系和 UHBR 系不只是数字不同，**测量参考面根本就在不同位置**——HBR 扣的是探头抓到的裸眼，UHBR 扣的是"参考接收器输出上"的眼。拿裸眼去扣 UHBR 模板，**没有一颗芯片过得了**。

再看最后两行：同样这根线，**UHBR13.5 就算挂了均衡也只剩 0.18 UI 眼宽，UHBR20 干脆连均衡都救不回来。** 均衡是拿来补损耗的，不是拿来变魔术的——**信道烂到一定程度，接收端再聪明也没用。**

![动图1：同一根 1.5 m 线，速率档从 HBR 2.7G 一路推到 UHBR20，左右并排两只真仿真眼。左眼永远挂着 HBR 那把老尺子（280 mV × 0.45 UI）——这本身就是"错误做法"的演示；右眼挂本档真正该用的模板。前三档 HBR/HBR2/HBR3 两边一样、都过。到 UHBR10 时左眼掉到 207 mV 被老尺子判 FAIL（注意眼宽 0.47 UI 其实过线，两个数分开上色，真正判死它的只有眼高），右眼经参考接收器（CTLE 4 dB + DFE 2 抽头）睁到 356 mV、用 UHBR 尺子 55 mV × 0.30 UI 判 PASS——同一时刻两个相反的结论，差别只在参考面钉在哪。再往上 UHBR13.5 均衡后只剩 0.18 UI 眼宽、UHBR20 连均衡都救不回来：均衡补的是损耗，不是变魔术](/images/41/anim01_rate.gif)

## 四、番外主角：eDP——你天天在用、却从没见过的那条 DP

用户最关心的"内屏"就在这里。**eDP（Embedded DisplayPort，嵌入式 DisplayPort）** 是 VESA 把 DP 裁剪、优化后专门用于**设备内部屏**的版本：笔记本、平板、一体机、很多手机的屏，主板到面板之间那条排线，跑的就是 eDP。

它和外接 DP 同源，但为"内屏、省电、省成本"做了几件专属的事：

- **PSR / PSR2 / Panel Replay（面板自刷新）**：屏里带一块帧缓存，**画面没变时，面板自己刷新自己**，GPU 和主链路就能休眠——静态桌面、看文档时**特别省电**。你笔记本"合盖不断电、屏一直亮却不怎么耗电"，就是它。
- **背光控制 / CABC / 局部调光**：eDP 能直接对面板背光下细粒度指令（外接 DP 显示器一般做不到这么细），按内容自适应调背光省电。
- **MSO（Multi-SST Operation，多单流切分）**：把一条链路切成多路，喂给高像素密度面板。
- **更省的电气档**：可以用更低摆幅、更少 lane 跑，一切为功耗让路。

**测试上的差别**：eDP 的一致性测试同样看眼图、看抖动，但**多了一堆"面板级"验证项**——PSR 进出退时序对不对、背光调光有没有闪、Panel Replay 局部刷新会不会撕裂。这些是外接 DP 没有、eDP 特有的坑。

![图5：eDP——设备内部那条看不见的 DP。左：主板 SoC/GPU ──eDP 排线──> 笔记本内屏面板（画出焊在里面、无插头，对比外接 DP 有插头）。右：eDP 专属四件事，各配一句测试关注点：①PSR/Panel Replay 面板自刷新（画面不变→面板自己刷、GPU 休眠省电｜测：进出退时序、局部刷新会不会撕裂）②背光控制/CABC 局部调光（按内容调背光｜测：调光闪烁 flicker）③MSO 多单流切分（喂高密度面板）④更低摆幅/少 lane（为功耗让路｜测：低摆幅下眼图还够不够）。底部一句：eDP=DP 内核 + 一堆面板级省电特性，测法在 DP 基础上多了"面板项"](/images/41/ill05_edp.png)

## 五、测什么·三类：Source 眼图、Sink 压力测试、线材通道

和第 35 篇的方法论、和 HDMI 一样，DP 一致性测试也落到**电气三阵营**，只不过因为 DP 一律嵌入式时钟，三类全程都在"CDR + 眼图"的世界里：

- **① Source / Tx（发送端）测试**：在 **TP2**（源输出经参考线缆 / 夹具后的点）抓**数据 lane 眼图**，扣 VESA 眼图模板，测抖动（RJ/DJ/TJ 分离见第 32 篇）、上升沿、电平摆幅、**pre-emphasis（预加重）各档**。HBR 一套模板、UHBR 又一套（更严、带参考均衡）。
- **② Sink / Rx（接收端）测试**：用 **BERT / 码型发生器**在 **TP3**（sink 输入点）造一个**校准过的"压力眼"**（loss + jitter 都加到规范上限），看 sink 还能不能正确接收——即**抖动容限（jitter tolerance）**、接收灵敏度、CDR/PLL 跟不跟得住（见第 38 篇 Rx jitter tolerance，同一路数）。
- **③ Cable / 通道测试**：线材 / 连接器的插入损耗、回损、lane 间 skew、串扰——尤其 UHBR 线和 USB-C 线，通道裕量是过不过的关键。

![图6：DP 一致性测试三阵营（全程 CDR+眼图世界）。左 Tx/Source：示波器在 TP2 抓 4 条 data lane 眼图→扣 VESA 眼图模板+抖动分离 RJ/DJ/TJ（见第32篇）+预加重各档；标 HBR 模板 vs UHBR 模板(更严+参考均衡)。中 Rx/Sink：BERT/码型发生器在 TP3 造校准压力眼(loss+jitter 加满)→测抖动容限/接收灵敏度/CDR 跟踪（见第38篇）。右 Cable：VNA/示波器测插损/回损/skew/串扰，UHBR 线与 USB-C 线是重灾区。底部标 TP2=源端(过参考线缆)、TP3=宿端输入，两个测试点别搞混](/images/41/ill06_test3.png)

## 六、怎么测：进测试模式 + link training 到目标档 + 参考均衡

具体到台面上，DP 的流程和 HDMI FRL 高度相似（因为本来就是同一路）：

1. **搭夹具、接测试点**：Source 测试用带 TP2 探测点的夹具 / 转接；Sink 测试把码型灌到 TP3。
2. **通过 AUX / DPCD 让被测件进"测试模式"**：写 DPCD 寄存器，让 Source 固定输出规定的**测试码型（PRBS / 特定 pattern）**、锁定在目标速率档（比如 HBR3 或 UHBR20），关掉自适应，方便重复测量。
3. **link training 到目标档**：DP 传数据前，Source↔Sink 要先做 **link training**——从低速档往高试、调 lane 数 / 电压摆幅 / 预加重，训到一个稳定档位，结果写进 DPCD。训不上就回落低档（4K144 变 4K60 常死在这）。
4. **示波器抓眼图 / BERT 打压力**：Tx 侧抓眼图套模板；Rx 侧灌压力码型测容限。
5. **UHBR 必须上参考均衡**：UHBR 速率下裸眼图基本是"闭"的，**必须在示波器里挂上规范规定的参考均衡（CTLE / DFE见第 34 篇）**把眼睁开再判——这一步和 USB 3.x、PCIe 完全一个思路。

![图7：DP 测试台面搭建。左区块"进测试模式"：上位机经 AUX 写 DPCD 寄存器→被测 Source 固定输出 PRBS 测试码型、锁定目标速率档(HBR3/UHBR20)。中区块"link training"：Source↔Sink 从低速往高试→调 lane 数/摆幅/预加重→训到稳定档写回 DPCD→训不上则回落(4K144→4K60)。右区块"测量"：TP2 接示波器抓眼图套 VESA 模板；TP3 接 BERT 灌压力眼测容限。底部强调框：UHBR 必挂参考均衡 CTLE/DFE（见第34篇） 才能把闭着的眼睁开判读——和 USB3/PCIe 同路](/images/41/ill07_bench.png)

### 6.1 源端台面长什么样（TP2）

![图10：DP 源端一致性台面 @TP2。左上"主机 / 一致性软件"跑 VESA PHY CTS 测试套件，选速率档 HBR~UHBR20、10 个合法组合逐个跑；右接"AUX / DPCD 控制盒"（DP 的控制面，1 Mbps 双向）——写 DPCD 让 DUT 进测试模式、锁档，读 DPCD 看现在训在第几档。左下"被测 Source（DUT）"输出固定 PRBS 码型，当前摆幅 L2 + 预加重 L1；经"TP2 夹具 + 参考线缆"（TP2 = 源端经参考线缆之后的点，最坏情况参考线缆要嵌进来，夹具自身损耗靠去嵌扣掉）→ CH1 进实时示波器。屏内是 UHBR 模式下经参考接收器（CTLE 4 dB + DFE 2 抽头）输出的真眼：眼高 356 mV、眼宽 0.53 UI，教学判据 55 mV × 0.30 UI。示波器软件里的处理链画成一条分叉：共同前段 ①去嵌掉夹具 → ②golden PLL 恢复时钟；然后 HBR 系裸眼直接扣 280 mV × 0.45 UI，UHBR 系先过参考接收器再扣 55 mV × 0.30 UI。四张坑位卡：①AUX 不通就什么都测不了（示波器一片安静，还以为 DUT 坏了）②10 个组合都要扫（只测默认那一档就交报告，现场换个组合当场翻车）③UHBR 别拿裸眼判 ④参考面钉在 TP2（在 DUT 出口直接测、少嵌一根线，报告比真实情况好看一大截）](/images/41/fig_setup_tp2.png)

台面上真正**属于 DP、别的接口没有**的，是那个 **AUX / DPCD 控制盒**。别的接口进测试模式靠按键、靠上电时序、靠特殊码型；**DP 是往寄存器里写一个值。** AUX 一断，示波器上一片安静——**新手最常见的第一个小时，就浪费在"以为 DUT 坏了"上面。**

### 6.2 预加重不是"越大越好"：一张两头都会翻车的图

第 3 节那张动图扫的是速率。这一张换个旋钮：**速率锁死在 HBR3 8.1 G/lane、线长锁死 1.5 m（插损 14.9 dB @10 GHz），只动预加重这一根滑杆，从 0 dB 一路加到 11 dB。**

⚠️ 说"只动一根滑杆"要加一句注解：**峰值被规范封顶在 1200 mV**，所以预加重加多少、稳态摆幅就得让多少——这两个旋钮在 DP 里本来就是**联动的**。动图扫的这条连续曲线，正是 6.3 节那张三角表里的**一条对角线**：预加重从 L0 走到 L3 的同时，摆幅反向从 L3 让到 L0，滑条底下那四个刻度就是规范认下来的四个合法档。

很多人心里的模型是"预加重是用来补损耗的，所以加得越多越保险"。真跑一遍，眼图给的答案是 **两头都会翻车**：

下表的**稳态电平**按 `1200 ÷ 预加重倍数` 精确换算（这正是动图里那根柱子实时算的式子），**眼高 / 眼宽**取自动图对应帧（动图是连续扫的，dB 值取到一位小数）：

| 预加重 | 稳态电平 | 眼高 | 眼宽 | 判定（教学判据 280 mV × 0.45 UI） |
|---|---|---|---|---|
| **0.0 dB（＝规范 L0，配摆幅 L3）** | 1200 mV | **254 mV** | **0.43 UI** | **FAIL —— 高、宽一起塌** |
| 1.5 dB | 1010 mV | 303 mV | 0.53 UI | PASS |
| 3.4 dB（≈规范 L1 的 3.5 dB） | 811 mV | 369 mV | 0.63 UI | PASS |
| **5.1 dB** | 667 mV | **409 mV** | **0.66 UI** | **PASS（眼高峰值）** |
| 5.9 dB（≈规范 L2 的 6 dB） | 608 mV | 399 mV | 0.65 UI | PASS |
| 7.6 dB | 500 mV | 347 mV | 0.63 UI | PASS |
| **9.5 dB（＝规范 L3，配摆幅 L0）** | 402 mV | **268 mV** | 0.58 UI | **FAIL —— 只有眼高破** |
| 11.0 dB（已在规范外） | 338 mV | 216 mV | 0.57 UI | FAIL |

💡 **把稳态那一列和摆幅四档对一下，对角线就自己跳出来了**（注意这里数的是**摆幅**等级，和前一列的预加重等级正好反向）：0 dB→1200 mV ＝**摆幅 L3**；3.4 dB→811 mV ≈ **摆幅 L2** 的 800；5.9 dB→608 mV ≈ **摆幅 L1** 的 600；9.5 dB→402 mV ≈ **摆幅 L0** 的 400。这不是巧合——**稳态 = 1200 ÷ 预加重倍数**，峰值封顶这一条约束，把两个旋钮焊成了一根滑杆。

**通过窗口是 0.98 ~ 9.29 dB，两头都在窗外，而且翻车的方式完全不同：**

- **左边（加重不够）**：ISI 没补掉，**眼高和眼宽一起塌**，而且**眼高塌得更狠**——眼宽 0.43 UI 离 0.45 的线只差 5%，眼高 254 mV 离 280 的线差了 9%。往上抬预加重的时候也是眼宽先回到线上，**眼高一直拖到 0.98 dB 才补回来**。这是"符号间干扰"最经典的样子。
- **右边（加重过头）**：注意看**稳态电平那一列**——峰值被规范钉死在 1200 mV 天花板上，你把预加重加大，**加的不是高频，而是把稳态那一段压下去**。11 dB 时稳态只剩 338 mV，眼宽反而还有 0.57 UI（够用），**是眼高先破的**。

**这就是为什么 DP 一致性测试要求把预加重逐档扫一遍，而不是挑个"典型值"测一次。** 你的芯片可能在**预加重 L1、L2** 漂漂亮亮，**预加重 L0 和 L3** 一测就趴——而现场跑 link training 时，**Sink 有权点名任何一个合法组合**。

![动图2：HBR3 8.1 G/lane、1.5 m 线固定不动，把预加重从 0 dB 连续扫到 11 dB；峰值被封顶在 1200 mV，所以稳态摆幅是跟着反向让下去的，滑条底下四个刻度就是规范三角表那条对角线上的四个合法档（预加重 L0→L3 对摆幅 L3→L0）。屏上一直挂着教学判据 280 mV × 0.45 UI 和峰值天花板 1200 mV。0 dB 时眼高 254 mV、眼宽 0.43 UI，两项一起在窗外，眼高塌得更狠（差 9%，眼宽只差 5%）——这是 ISI 没补掉的典型样子；加到约 1 dB 翻成 PASS；5.1 dB 附近到达眼高峰值 409 mV / 0.66 UI；继续加，稳态电平被 1200 mV 天花板压着一路往下掉（9.5 dB 时只剩 402 mV，正好落回摆幅 L0 那一档的 400 mV），眼宽还有 0.58 UI，却是眼高先破线 268 mV 判 FAIL。通过窗口 0.98~9.29 dB，两头都会翻车，而且翻车方式不同：左边高宽一起塌、眼高更惨，右边只塌眼高](/images/41/anim02_preemph.gif)

### 6.3 顺手把规范里那条"看着像行政规定"的条文解释掉

VESA 规范里有一条，很多人背下来但没想过为什么：**摆幅等级 + 预加重等级之和不得超过 3**。所以 4×4 = 16 个组合里，**只有 10 个是合法的**，排出来是一张三角表：

| 摆幅 \ 预加重 | L0 | L1 | L2 | L3 |
|---|---|---|---|---|
| **L3** | ✓ | ✗ | ✗ | ✗ |
| **L2** | ✓ | ✓ | ✗ | ✗ |
| **L1** | ✓ | ✓ | ✓ | ✗ |
| **L0** | ✓ | ✓ | ✓ | ✓ |

读起来像条行政规定，其实它只是**一句物理约束的换算结果**：**发送端峰值电压不得超过 1200 mV。**

摆幅四档 400 / 600 / 800 / 1200 mV，预加重四档 0 / 3.5 / 6 / 9.5 dB。预加重是在跳变沿上**往上加**一段，所以峰值 = 摆幅 × 预加重倍数。把这两组数逐格乘一遍就会发现：**凡是和超过 3 的格子，峰值全部顶穿 1200 mV 那块天花板**——不是规范委员会拍脑袋划的线，是电路根本给不出那么高的电压。

上面 6.2 那张扫图里"稳态电平一路往下掉"，也是同一件事的另一面：**峰值被钉住了，你加预加重，就只能牺牲稳态。**

所以一致性测试要一格一格扫这 **10 个绿格**，每一个都得落在模板窗口里。**只测一个"典型组合"就交报告，是最常见的漏测。**

### 6.4 宿端台面长什么样（TP3）：判据根本不在示波器上

![图11：DP 宿端一致性台面 @TP3。左上"误码仪 BERT（信号源）"造一只"刚好难到卡线"的眼：插损 19 dB + 正弦抖动 0.20 UI，摆幅压到 L0 + 预加重 L3（合法组合里最难接的一档）；→"压力信道（损耗板 + 加抖）"把好信号做坏、坏得可复现，抖动在发送端注入、随信号一路走 → TP3 → "被测 Sink（DUT）"（显示器 / eDP 屏 / 转接芯片），用它自己的 CTLE / DFE / CDR ——这正是这场测试要考的。示波器画成红色虚线连到 TP3，标"只在校准阶段接：校准完拔掉，再把 DUT 接上去判定"；屏内是校准好的压力眼，眼高 119 mV（比目标高 3%）、眼宽 0.302 UI（高 1%），标"这是校准窗口，不是及格线：眼比它开 = 压力没加够，眼比它闭 = 把好屏冤枉成坏屏"。中下一块大面板"判据在哪儿？另一路 AUX 一直挂着，从 DPCD 里读计数器"：✗ 看画面（FEC 会把零星错码悄悄纠掉——画面好好的，链路已经在挣扎）／ ✓ 读 DPCD（symbol error 计数 + FEC 纠错/未纠错块数，规定时间内不得超限）。四张坑位卡：①先校准再接 DUT ②判据在寄存器里 ③校准完把探头撤了（探头是负载，挂着它 DUT 收到的已不是校准好的那只眼）④eDP 要先关 PSR（面板自刷新时屏幕内容来自本地缓存，链路根本没在跑，错码全被掩盖，一测就"全过"）](/images/41/fig_setup_tp3.png)

宿端这张台面，有**两件事**和你在源端养成的习惯是反的：

**第一，示波器只在校准阶段登场。** 你要先用 BERT + 损耗板 + 抖动源，把一只**故意做坏的眼**调到规定的"难度"上——这台面上是眼高 119 mV / 眼宽 0.302 UI（教学校准目标 115 mV × 0.30 UI，实测余量 +3% / +1%）。**校准是双向的**：眼比目标开，说明压力没加够，**测了等于没测**；眼比目标闭，那是**把好屏冤枉成不合格**。校准完，探头必须撤掉——**探头本身就是负载**，挂着它，DUT 收到的已经不是你刚校准好的那只眼了。

**第二，判定不在屏幕上，在寄存器里。** UHBR 强制开 FEC，**零星错码会被悄悄纠掉，画面看着好好的，链路其实已经在挣扎。** 所以判据是另一路 AUX 一直挂着、从 DPCD 里读出来的 **symbol error 计数 + FEC 纠错 / 未纠错块数**，规定时间内不得超限。**"看着画面挺好就放行"，在 DP 上是彻底失效的判法。**

> 🔩 **eDP 专属的一个坑**：测内屏时**必须先关掉 PSR**。面板自刷新的时候，屏幕内容来自面板自己的本地缓存，**链路根本没在跑**——你灌进去的错码全被掩盖，一测就"全过"。

### 6.5 训不上高档，用户看到的不是黑屏，是选项一档一档消失

最后把三个旋钮合起来跑一遍**真的 link training**：**换线**（把信道插损从 7 dB 一路劣化到 26 dB @10 GHz），每一步让 Source 和 Sink 在 (速率 × 摆幅 × 预加重) 里**从最高档往下搜**，搜到第一个还有裕量的组合就停。

落档结果是这样的：

| 信道插损 @10 GHz | 训到 | 用户端表现 |
|---|---|---|
| 7.0 dB 起 | UHBR20（20 G/lane） | 8K60 HDR 10bit |
| **9.9 dB** | UHBR13.5（13.5 G/lane） | 4K240 |
| **15.3 dB** | UHBR10（10 G/lane） | 4K165 |
| **18.2 dB** | HBR2（5.4 G/lane） | 2K165 |
| **21.6 dB** | HBR（2.7 G/lane） | 1080p144 |

两个值得停下来看的地方：

**① 全程没有黑屏。** 从 8K60 一路掉到 1080p144，用户端**一次黑屏都没有**——只是显示设置里那些高刷、高分辨率的选项，**一档一档地灰掉、消失**。这正好回答了开篇那个"为什么高刷选项会灰掉"：**很多时候链路是好的，只是没训上去。**

**② HBR3 被整档跳过了。** 插损从 15.3 走到 18.2，档位直接从 UHBR10 掉到 **HBR2**，**中间的 HBR3（8.1 G/lane、能撑 4K120）一次都没被选中**。为什么？因为 link training 搜的是"**这条信道下还能站住的最高档**"，而不是"依次往下退一格"。HBR3 在这个插损区间**恰好也站不住**——它虽然速率比 UHBR10 低，但它是 8b/10b 编码、判据用的是 HBR 那把更严的裸眼尺子（280 mV × 0.45 UI），并**不享受 UHBR 的参考接收器**。**"降一档"和"降到能用的那一档"，是两回事。**

现场对应的场景很具体：用户换了根便宜的长线，**4K120 这个选项并不是"变成 4K60"，而是整个消失了**，直接跳到 2K165。你要是按"应该逐级回落"的直觉去排查，会一直找不到北。

![动图3：一根线的插损从 7 dB 一路劣化到 26 dB @10 GHz，每一帧都真跑一遍 link training（在速率 × 摆幅 × 预加重里从最高档往下搜）。屏上同时给出当前训到的速率档、选中的摆幅/预加重组合、裕量条（判据 1.0）和右侧的分辨率阶梯灯。落档点：7.0 dB → UHBR20 / 8K60 HDR 10bit；9.9 dB → UHBR13.5 / 4K240；15.3 dB → UHBR10 / 4K165；18.2 dB → HBR2 / 2K165；21.6 dB → HBR / 1080p144。全程没有一次黑屏，用户端看到的只是高刷选项一档一档灰掉。特别标注：18.2 dB 这一跳直接从 UHBR10 掉到 HBR2，中间的 HBR3（4K120）被整档跳过——因为 link training 搜的是"还能站住的最高档"，不是"依次退一格"，而 HBR3 用的是 HBR 那把更严的裸眼尺子、不享受参考接收器](/images/41/anim03_train.gif)

## 七、⚙️ 关键仪器设置：把模块三的 SI 概念落到旋钮上

DP 的仪器设置几乎照搬 HDMI FRL / USB 3.x 那套（这也是"学会一个通一片"的好处）：

- **去嵌（de-embed）见第 33 篇**：把夹具 / 探测通道的损耗从测量结果里数学扣掉，还原芯片管脚处的真实信号。
- **嵌入参考线缆 / 参考通道**：Source 测试要在"最坏情况参考线缆"后测（TP2 的定义），模拟真实线材损耗。
- **参考均衡 CTLE / DFE见第 34 篇**：UHBR 强制用，把高频损耗补平、把闭着的眼睁开——**判据是"参考均衡之后"的眼图**，不是裸眼图。
- **时钟恢复 golden PLL见第 32 篇**：DP 是嵌入式时钟，示波器要用规范规定的黄金 PLL 环路参数恢复时钟，才能正确测抖动。
- **带宽按规范档设**（见第 29 篇 / 速查 02）：按波特率约 0.7～1 倍选示波器带宽，别过冲。
- **抖动分离 + eye mask**（见第 31 / 32 篇）：把 TJ 拆成 RJ / DJ，再套眼图模板判裕量。

> 一句话：**DP（尤其 UHBR）的仪器设置 = USB 3.x / PCIe 那套嵌入式时钟测法**。你在第 38 篇学的东西，这里几乎能直接复用；HDMI 的 TMDS 那半套（转发时钟）在 DP 上完全用不到。

## 八、判据从哪来：眼图模板 / 抖动预算不是拍脑袋

和第 35 篇讲的一样，DP 的判据也来自 **VESA 的 CTS（Compliance Test Specification，一致性测试规范）**，不是拍脑袋：

- **眼图模板、抖动限值**：从信道损耗预算 + 抖动预算反推而来（见第 35 篇）。HBR 系列一套、UHBR 系列一套（后者含"参考均衡之后"的判定）。
- **预加重 / 电压摆幅各档**：每个组合都要落在规范窗口内。
- **link training 结果 + FEC 行为**：链路层 CTS 要验训练能不能到目标档、FEC 纠错行为对不对。
- **DSC / MST 单独验**：开压缩、开多流时的正确性，是链路层的独立测试项。

DP 的判据体系比 HDMI 更"分层清楚"：**PHY CTS（电气：眼图 / 抖动 / TP2 TP3）+ Link Layer CTS（协议：训练 / DPCD / EDID / MST / FEC / DSC）** 两大本，分别由不同测试系统跑。

> ⚠️ **关于本篇所有数字的一个郑重声明。**
>
> DP 的眼图模板、抖动限值这些具体数值，需要 **VESA 会员资格**才拿得到，**不是公开值**。所以本篇每一张图上标的判据，都明写了「**教学判据**」四个字：HBR 系用 280 mV × 0.45 UI（裸眼）、UHBR 系用 55 mV × 0.30 UI（参考均衡之后）、TP3 压力眼的校准目标用 115 mV × 0.30 UI。
>
> 这些数是**为了让物理趋势跑得出来**而选的自洽取值。**趋势是成立的**——参考面钉在哪、预加重两头都会翻车、link training 会整档跳过、峰值封顶逼出那张三角表——这些结论不依赖具体数值。但**绝对数值请不要引用到你的测试报告里**，以你手上那一版 CTS 为准。
>
> 同理，仿真里的信道模型（一阶低通 τ）和噪声取值（幅度的 3.5%，当作串扰 + 接收端等效噪声的合计）也是教学取值，不是任何一款真实线材的实测数据。

## 九、常见翻车与调试：黑屏 / 掉刷新率 / 菊花链带不动 / eDP 闪，怎么分层揪

DP 翻车，**先分层、别一上来就赖信号**（顺序和 HDMI 一样，只是多了 MST / DSC / eDP 几层）：

1. **先看协商层（AUX / DPCD / EDID）**：屏认不认得出？EDID 读到没？DPCD 里 link training 训到第几档？——**"高刷选项灰掉""插上没反应"多半死在这**，跟信号无关。
2. **再看电气层（眼图 / 均衡 / 线材）**：训到高档但花屏、闪断、雪花——量数据 lane 眼图、skew、看线材够不够 UHBR 级、参考均衡后眼还睁不睁。
3. **压缩 / 多流层（DSC / MST）**：8K 上不去 / 开 DSC 才行；菊花链第二台屏黑——查 MST 的流分配、Hub 带宽是否够。
4. **内容保护层（HDCP）**：黑屏但灯亮、放版权内容才黑——HDCP 握手问题，和信号质量无关。
5. **eDP 专属层**：内屏花屏 / 闪烁 / 撕裂——查 PSR 进出退时序、背光调光、Panel Replay 局部刷新（外接 DP 没有这层）。

**现象速查**：高刷选项灰掉=EDID/DPCD 没协商上；训到高档仍花屏雪花=眼图/线损/skew；菊花链第二屏黑=MST 流分配/Hub 带宽；8K 只能开 DSC 才行=带宽到顶；黑屏灯亮放版权内容才黑=HDCP；笔记本内屏闪烁/撕裂=eDP 的 PSR/背光/Panel Replay。

## 一句话总结

**一句话：DisplayPort 从出生就站在「嵌入式时钟 + CDR + 打包传输」这一岸（HDMI 是在分水岭上走了个来回才过来），所以它的一致性测试一上来就是 USB3 / PCIe 那套。学会了 HDMI FRL，DP 你已经会了一大半。**

- **站位**：从出生就是嵌入式时钟 + CDR + 打包传输，和 USB3 / PCIe 同岸，不像 HDMI 那样在分水岭上走了个来回。
- **怎么测**：看眼图、做抖动分离、用参考均衡、TP2/TP3 分点；到 UHBR（128b/132b + FEC）把裕量压到极限。
- **DP 特有**：笔记本里那条 eDP 的面板级省电项，构成了 DP 测试和 HDMI 既重叠又不同的那部分。
